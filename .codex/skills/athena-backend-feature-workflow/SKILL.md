# ATHENA 后端设计开发

用本技能识别当前阶段并只执行该阶段允许的工作。不要因为前一阶段已经确认而自动进入下一阶段。

## 读取事实来源

从仓库根目录开始，依次读取：

1. `AGENTS.md`；
2. `docs/developer-guide/design-led-backend-development.md`；
3. `docs/requirements/README.md`、`docs/design/README.md`；
4. 受影响能力的需求、技术设计和实际源码。

需求和技术决定必须写入仓库文档。聊天内容可以帮助理解当前请求，但不能替代文档状态或成为后续任务的唯一依据。新文档直接使用 `docs/requirements/template.md` 或 `docs/design/template.md`，不要在技能目录复制模板。

## 识别工作模式

| 模式 | 进入条件 | 本次允许的主要产出 |
| --- | --- | --- |
| 需求讨论 | 目标、范围、规则或验收仍需梳理 | `讨论中` 的需求文档；只读现状分析 |
| 需求确认 | 用户明确确认需求内容 | 写回确认决定并把需求标为 `已确认` |
| 技术设计 | 关联需求已为 `已确认`，用户要求设计后端方案 | `设计中` 的技术设计；只读源码分析 |
| 设计确认 | 用户明确确认技术设计 | 写回决定并把设计标为 `已确认待实现` |
| 实现 | 正常门禁均满足且用户另行明确要求实现，或用户明确要求修复到无歧义的 `已实现` 设计 | 设计范围内的源码、配置和同步文档 |
| 设计一致性审查 | 用户要求审查，或授权实现已完成 | 需求—设计—源码对应关系及偏差报告 |

用户的确认只推进当前文档状态。除非同一请求还明确要求执行下一阶段，否则完成状态更新后停止。

## 执行阶段门禁

### 需求讨论与确认

- 只在 `docs/requirements/` 中形成目标行为，不预先选择组件、数据库结构、RPC 字段或基础设施。
- 可以只读检查源码和 `已实现` 设计，以辨认现状、约束和术语；不得修改后端源码。
- 需求仍有会影响技术方案的问题时保持 `讨论中`。只有用户明确确认且实质问题已经解决，才标为 `已确认`。
- 确认结果先写回需求文档，再报告状态；不要自动创建技术设计。

### 技术设计与确认

- 开始前验证关联需求确实标为 `已确认`；否则返回需求阶段。
- 基于真实源码和相关 `已实现` 设计说明现状差距，按仓库模板更新或创建 `设计中` 文档，并建立需求双向链接。
- 本阶段不得修改后端源码。用户明确确认设计后，先写回决定和状态 `已确认待实现`，然后等待另行实现任务。

### 实现

修改任何后端源码前，同时验证：

- 需求路径存在且状态为 `已确认`；
- 技术设计路径存在且状态为 `已确认待实现`；
- 当前请求明确授权实现；
- 本次范围、成功标准、授权验证和停止条件已能从任务与文档中确定。

正常功能实现缺少任一门禁时不编码，继续当前可安全完成的文档工作并说明缺口。用户明确要求修复、代码可证明仅偏离现有 `已实现` 设计且该设计无歧义地定义期望行为时，是唯一例外；不要为此虚构历史需求。门禁满足后：

1. 将需求条目映射到设计章节和源码改动。
2. 在确认范围内实现；命名、辅助函数拆分和局部组织自主决定。
3. 同步相关技术设计、真实源码链接和仓库说明，直接清理被替换的旧实现。
4. 若变更触发 SQLC、Proto、ABI 或跨两个及以上依赖层，组合使用 `$sync-athena-changes`，不要复制其生成规则。
5. 只执行用户授权的验证；项目默认禁止自行规划或运行测试。
6. 完成需求映射和设计一致性审查后，才把设计状态改为 `已实现`。

### 设计一致性审查

- 按需求逐项比较设计、源码、配置、生成边界和旧实现清理情况。
- 单独的审查请求默认只读；只有用户同时明确要求修复时才修改源码。
- 使用仓库工作流指南定义的完成报告格式，不用聊天结论替代文档修正。

## 处理变化与缺陷

- 业务规则、权限、业务状态、范围、可观察行为或验收标准变化：将需求退回 `讨论中`，记录拟议变化并等待重新确认。
- 组件边界、接口或数据契约、数据模型、事务并发、核心流程或基础设施变化：将设计退回 `设计中`，记录拟议变化并等待重新确认。
- 发现实质偏差时，只完成不依赖该偏差的部分；不得以“实现细节”为名绕过回退。重新确认后还需用户明确授权继续变更后的实现，原授权不自动覆盖变化范围。
- 用户已明确要求修复且代码仅偏离无歧义的 `已实现` 设计时，可以直接按设计修复。代码与文档谁正确无法判断，或期望行为未被文档定义时，先回到对应设计阶段。
- 格式化、注释、文案，以及生成源、契约和设计语义均未变化的纯生成文件刷新等机械修改不进入本流程；修改 SQL、Proto、ABI 等生成源不属于豁免。
