# 人工 UI 验收指南：【AI 填写任务名称】

> 这是给用户照做的浏览器操作说明，不是自动测试方案。AI 必须替换所有占位符；不得要求用户执行 Git、Go、Node、API、构建或 Playwright 命令。运行本轮明确列出的 start/status/seed/stop 脚本是唯一现场管理例外。

## 验收现场

- 任务：`【AI 填写】`
- 轮次：`【AI 填写 R1/R2/...】`
- 目标版本：`【AI 填写完整 SHA 或其他不可变版本】`
- worktree：`【AI 填写绝对路径】`
- UI 地址：`【AI 填写 member 地址】`；管理员：`【AI 填写 admin 地址】`
- 身份：`【AI 填写 member/admin 身份和权限】`
- 运行脚本：`【AI 填写 scripts/start-review.sh、status-review.sh、stop-review.sh 的实际路径】`
- 前置数据脚本：`【AI 填写 seed-review.sh 路径；不需要时写“不需要”】`

### 用户执行顺序

1. 在目标 worktree 中运行 `【AI 填写 start-review.sh 命令】`。
2. 需要时运行 `【AI 填写 status-review.sh 命令】`，确认页面地址和实例归属。
3. 需要时运行 `【AI 填写 seed-review.sh 命令】`；脚本只准备 UI 前置数据，不判断页面结果。
4. 打开下面的页面流程，只用浏览器完成操作。
5. 完成后运行 `【AI 填写 stop-review.sh 命令】`，或请求 AI 按归属协助收尾。

这些脚本不运行自动测试、API 测试、构建、reset 或无关数据删除。用户只需要向 AI 报告页面观察，不需要填写本文件或其他 Markdown 文件。

## 页面流程

### 流程 1：【AI 填写业务流程名称】

- 入口：`【AI 填写 URL、member/admin 和桌面/手机入口】`
- 身份：`【AI 填写角色】`
- 前置：`【AI 填写必须已存在的页面状态；没有则写“无”】`
- 操作：
  1. `【AI 填写点击、输入或导航】`
  2. `【AI 填写下一步】`
- 预期看到：
  - `【AI 填写用户可以直接观察的结果】`
  - `【AI 填写错误、加载、空态或确认状态】`
- 手机/桌面差异：`【AI 填写；没有则写“相同”】`
- 恢复：`【AI 填写如何取消、撤销或离开；没有副作用则写“无”】`

### 流程 2：【AI 填写业务流程名称】

- 入口：`【AI 填写】`
- 身份：`【AI 填写】`
- 前置：`【AI 填写】`
- 操作：
  1. `【AI 填写】`
  2. `【AI 填写】`
- 预期看到：`【AI 填写】`
- 手机/桌面差异：`【AI 填写】`
- 恢复：`【AI 填写】`

> AI 按实际范围增删流程。每个流程必须描述用户动作和可观察结果，不要改成命令、断言或接口检查。

## 反馈方式

完成一个流程后直接回复，例如：

- `流程 1 通过，桌面和手机都正常。`
- `流程 2 有问题：点击保存后仍显示旧名称，发生在 member，附截图。`
- `流程 3 受阻：页面无法进入，浏览器显示具体错误。`

AI 会记录原始反馈、版本、页面、身份、截图/录屏路径和问题编号。用户不需要编辑 `human-report.md`。
