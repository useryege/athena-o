## 2. 领域边界与接口版本

钱包采集由单链研究 Worker 执行；任务、租约、配额、首轮时间及有限重试统一遵守 [研究任务运行时](research-task-runtime.md)。
项目研究状态及停止栅栏来自 [发现与研究生命周期](discovery-research-lifecycle.md)；owner／fee 读取结果来自 [源码事实与读取说明](source-facts-and-read-plans.md)。
成员只读与管理员配置入口由 [查询与管理](research-query-and-administration.md)统一提供；查看或展开资金图不调用采集接口、不创建研究任务。

| 领域契约 | 输入 | 独立输出与版本 |
| --- | --- | --- |
| L1 登记 | 项目、链、地址、角色证据、观察区块或源码产物身份 | 钱包锚点、角色区间、初始任务；`wallet_role_schema_version` |
| 历史采样 | 链、地址、截止高度、历史类型、固定采样参数 | 原始页、逐项校验、取得状态；`sampling_rules_version` |
| 交易补证 | 链、顶层交易哈希、所需交易或回执类别 | 共享交易／回执证据及独立失败；`evidence_schema_version` |
| 钱包行为解析 | 项目钱包、样本关联、交易及日志、可信协议映射 | 钱包级行为与支持依据；`behavior_rules_version`、`protocol_coverage_version` |
| 来源扩展 | 钱包、项目门槛、证据、当前扩展代次 | 资金关系、层级松弛、必要下游任务；`funding_rules_version` |
| 资产快照 | L1 钱包、观察区块、固定资产集合、路径配置版本 | 六项结果及同次已知小计；`valuation_rules_version` |

上述版本独立变化，不用单个画像版本表示所有资料。接口中的链、地址、哈希、整数金额和来源身份为强类型；JSON／Proto 的大整数以十进制字符串传递。
升级解析规则只重建对应派生事实，不悄悄扩大原始采样页。对停止项目不新增专属重算任务；共享交易证据的新增版本不自动改写其冻结结果。

## 3. L1 登记与角色生命周期

部署者在项目可靠创建时登记。部署回执、初始接收钱包、owner 和 fee 结果分别到达、分别登记，不互相等待。
初始接收钱包只分析部署交易中目标 Token 发出的合法 `Transfer`，按每地址流入减流出得到净接收原始整数；自转账净额为零。
排除零地址和非正净额，按净额降序、地址字节升序稳定排序；在采集观察区块查询代码，取无代码的最多 5 个地址。
所有地址代码判断固定在同一观察区块，保存高度、哈希和时间；这里只表示该观察区块无代码，不推断永久 EOA 身份。
代码查询失败保留未确定状态，不当作无代码；若前序候选未判定会影响前五名，不将后序候选发布为已确定排名。
部署回执缺失、失败或候选判断未完成仅影响该研究资料，不回滚已接受项目，也不阻塞后续区块扫描。

owner 和全部已取得 fee 非零地址均可为合约；一个地址保留多个角色、多个税费用途，仅登记一个项目钱包。
零 owner／fee 原值及证据由读取资料保存，不建立钱包节点和主动交易监控；不得凭名称或地址外观排除其他非零地址。
fee 的同一用途或数组部分读取成功时，已证实的每个非零地址立即新增该来源当前角色、历史 L1 和必要初始任务；仅该项完整成功才可撤销旧集合中未再出现的角色，未知缺项不能解释为已删除。
上述角色及任务提交仍须满足项目研究状态和共同停止栅栏；owner 冲突或读取失败不得用猜测替换最近有效身份。

`project_wallet.l1_anchor` 一旦由有效直接角色建立便保留，`l1_joined_at` 记录首次成为 L1 的持久时间。
`wallet_role_interval` 独立记录角色用途、有效观察起止及来源；关闭当前角色不删除钱包、历史角色、样本或资金边。
旧 owner／fee 失去最后当前角色时，继续未完成的历史与上游研究；L1 初始资料资格不以是否仍有当前角色重新计算。
owner 变化仅按生命周期契约切换其活动监控，部署者始终保留；fee 角色本身不新增主动交易监控。
曾为深层钱包的地址新成为 L1 时沿用同窗口样本，补建尚缺首轮资产工作，将最短层级改为 L1，并重新评估允许的上游深度。
持币 Top 100 地址仅用于匹配既有角色与关系，不因为持币自动成为 L1 或启动历史、资产与上游研究。

## 4. 普通与内部历史的独立采样

每个项目钱包的两类历史均固定为 `startblock=0, endblock=B-1, sort=desc, page=1, offset=300`，B 是项目部署高度。
`B=0` 保存显式空范围和空结果，不发送会下溢或读到部署后的请求。后续加入的钱包也不改变历史截止点。
通过 Etherscan Manager 分别请求 `account/txlist` 和按地址 `account/txlistinternal`，不使用付费全链区块范围内部查询替代。
先保留实际原始页，再判断成功、金额和用途；失败、零额、小额和未知记录占原始样本名额，不翻页补满。
内部页独立查询，不以普通页内 300 个哈希的内部记录代替；返回超过 300 条或违反范围是接口异常，不能静默截断伪装成功。

| 维度 | 持久状态与语义 |
| --- | --- |
| 请求进度 | 尚未请求、等待配额、已发送、待重试、已结束；等待不是首轮响应 |
| 取得结果 | 成功有记录、成功空页、有效空范围、失败、部分可用，普通／内部分别表达 |
| 样本边界 | 原始数量、有效数量、错误记录位置、是否恰到 300 条；不足上限也不宣称完整调用轨迹 |
| 解析进度 | 待补证交易数、已解析数、未分类数、证据缺项；独立于原始页取得结果 |

校验页参数、链和地址归属、区块范围、哈希、整数及顺序；单行异常保存原文与原因，可用行先落库，整页标为部分可用。
网络失败不捏造空页；成功空页是有效事实。每次响应不可变保存，不把多个重试页拼成超过 300 条的合成样本。
样本缓存身份为 `(chain_id,address,cutoff_block,history_kind,sampling_rules_version)`，同时保存固定参数、提供方及响应版本。
项目每钱包每历史类型选定首次可用的原始页，包括部分可用页；一经持久关联，`chosen_sample_id` 及至多 300 个原始成员行永久固定，不因共享缓存 head、重试或规则升级替换另一页。
尚未选页且请求完全失败时，有限重试可接受后续首个可用页；已选空页同样是固定样本，不能用后续响应补满。
已选页的有限重试只允许按可靠记录身份为原始成员补正或补齐字段，另存补证及匹配依据而不改写原文；序号、金额或相似字段组合不能作为猜配依据。
新响应中不能可靠匹配原始成员的条目仅保存审计，不进入该项目行为、资金关系或来源扩展；原始条目身份不明时不猜配，也不凭新页为其扩图。
由样本产生的行为、边与任务必须引用项目 `chosen_sample_id`、原始行 ID 和对应规则版本；提交核验成员资格，不能通过累加重试响应把派生范围扩大到超过 300 条。
共享缓存可独立保存新响应及有效 head，供尚未选页的项目选用；已有项目不跟随切换。并发选页通过唯一关联保证只接受一个原始页，不能只按地址永久缓存或把普通页当作内部页。
失败不会覆盖已有成功页；部分页继续保留已知结果及原有限重试资格，缺失字段与身份未定如实表达，不能缓存为“该钱包无其他事实”。

官方 [Free 额度](https://docs.etherscan.io/rate-limits)公布 3 次／秒、每日 100,000 次；[2026-07-01 变更](https://docs.etherscan.io/changelog)将上述两种 Free 单次记录上限设为 1,000，本文仍只取 300。
此为公开文档核验，不是实际账户配额或性能测量；多个 Key 的可用总量、共享限制与其他业务占用由运行时核实，不能直接乘算吞吐。
[普通地址接口](https://docs.etherscan.io/api-reference/endpoint/txlist)与[内部地址接口](https://docs.etherscan.io/api-reference/endpoint/txlistinternal)分别建能力及错误统计，不把所有历史查询假定为某个其他端点的限流档位。

## 5. 原始记录、交易证据与去重

原始页中的每条出现位置以 `(sample_id,row_ordinal)` 保存，重复内容也不抹掉，以便核对提供方实际响应。
规范普通交易身份为 `(chain_id,tx_hash)`；内部转账优先使用 `(chain_id,tx_hash,provider_namespace,trace_id)` 并验证其内容一致。
`trace_id` 作为提供方不透明身份，不靠字符串排序推断执行先后；同身份内容冲突进入证据冲突状态，不任选一条。
未返回可靠内部身份时，保留原始出现位置及 `identity_unresolved`，不能用 `(tx_hash,from,to,value)` 合并可能真实存在的两次相同转账。
未解决的身份不进入去重金额汇总或驱动上游节点扩展；展示其已知流水与缺项，不能靠重复原始页虚增金额和钱包。
若后续获得足以可靠对应已选原始条目的身份依据，建立该原始行到规范证据的关联，再幂等生成关系；仅新响应出现一个相似条目不构成依据，不因此获取第二页历史或通用全量 trace。
普通与内部记录若确实描述同一实际转账，只有存在可靠对应依据才共享 `canonical_transfer_id`；疑似重叠而无法确认时保留未定，不按字段相同猜合并。
确定的普通交易证据不因身份未定的内部副本被删除；该副本只保留原始依据，不再次计额。

行为交易集合为普通样本哈希与内部样本关联顶层哈希的并集，按链和哈希共享交易内容及回执。
回执补证必须验证交易哈希、区块身份和成功状态；失败或缺失单独记录，内部行成功标志不能覆盖顶层回滚。
内部子调用明确失败或回滚时不生成成功入账；证据不能确定是否成功时保留未知，不把父交易成功当作所有子调用成功。
共享交易对象只节省重复取数；`project_wallet → sample → tx/log/evidence` 关联保留每个钱包为什么进入分析范围。
同一交易可能涉及多个项目钱包，每个钱包行为须分别取证，不能将整笔交易的所有买卖复制到所有关联钱包。

## 6. 历史部署和代币交互解析

直接部署只接受当前钱包为顶层 `from`、顶层创建且成功的证据；地址来自普通记录 `contractAddress` 或有效创建回执。
保留失败创建尝试，内部 `CREATE/CREATE2` 不生成本版成功直接部署清单，也不成为发现新项目的入口。
交易项目按链和 Token 地址关联已有项目及静态报告；名称、符号、方法名只作描述，不作地址身份依据。
首版明确买卖覆盖 Uniswap V2/V3/V4、Sushi V2/V3、PancakeSwap V2/V3；复用可信 Factory／Manager 与池币种映射及独立协议 ABI。
只有可信 Swap 证据和当前钱包的实际支付、接收或可验证路由关系能支持买入／卖出归属；单独出现 Swap 或钱包是顶层发起人均不足以归属全部路径。
聚合器、多跳、合约钱包、转账税或钩子导致归属不明确时保存 `unclassified` 及已有证据，不强行分为买入或卖出。
授权、普通转账、被动收款和其他交互独立分类；同交易允许多个有依据的行为，不将被动收款解释为主动参与项目。
必要补证只服务已有样本关联的交易，不增加原始历史页、不强制固定 Router 或报价资产，不做全市场完整交易声明。
每条行为保存规则版本、覆盖版本、钱包归属依据、日志位置、缺失原因与项目链接；规则无法解析属于事实边界，技术请求失败另列。

## 7. 资金门槛、内部归因与路径证据

项目开始时固定 `funding_threshold_atomic`，ETH 默认 `10^16 wei`；后续链配置变化不重算当前项目既有或未来派生关系。
仅成功、未回滚、实际转入当前钱包 W 的非零原生 ETH，且单条金额达到门槛，才有资格生成资金关系。
普通入账为真实 `from → W`。小额之间不累计、不按净额取代单条判断；代币入账和出账不派生本版上游／下游。

| 内部 A 调用 C、C 向 W 入账的条件 | 关系与扩展 |
| --- | --- |
| 实际转出方 C 命中管理员本链交易所／跨链库 | 优先 C→W 内部实际关系；C 作为终止来源完成本层双历史与行为；不穿透 A |
| C 未命中，A 已知且不是 W | A→W 发起人归因；保留 C→W 实际证据，C 不因中转占层 |
| C 未命中，A 自身命中地址库 | 保留归因及实际证据，A 完成本层研究后停止上溯 |
| C 未命中，A=W | 保存自身发起回款，不新增外部来源或外部来源金额 |
| C 未命中，A 未取得 | 保存已知 C→W 流水及缺失原因，不猜测归因和来源节点 |

实际转出方优先规则先于自身回款和发起人缺失判断；任一节点继续扩展仍须满足项目研究中、当前节点可扩展和 L5 边界。
每条内部入账只有一个计额证据；A→W 归因和 C→W 实际流水是同一笔入账的两个视角，不能相加。
关系类型固定区分 `normal_direct`、`internal_initiator_attribution`、`internal_terminal_direct`，关系引用实际证据而不复制金额。
归因不证明 A 实际出资、控制 C 或控制 W；提供方标签可展示，但不替代管理员地址库精确命中。
金额与笔数汇总使用同一组已确定去重证据；未定身份与失败记录分别计数展示，不混入成功资金总额。
实际路径逐跳检查上游入账早于下游出账，先比较区块、交易序号；同交易内部先后缺证据时保持未知。
时序不满足的关系仍留在历史图，不能标为该笔入账的连续路径；时序满足也不证明混合资金归属，归因边始终保留归因语义。

## 8. 图扩展、最短层级与地址库变更

项目钱包按 `(project_id,chain_id,address)` 唯一，历史 L1 锚点的深度为 1；其他节点按逆资金方向到任一锚点的最短距离定层。
新增来源边对来源节点执行最短距离松弛；共享来源只保留一个节点，反向边、循环和跨层边全部保留。
节点从 L5 变为 L3 时复用既有双历史及行为结果，补执行新剩余深度允许的上游扩展，不重复下载相同页。
扩展检查键包含节点、已处理证据位置、允许深度和 `extension_generation`；同代同范围不重走循环。
L5 和命中终止库的节点完成自己的两类历史与行为分析，但不新增更上游节点；图内已存在节点之间的已知关系可以保留。
不限制每层来源数量，使用持久分页遍历和有界内存批次处理全部已发现分支；技术批次大小不是业务截断上限。

地址库以链和精确地址匹配，保存类型、名称、依据、库版本；更新后在项目内推进受影响节点的 `extension_generation`。
链级地址库版本在管理事务中立即生效；扩展提交重新核对当前版本与命中事实，不能等待异步节点代次同步才阻止新上溯。
新增终止标签取消受影响节点尚未开始的扩展；已经开始的任务可以保存本层事实，旧代结果不得派生新上游任务。
移除标签只对仍研究中的项目建立新代扩展，恢复尚未执行或因标签抑制的范围，不重复旧证据计额、不重取固定样本。
已有节点、资金边和原始证据不因标签变化删除；新决策记录实际使用的库版本，不把旧归因证据偷偷改写为另一来源。
已处理入账沿用生成关系时的归因决策，标签变化只影响未执行的后续扩展，不对同一证据再生成一笔不同来源的可累计入账。
角色关闭不推进用于终止扩展的取消代次；历史 L1 仍有效。项目停止则按共同停止栅栏禁止任何新派生，与标签或层级变化无关。

## 9. 六项资产与固定路径估值

仅历史 L1 锚点具有首轮资产任务；L2–L5 不查询余额。普通活动不重抓固定历史图，资产刷新只接受已授权数据组的刷新任务。
ETH 固定资产集合为原生 ETH、WETH、USDT、USDC、DAI、WBTC；合约地址、精度和可信部署按 ETH 配置版本保存，不按符号动态找币。
每次资产轮次在实际采集开始时固定观察区块 O，保存区块哈希、链上时间、采集时间和路径版本；所有余额、池状态、价格均指向 O。
读取指定区块失败不能退回 latest，也不能用另一高度的价格补齐本次余额；历史快照始终保留其实际观察依据。

| 资产／情形 | 估值规则 |
| --- | --- |
| 原生 ETH | 原生余额乘 WETH 对 USDT 的固定路径价格，无需实际包装 |
| USDT | 按原始余额与自身精度直接计值 |
| WETH、USDC、DAI、WBTC | 使用各自配置路径，不将稳定币固定按 1:1 |
| 已确认余额为零 | 独立记录余额及价值为零，无需价格即可视为本项完整 |
| 非零而路径／池状态／价格缺失 | 保留余额与原因，价值未知；不得写成零 |
| 余额读取失败 | 余额和价值均未知，保留错误；不得作为零余额处理 |

管理员路径只允许首版七协议可信部署，直接到 USDT 或最多一个中间资产；逐跳币种衔接、方向、池身份及终点必须校验。
V2 使用同块储备比例，V3/V4 使用同块平方根价格及币种方向取得现货比例；零储备、无有效流动性或无合法价格使该路径不可用。读取依据为 [V2 getReserves](https://raw.githubusercontent.com/Uniswap/v2-core/master/contracts/UniswapV2Pair.sol)、[V3 slot0](https://raw.githubusercontent.com/Uniswap/v3-core/main/contracts/interfaces/pool/IUniswapV3PoolState.sol)及 [V4 StateView](https://raw.githubusercontent.com/Uniswap/v4-periphery/main/src/lens/StateView.sol)，各部署使用与其版本匹配的适配器。
Token0 到 Token1 的单位价格为 V2 的 `(reserve1/reserve0) × 10^(decimals0-decimals1)`，或 V3/V4 的 `(sqrtPriceX96²/2^192) × 10^(decimals0-decimals1)`；反方向取倒数，逐跳方向和精度分别核验。
V4 按可信 Manager、完整 PoolKey 和 poolId 核验；动态费与 hooks 不被推断为实际成交承诺，本资料是现货标记价值，不执行交换或报价模拟。
原始余额及储备使用整数，价格和逐跳相乘使用任意精度有理数；全过程不使用二进制浮点，不在每跳提前舍入。
保存估值分子／分母和精度，展示时按声明精度舍入；六项已知小计先汇总精确值再舍入，避免把显示舍入误差当作资产差异。
每项保存资产、余额、价值或缺项、路径、池、读取方法与状态证据；无需路径的零余额和 USDT 也保留各自依据。
本次小计仅包含同一快照已确定价值；一项缺失即标记总值不完整并列出缺项，不能用旧余额或旧价格填缺。
首次响应后同块重试可补全该快照；新观察区块必须新建快照。路径配置变更仅影响以后轮次，不回算历史。

## 10. PostgreSQL 持久对象与事务

以下为目标逻辑表；实现时由迁移、sqlc、模型和查询消费者一并落地，不复用旧 JSON 汇总替代逐条事实。

| 对象 | 核心内容与唯一约束 |
| --- | --- |
| `project_wallet` | 项目、链、地址唯一；历史 `l1_anchor`、首次加入时间、最短层级、扩展代次及分项进度 |
| `wallet_role_interval` | 项目钱包、角色／用途、来源身份、有效起止、当前／历史标记；重复观察幂等 |
| `wallet_history_sample` | 采样缓存身份、响应版本、原始页、固定参数、数量和状态；共享 head 不控制已有项目选页 |
| `project_wallet_history` | 项目钱包和历史类型唯一；首次选定的 `chosen_sample_id` 不可替换，保存选页时间和采样规则版本 |
| `wallet_history_sample_row` | 样本及原始序号唯一；不可变原文、校验状态、规范证据关联及身份缺失原因；字段补证另存版本和可靠匹配依据 |
| `transaction_evidence` | 链、哈希、交易／回执类别及证据版本；内容冲突显式隔离 |
| `transfer_evidence` | 规范转账身份、实际两端、整数金额、成功依据、发起人、顺序与来源样本 |
| `funding_relation` | 项目、关系类型、规范转账证据、来源与接收钱包；显示边聚合不另造入账事实 |
| `wallet_behavior` | 项目钱包、交易、行为、规则版本及钱包归属证据；同交易可有多个不同事实 |
| `wallet_asset_snapshot` / `wallet_asset_item` | 钱包、轮次、观察块、路径版本；六项独立状态、精确价值、同次小计和完整性 |
| `wallet_extension_progress` | 节点、代次、允许深度、证据位置、抑制原因；恢复无需依赖内存图 |

角色生效、L1 登记、必要初始任务和项目查询修订在一个事务内提交；复用样本只新增项目关联，不复制每个角色的数据。
每钱包每历史类型的页及状态独立提交，不等待其他钱包或另一类成功；首次选页与固定成员关联同事务发布，有效行与失败明细一同可查，后续补证不能改变成员集合。
扩展提交锁定项目及节点，核对 `project.research_state`、`project.revision`、任务 `claim_generation`、`extension_generation` 及已选样本行身份，再原子写关系、节点与派生任务。
节点、角色或关系投影发布时同步推进 `graph_revision` 并保留有效版本区间，支持查询文档约定的固定图版本分页；修订不改变证据身份。
在途任务遇到停止或扩展旧代可保存其被允许的事实结果，但派生提交必须拒绝；不能先发布节点、再异步发现任务本不允许创建。
资产逐项提交与快照小计、完整性修订同事务更新；较旧轮次的晚到结果只补自己的快照，不能覆盖新快照当前指针。
租约失效拒绝过期工作进程写入；数据库提交失败重放同一结果的幂等写入，不虚增提供方调用计数。

## 11. 调度、恢复与进度

L1 普通、内部和资产首轮分别以 `l1_joined_at → first_result_visible_at` 统计 P95 ≤ 10 分钟，包含排队，命中有效缓存的持久关联即形成可查结果。
资产首轮完成点要求六项均有真实首次结果或明确共享请求失败依据；只返回一项、其余仍等待的快照可展示进度，但不能计为完整首轮响应。
实际空结果、失败待重试和部分结果如实可查；未发出请求的等待状态不能计完成，成功率及缺项率单独统计，不能靠快速失败满足质量目标。
某类已从深层完成后加入 L1，可直接引用其有效结果；首次成为 L1 的时间不因后续角色变化或重复任务重置。
历史行为补证、解析和 L2–L5 在项目间公平使用 L1 首轮后剩余配额，逐层持续推进，无全图统一完成期限。
公平调度与背压采用共同运行时的持久队列；监控分项目等待年龄，不能让单个高分支项目独占剩余额度，也不能把后台并发上限变为分支上限。
瞬态采集每轮最多 3 次真实请求；未取配额不算开始，`first_started_at` 与租约代次遵守共同运行时，不在本文另设重试计数。
停止取消未开始任务，已开始任务可按原有限重试收尾，不新建补证、资产刷新或来源扩展任务；不同任务不能借共享交易缓存绕过停止栅栏。
重启从原始页、规范证据关联、扩展游标与快照项恢复；只重做未完成部分，不重新从 L1 遍历所有已完成分支。
查询分别显示样本覆盖、补证进度、解析边界、各层已知／待办节点、L5／标签终止和停止取消原因；未知总节点数时不伪造全图完成百分比。

## 12. 验收与实现核对

| 场景 | 必须验证的结果 |
| --- | --- |
| 部署回执慢或失败 | 项目发现与后续区块不受阻；后台接收钱包状态独立可查 |
| 净接收排序含合约、自转账和代码读取失败 | 只选已确定净正且观察块无代码的最多 5 个，不猜排名 |
| 同地址四角色；旧 owner 失去最后当前角色 | 一个历史 L1 和一套双历史，当前身份关闭，历史及上游继续 |
| owner 为零、同一 fee 数组部分成功 | 零值保留依据不研究；已证实非零地址立即加入当前来源角色和 L1，仅整项完整成功才能撤销旧集合 |
| 普通 300、内部 300；B=0 | 两类独立，过滤不补页；空范围无提供方请求 |
| 一个钱包／一类失败 | 其他已取得结果可查，原始页、失败与成功状态互不覆盖 |
| 首个部分页后重试返回不同第一页 | 项目原始成员及样本 ID 不变；可靠匹配只补字段，不匹配条目仅审计，各类派生仍限原始至多 300 条；尚未选页的新项目可独立选新页 |
| 两条相同金额内部记录无 traceId | 原始两条保留，身份未定，不 tuple 合并或重复计额扩展 |
| 两条 0.006 ETH 与一条 0.01 ETH | 只后一条达标，门槛变更不影响已有项目 |
| A→C→W，C 命中／A 命中／A=W／A 缺失 | 按优先级保留真实与归因证据，不穿透终止 C，不猜来源 |
| 新内部哈希、多钱包同交易、模糊聚合器路径 | 补证一次、钱包归属分别验证，不将全交易强分买卖 |
| 共享来源、循环、L5 后发现更短路径 | 唯一节点和去重金额，保留循环；只补新深度允许扩展 |
| 标签新增与在途提交竞态，移除后恢复 | 旧代可存事实不派生；研究中恢复未执行范围，停止不重开 |
| WBTC 非零缺价、USDC 非 1:1、零余额无路径 | 非零缺价为未知，稳定币用实际路径，零余额本项完整 |
| 资产项失败、同块重试、新轮次先完成 | 同次部分值立即可查，不跨快照填缺，旧轮次不覆盖新指针 |
| 数据库失败、租约过期、停止与派生并发 | 幂等恢复且拒绝过期写入，停止后无新任务首次启动或派生 |
| 冷缓存、多项目高分支持续负载 | 分别验证 L1 三项首轮时效与质量，深层公平推进，不截断范围 |

实现验收需记录实际 RPC、Etherscan 账户额度、并发负载和缓存命中条件；本次只形成书面目标，没有运行真实账户请求、数据库迁移或容量测试。
