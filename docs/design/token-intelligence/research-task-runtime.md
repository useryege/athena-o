# Token 研究任务运行与提供方调度

> 设计状态：设计中（分节方案已确认，书面规格待审阅；尚未实现）。
>
> 本文定义第一板块后台研究的目标运行机制，不描述现有六源采集器已经具备这些能力。
> 业务只采集、解析、保存和展示事实，不产生评级、排除、移交或交易决策。

## 1. 范围与关联

采用分职责进程与 PostgreSQL 持久任务：研究协调、链上读取、Etherscan 采集、Ave 采集、AI 分析和钱包解析分别运行。
同一构建产物按启动配置承担职责；扫描、活动和 Swap 监控属于链实例，研究执行按任务所带链身份访问资源。
研究任务不阻塞逐块发现保存，不以全部资料完成作为项目展示或研究停止的门槛。
不沿用固定六类任务、整项目终态屏障或单个不可变画像；`simulation_result` 不进入新运行模型。

## 2. 时效与计时边界

以下目标适用于提供方正常、实例健康且输入负载处于已校准容量范围内的运行；超载仍保留任务并报告积压，不截断业务范围。

| 路径 | 起点与结果 | 目标 |
| --- | --- | --- |
| 追平后的发现、活动、Swap | 链上数据可获得至对应事实可靠处理；研究进程不得占用其保留资源 | 各 P95 15 秒 |
| 三天发现补扫 | 已确定三天起点至发现游标追平；不等待后台研究 | 2 小时 |
| 新项目基础资料 | 项目及初始任务提交至 Token 当前状态、源码首次请求、Ave 总数、Top 100 各自真实首轮状态 | 各 P95 1 分钟 |
| 五类 AI 产物 | 非空源码就绪至质检、公开链接、owner、税费接收方、税率各自产生首次有效分析；已有有效结果直接复用 | 各 P95 5 分钟 |
| 新 L1 资料 | 地址加入 L1 至普通历史、内部历史、六资产快照各自真实首轮状态 | 各 P95 10 分钟 |
| 活动资料刷新 | 依赖已就绪且本组冷却已结束至该轮真实首轮状态 | 各 P95 1 分钟 |
| 钱包行为及 L2–L5 | 在公平后台持续推进，公开实际进度与缺失原因 | 不设整图统一完成期限 |

真实首轮状态是实际读取产生的成功、成功空、部分成功或具体失败，不包括仅创建、排队、领取任务或等待配额。
基础资料不等待 AI、owner 或钱包；Ave 两个接口分别计时，不能以其中一个成功代表另一项完成。
有效 AI 分析包括有依据的未发现或未识别可用方式，不包括超时、格式错误或伪造的全否结论。
尚未产生要求结果的超期任务进入未达标数量及在途年龄指标，不从统计中消失。
记录依赖等待、冷却、配额等待、队列等待、外呼和提交耗时，以说明实际延迟；异常期间仍报告实际端到端延迟。

## 3. 持久契约与任务身份

| 记录 | 唯一身份及职责 |
| --- | --- |
| `project` | `research_state` 表达研究或停止，`revision` 随影响调度的生命周期变更递增；两者均在项目事务中维护 |
| `research_task` | `scope + subject_key + task_kind + generation`；任务状态、依赖、可执行时间、首次执行时间、租约与错误 |
| `research_task_dependency` | 父任务、产物条件、子任务；满足真实业务依赖后解除等待，不要求所有同项目任务终态 |
| `research_group_state` | 项目与资料组；请求代次、运行代次、合并后继、冷却和已处理触发位置 |
| `research_task_attempt` | 任务、外部操作键、请求序号；预算预留、派发登记、响应、结果不明及终态证据 |
| `shared_work` / `shared_work_demand` | 共享产物运行及各项目或管理员的需求；项目需要执行的状态与永久展示引用分开 |
| `fact_observation` | 不可变事实或尝试结果；来源、观察区块、采集时间、输入版本、内容摘要及完整性 |
| `project_fact_head` | 项目、事实项与主体；最近有效成功、最近尝试和本次资产快照指针 |
| `provider_budget` / `provider_reservation` | 提供方、账户、key、端点预算及唯一请求预留；多进程共同计额 |
| `research_outbox` | 与事实、任务状态同事务保存的唤醒及下游协调消息；消费者幂等处理 |

项目主体可为资料组、钱包、交易或某项读取；项目身份始终包含链，不能按地址跨链复用。
`generation` 表示业务刷新或重检轮次，`research_task.claim_generation` 每次领取递增，只用于隔离旧执行者。
派发记录捕获 `project.revision`；提交发现版本变化时重新判定允许动作，不能将停止前已开始的合法收尾结果一概丢弃。
重复事件使用项目、事件身份、动作和目标组的幂等键；重复消息不会新建刷新轮次或重复增加需求。
钱包样本复用键包含链、地址、部署前截止块、普通或内部类型及采样版本；解析另带规则版本。
跨项目仅复用完全匹配的证据；各项目角色、门槛、层级、地址库判断和派生义务分别保存。
同一结果可以被多个项目引用，但不由一个项目停止删除，也不按地址永久缓存有界历史。
任务负载引用结构化输入和证据标识，不把全部源码、钱包历史或项目图反复复制进队列。

## 4. 状态机与执行租约

任务状态固定为 `waiting_dependency`、`ready`、`running`、`retry_wait`、`succeeded`、`failed`、`canceled`。
依赖未满足时保持等待；依赖得到明确不可用结果时保存实际原因，终结不能执行的子任务，不伪造业务否定事实。
研究中的成功空源码仍可能被后续合法补采补齐，相关分析等待非空产物条件，不将一次空响应当作永久不可用。
`ready` 或已到时间的 `retry_wait` 可以领取；过期 `running` 由恢复器检查请求记录后重新协调。
领取使用 `FOR UPDATE SKIP LOCKED`，递增 `claim_generation`，默认租约 30 秒、每 10 秒续租。
所有续租、重试、失败和提交同时校验任务、代次、运行状态及 `clock_timestamp()` 下仍有效的租约。
外部请求不持有数据库事务；进程关闭、失租或续租失败取消本地调用，并禁止旧执行者更新事实和任务。
任务 claim 本身不设置 `first_started_at`；等待依赖或配额不算已开始，不因此获得停止后的执行资格。
提交前验证租约；同一成功代次重放相同内容摘要为幂等，不同摘要为完整性错误。
数据库写入错误不冒充提供方失败；但先前已经登记派发的请求仍占原请求序号，不能因持久化失败重置次数。
执行者崩溃后的恢复先检查该次是否有已保存结果；可复用时仅重做提交，不重新调用提供方。
无法确定外呼是否发生或完成时标记该次 `outcome_unknown`，只允许在剩余额度内创建下一请求序号。
任务表的三种等待原因分别保留依赖、冷却和资源阻塞说明，避免单个 `pending` 掩盖实际进度。

## 5. 派发、停止与提交事务

项目任务首次派发事务锁定项目和任务，核验 `project.research_state` 为研究中、依赖满足、代次有效，再原子取得全部适用预算。
取得预算后登记唯一请求序号和 `first_started_at`，提交事务后才允许执行对应外呼。
纯解析任务取得受限 CPU 执行槽后在相同生命周期事务中登记开始，不创建外部请求序号。
预算不足则保持可等待状态，不登记执行、不占请求次数；领取线程释放任务并按下一可执行时间重排。
停止事务与首次派发竞争相同项目锁：停止先提交则禁止派发；派发登记先提交则该任务属于允许收尾的在途任务。
停止命令只锁定 `project` 行，写入权威停止状态、递增 `project.revision`并提交清理outbox；不枚举或锁定共享工作，不同步取消整张项目任务图。
事务提交与远端接收之间不存在跨系统原子性；派发登记后崩溃即使可能尚未发送，也保守占用该次。
每个请求序号只允许登记的执行者发送一次；失租恢复不能重新发送同一序号，也不承诺远端 exactly-once。
派发许可默认 1 秒内使用，执行者同时检查许可期限及有效 claim；过期许可禁止发送，该次保守终结后由恢复流程决定剩余重试。
项目停止立即使 `first_started_at` 为空的任务失去派发资格，outbox后台分批标记取消；已有首次执行时间的 `retry_wait` 仍按原有限次数收尾。
停止后禁止创建新的项目下游任务，包括新钱包、扩展层、链上读取和活动刷新；已开始逻辑任务的剩余重试不是新下游。
成功提交事务保存尝试、不可变事实和成功指针，并只对仍研究中的项目写入新的项目下游任务或协调消息；共享产物可用消息继续遵循订阅规则。
失败提交事务保存真实失败和最近尝试指针，不覆盖最近成功；终态错误不会阻止其他独立分支提交。
状态读取区分“研究已停止、在途收尾中”与“专属事实已冻结”；冻结只等待停止前已登记且仍可能写入本项目专属事实的在途任务终结，不等待后台取消标记遍历。
仅更新共享版本的分析不阻塞项目专属事实冻结；共享需求自身的收尾固定关联停止前已授权的运行版本，不等待其他项目或管理员后续重检，也不追逐最新共享版本。
有限请求次数不等于固定收尾时长：已开始任务若等待已知日额度重置，继续展示资源等待，不能冒称已冻结。
旧 owner 或税费地址失去最后一个当前角色后仍保留历史 L1，继续尚未完成的历史及上游研究。
零地址保存其原始读取结果及解释，不创建 L1 节点；角色切换与活动监控遵循生命周期文档。

## 6. 一个运行轮次与一个合并后继

每项目每资料组最多一个逻辑运行轮次和一个合并后继；运行轮次包括其有限重试等待。
触发事务锁定组状态：尚未开始的轮次吸收新触发；已开始则更新唯一后继的目标代次和最新触发位置。
首次实际派发登记时启动该组 10 分钟冷却；领取、排队及失败重试不重新开始冷却。
后继须同时满足前轮终结、依赖就绪及冷却结束，才可派发；触发次数不是请求次数。
`Approval` 仅续期，不创建本机制中的源码或资料刷新任务；部署者和当前 owner 的主动交易不刷新其他资料。
源码补采使用独立的 `source_acquisition` 协调状态，只共享一个运行和一个合并后继规则，不套用 Transfer 资料组的 10 分钟冷却，也不新增固定源码冷却。
源码成功空响应结束本轮，只有新的合法活动或管理员补采需求才可形成后继；不设置周期源码查询。
源码重复触发保留一个后继，待当前轮次结束并取得配额后执行；若已出现可复用非空源码，直接关联并终结，不重复下载。
项目停止取消尚未开始的后继；当前轮次即使仍有重试权，也不得在完成时释放出新的项目轮次。
观察期限续期不受上述冷却影响，不能排到资料刷新任务之后才执行。

## 7. 独立事实与钱包小任务

### 7.1 基础资料适配契约

Token 当前状态固定使用本次明确观察区块读取 `code.length`、`name`、`symbol`、`decimals`、`totalSupply`、`balanceOf(零地址)`及`allowance(零地址,零地址)`。
保存每项原值、是否执行、调用或解码诊断、区块号与区块时间；无代码时六项记录未执行，后续读取结果不改写最初不可变识别结论。
聚合外层 RPC 失败属于技术失败；单项空值、零值或调用失败保留逐项事实，不重新排除已识别项目，也不抹掉其他可取得项。
Ave 总数调用 `GET /v2/tokens/{token-id}` 读取 `holders`，Top 100 调用 `GET /v2/tokens/top100/{token-id}?limit=100`；端点依据 [Ave 官方 V2 文档](https://docs.ave.ai/reference/api-reference/v2)。
复用现有 `util/ave/ave.go` 的链映射及 token-id 规范：ETH 使用小写合约地址加 `-eth`，使用 `X-API-KEY`；请求记录绑定链和 Token。响应若返回链/Token 身份则必须匹配；Top100 未回显这些字段时按请求身份关联，不虚构回显或仅因缺少未承诺字段报错，返回结构仍须校验。
总数必须是实际取得的非负整数；Top 100 保留排名、地址、`amount_cur`、原始 `balance_ratio`、`remark`及`addr_alias`，缺失字段不填零。
两接口独立任务、独立请求次数及成功指针；分别记录查询起止时点和提供方更新时间，不伪造链上观察块或假设同区块快照。
少于100条或明确成功空列表按实际保存；超过请求边界、身份冲突或畸形结构记为技术失败，不静默截断后宣称成功。
提供方明确暂未收录时记录“提供方暂无数据”，不补成零持有人、不回退到 Etherscan，也不新增定时轮询；后续合法刷新可再次查询。
Top 100不是完整名单，不补页、不重算名单外分布；持有人仅匹配已有角色，不能自动加入 L1–L5 或触发钱包研究。
Ave 地址标签仅作为提供方事实，不代替管理员终止库；Token Detail 仅投影持币总数，不恢复市场、池、流动性或风险标签业务采集。

### 7.2 钱包独立工作与事实指针

普通历史、内部历史、L1资产分别建任务并独立保存；同钱包一类失败不能回滚另一类的成功或空样本。
每次历史查询固定 `0..B-1`、倒序第一页、最多 300 条原始记录；过滤后不翻页，不由任务重试扩大范围。
交易详情及回执按链和交易哈希去重获取；解析保留样本与钱包关联，不能将整笔交易所有行为归给每个关联钱包。
样本成功后即可派发有证据可做的行为或资金处理；缺失父交易、回执或顺序证据单独阻塞相关判断。
一个钱包或一组有界交易解析作为工作单元，不能在内存收集整个项目或整层后才一次提交。
解析可按持久游标分批，批量大小只约束一次工作量，不限制该钱包既有样本内必须处理的记录。
节点以距任一历史 L1 的最短距离分层；更短路径更新扩展代次并补齐允许范围，不能第一次访问后永久跳过。
派生事务核验项目状态、当前层级、扩展代次和管理员终止标签；L5及终止节点完成本层研究但不扩展。
标签新增保留事实并停止后续扩展；移除仅恢复研究中项目尚未执行的义务，不恢复已停止项目。
资产快照在开始时确定唯一观察区块，余额、路径池状态、价格及重试都使用该区块。
六项资产和各价格依赖逐项保存；快照状态包含本次已知小计、缺项和完整性，不从旧成功指针补齐当前缺项。
链上事实项指针以观察区块、业务代次和结果身份排序；Ave等无观察块事实按业务代次及查询时点排序，旧结果不能覆盖更新事实。

## 8. 公平调度与容量隔离

实时发现、活动和 Swap 使用独立 RPC 保留并发、连接池及请求预算，深层研究不得借用这部分容量。
研究资源池区分基础资料及刷新、新 L1 首轮、公平后台；五类 AI 使用其独立提供方预算并行协调。
默认研究权重为 `4:4:1`，前两类共同保证新 L1 不被持续基础流量饿死，后台保留可用研究容量的公平份额。
后台只使用实时保留和前台保障以外的研究容量；它的最低份额不来自挤占实时保留槽位。
同类内部先按项目，再按钱包或主体轮转；RPC、Etherscan、Ave建议每项目每提供方最多 2 个在途请求，未用槽位供其他项目使用。
LLM按共享产物及全局token预算独立并行，不套用每项目2槽限制；否则五产物在120秒单次时限下可能因三波串行超过5分钟。
有时效的同类任务按距离自身目标的剩余时间排序，但不能使同类另一个项目永远得不到服务。
后台 L2–L5 默认权重 `8:4:2:1`；各层均有非零服务份额，不使用严格浅层优先。
等待 15 分钟的后台任务获得老化提升，仅在后台资源池内提高位置，不升级占用实时资源。
空闲研究份额可借用，保障任务到达后停止借用新槽位；已派发请求不为抢占而重复执行。
按预计请求数或 token 消耗计算调度成本，以实际消耗校正；一个任务包含较多操作不能只收取一次成本。
各项目轮转位置和服务欠账由 PostgreSQL 持久协调，多副本不能各自独立优先处理同一大项目。
深层排队没有整图期限，持续发布待做节点数、最老年龄和各层取得状态；不得增加隐含来源数量上限。
上述权重、并发和老化时间是可调整技术初值，尚未经过负载验证；调整不得改变业务范围或取消公平份额。

## 9. 全局提供方预算

预算约束沿提供方、账户、API key、端点逐级生效；同一 key 从不同进程、Gateway 或链实例调用不增加额度。
多个 key 若共享账户额度，必须同时扣账户预算；只有已确认独立的额度才能相加。
配置包含可持续速率、允许突发、窗口请求总量、日总量及重置时区、并发上限和端点特有限制。
速率用持久化 GCRA 下一允许时点协调，缺少已核实突发额度时按无突发配置；日总量按提供方实际窗口边界计数，均使用数据库时间。
所有预算行按固定身份顺序加锁；一次事务取得全部必需额度并创建唯一 reservation，任一不足则全部不扣。
reservation 同时记录请求数额度、在途槽位、额度窗口和截止时间；LLM另预留输入及最大输出 token 预算。
真实响应已持久化时释放在途槽位；请求已派发则请求次数不退回，已知 token 实耗可归还未用预留。
确认尚未登记派发的预留可以释放；登记后结果不明时保守记额，在途槽位按请求截止及恢复宽限回收。
结果不明的 token 预留不凭猜测返还，在对应窗口到期释放；重启不能将持久窗口消费清零。
恢复器按 reservation 身份幂等回收，旧代次不能释放新请求的槽位或重复返还额度。
调度入口统一适用于首次请求、重试和管理重检；应用 SDK 或 Gateway 不再叠加不可见的自动重试。
[Etherscan 官方套餐表](https://docs.etherscan.io/rate-limits)的免费版 3 次/秒、100,000 次/日仅为配置核对基线，不是仓库 key 的实测容量或所有端点承诺。
部署前按实际账户、key、端点和套餐校准；Ave、RPC与LLM同样使用各自实际配置，不默认无限额度。
容量不足时保留队列、显示预计可执行时间并产生运维告警；不自动购买额度、增加凭据或减少五层分支。

## 10. 错误分类与有限请求

| 情况 | 次数及恢复规则 |
| --- | --- |
| 依赖、冷却或配额等待 | 没有外呼，不消耗请求序号；持久保存阻塞原因与下一可执行时间 |
| 实际返回 429 | 该次计数；采用 Retry-After 或有抖动退避，暂停受影响账户、key或端点，不切换出口规避同一额度 |
| 已知日额度耗尽 | 暂停到真实重置时点；等待不增加次数，独立有效额度仍可调度 |
| 凭据失效或权限不足 | 隔离受影响凭据或能力并告警；有合格替代资源时使用剩余次数，否则当前已执行请求按不可恢复错误终结 |
| 参数非法、方案不可执行 | 当前任务技术失败，不反复调用，不改成无源码、无owner或无税率 |
| 网络超时、5xx、暂时上游错误 | 使用剩余序号有限重试；超时与结果不明均保留证据 |
| 成功空源码或空历史 | 成功的明确空事实，终结本轮，不进入失败重试 |
| 数据库错误、失租 | 恢复已登记状态；不虚构提供方响应，也不撤销已发生或结果不明的请求次数 |

源码每轮最多 4 次；其他瞬态采集操作最多 3 次；每种 AI 分析运行最多 2 次，均包含首次请求。
一次逻辑任务含多个独立外部操作时，按操作键分别登记次数；不能用更换子任务或租约代次重置同一操作预算。
源码退避初值为 5、20、60 秒，其他瞬态采集为 5、20 秒，AI为 5 秒；采用约 20% 抖动且不早于提供方明确的恢复时间。
默认 Etherscan、Ave单次外呼超时 30 秒，研究RPC为10秒；AI单次120秒，两次执行与退避为5分钟目标留下排队空间。
AI结构或依据引用校验失败属于本次技术失败，可在剩余次数内重新请求；不能额外增加不计数的修复调用。
次数耗尽保存终态失败及实际原因；源码失败耗尽通过事务 outbox 提交通知，提交失败由 outbox 重试，不重发源码请求。
其他技术故障使用运维告警去重汇总；项目正常研究停止只记录原因和证据，不发送管理员业务通知。
已有有效分析或成功事实保留，技术失败不缓存为可复用的否定结论；只有新的合法业务触发或明确管理重检创建新业务代次。

## 11. 共享静态工作与订阅冻结

五种共享 AI 产物分别使用 `code_hash + artifact_kind` 定位最新有效版本，每个运行关联实际源码及其不可变输入摘要。
同一产物默认一个运行及一个合并后继；管理员操作保留各自审计及幂等标识，重复提交不无条件并发执行。
当前管理入口只提供已确认的质检报告重检，不因此新增其他四类分析的独立手动重检或随报告自动重跑。
提示词或模型配置变化不自动使已有有效结果失效，也不自动批量重检；明确重检才产生新 requested revision。
输出版本不可变；成功后用代次比较更新最新有效指针，迟到旧运行不能覆盖更新成功版本，失败重检保留旧有效版本。
共享需求分别记录等待执行、已纳入在途运行、已满足、冻结；项目展示引用独立保留，不因需求冻结删除。
共享任务首次派发先锁定固定产物键的 `shared_work`，再按稳定项目ID顺序锁定有界候选批次中的项目，核验权威研究状态及实际需求，取得配额后登记本次运行和相关需求的首次在途资格。
候选批次只限制短事务工作量；其余活跃需求可随后关联同一在途运行，不限制共享项目数量。单项目停止只竞争该项目行，不反向等待共享工作锁。
没有仍研究中的项目需求且没有明确管理员需求时，首次派发即被禁止；后台清理将未开始共享工作标记取消。清理尚未完成不能成为继续派发的依据。
共享运行已经开始时，即使最后活跃项目随后停止也按原次数收尾；冻结需求保留其已授权运行的结果关联，供展示而不派生专属任务。
仍有其他研究中项目或明确管理员报告重检需求时共享工作继续；停止项目不因此获得新的专属读取或钱包任务。
共享运行中加入新项目仍按共享工作、项目、需求顺序加锁；确认该项目研究中后，将本项目需求绑定该运行并登记首次在途资格，不新增模型请求。
停止先提交的新订阅者不得登记在途资格；关联先提交后项目停止时，只接收此前已授权结果，不创建任何项目下游。冻结项目继续读取共享版本，不重新激活需求。
共享完成事务保存版本、满足需求并写协调消息；消费消息时再次检查项目状态，不能仅凭消息创建时项目活跃派生。
需要共享协调的事务统一按共享工作固定键、项目ID、需求、任务、预算顺序加锁；任何持有项目锁的路径都不得再获取共享工作锁。
源码完成及其他项目事务只登记共享需求意图outbox；消费者取得共享工作锁后重新核验项目状态。停止清理也按相同方向分批处理，状态权威始终是项目行而非异步订阅标记。
源码请求仍以当前链和地址形成查询事实；同哈希只复用非空内容，空结果不会满足其他地址的源码需求。
同哈希源码协调只合并在途查询并在结束后重查非空缓存；空结果后其他地址仍可按各自合法轮次查询，不产生定时补采。

## 12. 只读方案校验与事实发布

LLM输入源码作为待分析数据，输出只允许严格声明式结构，不携带可执行脚本、工具调用或任意网络访问。
Go校验函数完整签名、参数类型与确定取值来源、返回ABI类型、提取路径和真实源码位置，再构造当前链当前合约的只读调用。
不猜测缺失参数，不发送交易或签名，不以存储读取、固定getter探测、代理实现递归或模拟交易作为兜底。
税率换算使用受限算术表达式和明确分母；动态分母与相关读取共享观察区块，除零或解码错误保留原值及失败原因。
方案版本与实际调用输入、原始返回、观察区块共同写入事实；共享新版方案不改写旧项目快照依据。
结构校验不等于证明AI语义正确；未知、不可判断和技术失败分别保存，质检五事实及两项标识不得由失败填成全否。
响应体、gas、单次解析内存和任务批量设置技术上限；超限形成可见技术失败，不静默截断税费地址、样本或资金图分支。

## 13. 存储、配置与运行检查

活跃任务表对资料种类、调度类、`available_at`及任务ID建立 ready/retry_wait 部分索引，对运行租约建立过期索引。
依赖表索引父产物和未满足子任务；共享需求索引活跃订阅；事实头使用项目、类型、主体唯一索引，避免列表查询遍历事实JSON。
大体积 attempt、observation和outbox按时间分区，并保留独立唯一身份索引记录；跨分区幂等键不依赖缺少分区键的唯一约束。
终态任务移入归档后保留任务身份、次数账本、事实和审计引用；活跃队列清理不删除证据，也不使旧消息重新创建同一工作。
已消费outbox仅在消费者水位与回放安全窗都通过后清理；未投递通知、未解决结果不明请求和共享有效版本不得清除。
分区创建、归档和清理采用小批量后台任务，避开扫描写入关键路径；出现死锁或序列化冲突重试短事务，不重发外呼。
配置显式区分业务10分钟冷却、已确认重试上限与技术lease、轮询、权重、并发、timeout、响应限制、预算窗口及恢复宽限。
通过 NOTIFY 唤醒加250毫秒数据库兜底轮询发现可执行任务；通知丢失、重启和多副本竞争不能丢任务。
上线校准必须同时观测外部请求量、各账户窗口剩余、真实并发、队列年龄、各层服务份额、SLO分布及DB锁等待。
容量验收覆盖三天补扫与新项目持续到达同时发生，验证研究积压不拖慢实时15秒路径，不以空载演示代替容量结论。

## 14. 验收与故障演练

- 六类旧屏障移除后，单个资料或钱包类型失败，其他真实结果立即可查询；没有整项目画像完成前提。
- 重复事件、重复消息、并发领取只形成一个当前轮次和一个后继；冷却从实际派发起，重试不重置冷却。
- 多副本共用账户及key时不倍增预算；429、日额度、凭据失效分别呈现正确阻塞或终态，SDK不暗中追加请求。
- 在派发登记前后、外呼完成前后及事实提交前后注入崩溃，验证次数保守、旧代次隔离、槽位幂等回收和事实无重复覆盖。
- 项目停止与首次派发、重试派发、共享订阅新增及下游提交并发时，按事务顺序保留在途资格且禁止新的项目派生。
- 海量共享关联与清理积压下，停止事务仍只更新项目行并登记outbox；清理前的陈旧需求不能启动请求，手动停止P95两秒目标不依赖遍历共享工作。
- 最后共享订阅停止取消未开始工作，其他订阅及管理员明确报告重检仍可推进；冻结项目展示最新有效版本但不重开研究。
- 在途共享运行加入新项目与该项目停止竞争时，正确登记或拒绝本项目需求；其他活跃项目及管理员后续重检不延迟停止项目专属事实冻结。
- 普通和内部样本独立成功、空或失败；部分资产估值不混用旧区块；历史L1失去当前角色仍完成原有义务，零地址不建节点。
- 多个大项目、持续新L1及深层宽分支同时存在时，验证项目和L2–L5均持续获得服务，不截断来源以通过测试。
- AI迟到、无效结构、重检失败和读取方案错误不覆盖有效版本或产生否定事实；120秒两次策略按真实输入负载验证5分钟目标。
- NOTIFY丢失、队列归档、分区切换及outbox重投后仍能恢复相同逻辑任务，业务事实、尝试账本和通知不丢失。
