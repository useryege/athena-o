# Token 研究事实查询与管理

> 设计状态：设计中（分节方案已确认，书面规格待审阅；尚未实现）
>
> 设计日期：2026-09-10。本文定义后端查询与命令边界，不设计前端页面；总入口见[第一板块主 spec](../../superpowers/specs/2026-09-10-token-first-block-design.md)。

## 职责和依赖

统一 API 从 PostgreSQL 读取项目、独立事实、来源证据、钱包图、覆盖及任务进度，并接受管理员明确授权的管理命令。查询不调用节点、Etherscan、Ave 或 AI，不因用户翻页或展开节点触发采集。当前阶段只输出事实，不产生推荐、评分、买入判断或交易执行状态。

API 依赖[发现与生命周期](discovery-research-lifecycle.md)、[研究任务运行时](research-task-runtime.md)、[源码事实与读取方案](source-facts-and-read-plans.md)及[钱包证据与估值](wallet-evidence-and-valuation.md)的持久契约。一个共享 API 可以读取多链项目，每条响应必须保留链身份；首版只有 ETH 数据。

## 事实读取模型

`project` 是研究生命周期的权威记录；`project_fact_head` 只是按项目、事实种类、对象组织的投影。不可变 `fact_observation` 保存原始输入/输出及依据，不能以“当前值更新”覆盖历史。共享源码/AI 通过 `code_hash` 的最新有效引用读取，不复制成项目永不更新的报告。

| 读取对象 | 必须返回的信息 |
| --- | --- |
| 项目摘要 | 项目/链/地址、部署身份、Token 识别观察块、研究状态、当前期限、最新合法活动、停止原因、停止时间、在途收尾与冻结状态 |
| 分项事实 | 事实种类和对象、最新成功 observation、最新尝试、等待/失败原因、实际观察块或提供方查询时间、版本和证据链接 |
| 源码及五项产物 | 确切输入源码、取得来源、复用依据、各最新有效版本、各最近尝试状态；失败重检与旧有效内容同时可见 |
| 覆盖状态 | 发现游标、各目标与协议版本的连续采集覆盖、未解析映射、活动应用游标、owner 屏障、已知最新高度和更新时点 |
| Swap 事实 | 导致停止的已验证证据、同覆盖版本已知最早证据、此前覆盖是否完整；未完成时不宣称已证明首笔 |
| 钱包及图 | 当前角色、历史角色和 L1 入口、最短层级、终止标签、采样窗口、资金证据/归因、行为、六项资产及实际缺失 |
| 任务/进度 | 依赖/配额/冷却等待、首次执行、实际次数、下次资格时间、各阶段已完成与积压、最后推进时间及错误 |

每个事实响应使用统一外壳：`subject`、`latest_success`、`latest_attempt`、`availability`、`evidence_refs`、`revision`。`latest_success` 与 `latest_attempt` 可以引用不同观察；最新成功为空也必须区分“成功无记录”与“从未取得”。业务未知结果（未收录、无可用读取方式等）保留其专属原因，不笼统写为失败。

`availability` 表达尚未请求、等待依赖、等待额度/冷却、执行中、成功、部分成功、业务空结果、技术失败待重试、失败耗尽、停止取消；具体任务内部状态仍由运行时负责，API 不把租约抢占等实现细节伪装成业务状态。一个事实可以同时显示旧成功值及新失败，不能用单个枚举抹去前者。

L1 资产是特例：所展示的一次快照只包含该观察块的六项结果，缺项不从其他快照补齐。金额均以十进制字符串承载精确整数或定点值，附 decimals、计价单位、路径与完整性，不用二进制浮点表示链上大整数。普通/内部历史及 Ave Top 100 明确标注有界采样，不称完整持币名单或完整账户历史。

## 查询契约

以下为传输层无关的操作契约，落地时映射仓库的 gRPC/HTTP 接口和生成类型；本次不修改 Proto。

| 操作 | 请求范围 | 响应及约束 |
| --- | --- | --- |
| 项目列表 | chain、地址/代码哈希、部署时间范围、研究状态、稳定分页 | 精简摘要及独立事实状态；不连接巨大证据 JSON，不保留风险或交易对筛选条件 |
| 项目详情 | project ID | 生命周期、事实索引、钱包/覆盖/任务摘要；完整事实和大图分开读取 |
| 候选识别记录 | chain、候选地址或部署高度、游标 | 包括未成为项目的非 Token 结论、代码检查与六项诊断、实际观察点；仅查证，不提供人工重新识别 |
| 分项事实及历史 | project ID、fact kind、subject、可选 observation ID | 当前指针或不可变版本，含原始来源；不得把别的项目观察当当前实例值 |
| 源码/共享产物 | code hash、artifact kind、可选 revision | 最新有效值及尝试，或指定历史版本；允许停止项目查看最新共享内容 |
| 钱包与资金关系 | project ID、地址/层级、游标 | 当前/历史角色、最短层和分页节点/边；实际证据与归因分别可查，不相加计额 |
| 钱包历史/行为/资产 | project ID、wallet、类别、版本/游标 | 两类原始样本及关联证据、该钱包行为、指定六资产快照与缺失项 |
| 覆盖/积压/任务 | project ID 或管理员链级范围、类别/状态、游标 | 分项覆盖、阻塞原因和实际进度；成员只能读取有权查看的 Token 研究事实 |

列表采用 keyset 分页，默认 50 条、最多 200 条属于 API 传输窗口，不改变后台研究范围。游标编码筛选摘要、稳定排序键和查询快照上界，服务端校验；大证据另以 ID 读取。钱包图在发布变更时保存 `graph_revision`，节点、角色和边的投影保留有效 revision 区间。一次翻页固定 revision，从而避免层级变化造成漏项或重复；新查询获得新 revision。无需跨请求持有 PostgreSQL 长事务。

单个详情请求使用只读一致快照，返回项目 revision 和观察时间；共享产物单独列出各自 revision，不承诺所有独立资料属于同一块或同一时刻。静态报告、角色、Ave 以及不同钱包快照本来就有不同时间范围。以这些显式时间表达可比较性，而非制造“完整画像完成时间”。

## 管理命令与权限

Token `READ` 或 `READ_WRITE` 成员均可读取上述事实；这些权限不授予以下管理员命令。使用已有管理员身份与权限检查，并记录 actor、request ID、命令范围、输入版本、结果和时间。基础授权现状见[访问控制](access-control.md)。

| 管理命令 | 校验与生效边界 |
| --- | --- |
| 修改链级观察时长 | 正时长及版本校验；默认 72 小时。新项目初始化及后续有效活动使用当时配置，不批量重写现存期限 |
| 修改 Transfer 刷新映射/组冷却 | 可选组限定为 Token 当前状态、owner、税费接收方、税率、L1 资产、Ave 持币资料；默认 Token 当前状态与 Ave，默认冷却 10 分钟。配置不产生周期任务 |
| 修改六资产估值路径 | 限当前链可信协议、确定池、币种相连、终点 USDT、最多两跳；版本用于后续快照，历史不改写 |
| 修改原生币资金门槛 | 非负精确原生币数量，ETH 默认 0.01；仅新项目取得新快照，已有项目继续原门槛 |
| 维护交易所/跨链地址库 | 链+规范地址唯一，保存类型/名称/依据；更新扩展代次，新增停止后续扩展，移除仅恢复研究中项目未执行部分 |
| 人工停止研究 | 锁项目并持久写停止；已停止时幂等返回原原因。不等待外部调用或同步更新所有任务行 |
| 手动源码补采 | 仅研究中且没有可复用非空源码的项目；合并同对象未开始需求，返回任务/轮次引用 |
| 指定共享质检报告重检 | 固定 code hash、实际源码和新输入配置；返回 revision/任务引用，允许已停止项目所引用的共享报告更新 |
| 确认扫描异常已处理 | 仅管理员运维入口，提交链、异常 ID 和预期游标版本；扫描进程重新核验节点链身份及 H ≥ C 后才能解除暂停，不改游标或重开研究项目 |

常规事实刷新只按已确认的活动映射触发；本设计不新增任意资料手动重跑、重开研究或批量买入命令。其他提供方、可信协议、模型及进程资源配置属于部署运维配置，留版本和审计，不暴露成普通成员功能。

改变刷新冷却时，未派发轮次按最新配置由 `last_dispatched_at` 重新计算下一资格；已经开始的轮次保留自身配置快照，技术重试不重置起点。移除某个刷新映射不撤销此前合法活动已经创建的轮次，只影响后续触发。观察时长与刷新映射在事件应用事务中读取确定版本，事件保存使用的配置依据，保证重放幂等。

命令使用客户端 `request_id` 幂等键，唯一范围为 actor 与操作；重复同输入返回原结果，不同输入复用同键返回冲突。配置写入使用 `expected_revision` 防止覆盖别人的更新。项目停止以首次成功事务为主原因，之后补出的更早 Swap 只作为另项事实。人工停止从 API 收到有效管理员请求到持久停止并阻止首次启动计 P95 ≤ 2 秒；普通读请求时延另行测量，不将它误报为已确认业务 SLO。

## 事务、索引与恢复

配置、审计记录和需要的持久工作标记在一个事务提交。地址库变更立即发布链级 library revision；扩展提交核验该版本，后台按索引更新受影响项目节点，故不要求管理员请求同步遍历全库。读接口同时显示节点解析版本及当前标签，避免后台重算期间误称扩展已全部同步。

查询主索引覆盖 `(chain_id,research_state,deployment_block,project_id)`、`(chain_id,address)`、`code_hash`、各事实 head 唯一键、钱包/边的 project+revision+稳定键，以及任务 project+state+available_at。证据按 ID 单独获取，列表不扫描原始源码、日志和交易体。分项计数可以异步投影，但必须返回统计截止时间；停止状态与命令返回直接读权威项目行。

暂不可用时返回明确服务错误或已保存的最后状态，不同步临时请求外部服务填洞。事务失败不返回成功；响应丢失时重复 request ID 可查询既有结果。配置损坏隔离对应采集能力、记录管理员可见错误，不能将资料值伪置零或自动退回未获确认的行为。

## 进度与容量可见性

五层不等于固定工作量。分别展示已发现节点、已完成/等待的普通与内部样本、待补交易、待解析行为、待扩展节点、L1 快照及各深度最老等待时间。分母尚会增长时，不给出“整个项目完成百分比”。ETAs 仅在工作量和最近稳定吞吐可估时返回估计值、计算依据及时间；上游暂停或规模未知时返回不可估计原因。

每项 SLO 返回起点、目标截止时间、首轮/有效完成时间及超标情况。冷却/依赖等待单独可查；正常运行负载超额不能通过隐藏等待项满足 P95。已停止取消与在途收尾分别计数，不能把取消当成成功采集。

技术任务或提供方错误通知按[运行时](research-task-runtime.md)和[生命周期](discovery-research-lifecycle.md)策略处理；Swap、不活跃超时及人工停止只记录事实，不发送常规管理员通知。

## 现状与目标差距

当前[项目读模型](project-read-model.md)、[API handler](../../../internal/tokenapi/project_detail_service.go)及[公共契约](../../../internal/server/tokenapi/types.proto)以 `x/6`、画像状态、市场/交易对信号组织读取；完整目标需要直接替换这些聚合和过滤能力。移除 `simulation_result`、画像构建等待、交易对风险/报价筛选及宽 Ave 市场字段，不提供历史兼容入口。

现有鉴权、通用分页及 transport 装配可按职责复用；项目事实、钱包图、覆盖、管理命令与相关生成类型需重新设计实现。旧前端已移除，本次不恢复页面，不将 UI 展开事件作为任务调度入口。

## 验收

- 一个分项完成后立即可查，不等待其他五项；旧成功值和新失败同时存在，源码空结果与技术失败可区分。
- 停止后在途结果可以更新到冻结点，共享新报告仍可见；没有 API 能重开项目或启动新的部署读取。
- 成员 READ/READ_WRITE 可以查看事实，不能修改配置或停止；管理员命令幂等、版本冲突、跨链地址隔离均可验证。
- 手动停止与首次执行竞争仅一个顺序成立，API 返回后没有未开始任务获得启动资格，重复停止不改变主原因。
- 相同图 revision 多页读取在后台层级变化时无遗漏/重复；页大小不影响后台 L1–L5 范围。
- 缺价和缺余额仍显示部分完整性，金额不丢精度；未知 Swap 映射和 owner 屏障不能显示为完整覆盖。
- 分项指标包含超时未完成样本、错误率和等待原因；断线恢复展示连续覆盖而非收到的最大高度。
