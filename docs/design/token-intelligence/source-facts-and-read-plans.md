# Token 源码事实与声明式读取方案

> 设计状态：设计中（分节方案已确认，书面规格待审阅；尚未实现）
>
> 设计日期：2026-09-10。范围、时效和跨子系统契约见[第一板块主 spec](../../superpowers/specs/2026-09-10-token-first-block-design.md)。

## 职责与边界

本子系统取得并共享非空源码，分别生成五类静态事实产物，再由受限的 Go 执行器对当前部署进行只读调用。入口是已发现项目的链、地址、运行时 `code_hash` 和研究需求；输出是不可变源码、独立 AI 产物、部署专属读取事实，以及仍在研究项目的新钱包需求。

质检仅回答无限增发、修改余额、限制转出、绕过持有人授权转账、放弃 owner 后仍保留控制权五项事实，并记录代理和外部未知依赖。不生成评级、通过结论或筛选条件，不解析代理实现地址、不追加外部源码、不签名、不发送交易、不执行 AI 程序，也不通过链上调用核实静态质检报告。业务依据见[源码](../../requirements/token/token-contract-source-flow.md)、[质检](../../requirements/token/token-contract-review-flow.md)、[owner](../../requirements/token/token-owner-wallet-flow.md)、[税费接收方](../../requirements/token/token-fee-recipient-wallet-flow.md)、[税率](../../requirements/token/token-tax-rate-flow.md)及[公开资料](../../requirements/token/token-public-links-flow.md)。

## 组件及数据流

| 组件 | 输入与输出 | 依赖 |
| --- | --- | --- |
| Source acquisition | 链、地址、`code_hash`、补采轮次 → 查询尝试、空结果或非空源码引用 | Etherscan、共享提供方预算 |
| Source artifact coordinator | 源码引用、产物种类、请求版本 → 去重后的独立分析任务 | PostgreSQL 任务和项目订阅 |
| AI analyzer | 确切源码、提示词、输出 schema → 有依据的结构化产物或技术错误 | 配置的 LLM 服务 |
| Read-plan validator | 产物中的调用说明 → 校验通过的声明式调用图或错误 | 可见源码、ABI 及版本化规则 |
| Deployment reader | 固定方案版本、当前合约、显式观察块 → 原始调用结果及逐项解释 | RPC、owner 观察屏障 |
| Fact projector | 有效产物/读取结果 → 最新有效引用、部署事实、角色变化 | 项目状态锁、事实及钱包仓储 |

```mermaid
flowchart LR
    demand["项目源码需求"] --> source["按地址查询或复用非空源码"]
    source --> inputs["不可变实际源码"]
    inputs --> review["静态质检"]
    inputs --> owner["owner 方案"]
    inputs --> fee["税费接收方方案"]
    inputs --> tax["税率方案"]
    inputs --> links["源码公开链接"]
    owner --> validate["声明式校验"]
    fee --> validate
    tax --> validate
    validate --> call["当前部署、显式区块 eth_call"]
    call --> facts["逐项事实与角色"]
    facts --> wallets["研究中项目的钱包需求"]
```

五项分析可以并行，互不构成完成条件。质检和链接不等待部署读取。各项首次有效产物从非空源码落库起分别计 P95 ≤ 5 分钟，包含排队；技术失败不计为有效完成。首次源码真实查询结果从正常追平的新项目落库起计 P95 ≤ 1 分钟；缓存命中直接返回来源引用。

## 数据身份和版本

| 逻辑表 | 唯一身份与关键字段 |
| --- | --- |
| `source_query` | `(chain_id,address,round,attempt_ordinal)`；提供方、请求时间、状态、响应摘要、错误、任务引用 |
| `source_document` | 源码内容摘要；原始响应、实际文件路径与文本、内容格式、取得地址、取得时间、提供方及字节码关联证据 |
| `source_code_binding` | `code_hash` → 首个已接受的非空 `source_document_id`；CAS 建立，另留全部来源证据 |
| `source_artifact` | `(code_hash,artifact_kind,revision)`；确切源码引用、输入摘要、提示词/模型/schema 版本、原始输出、校验结果、分析时间 |
| `source_artifact_head` | `(code_hash,artifact_kind)` → 最新有效版本；另记最新尝试及错误，不以失败移动有效指针 |
| `deployment_read` | `(project_id,fact_kind,generation,item_key)`；方案版本、观察块/哈希/时间、调用输入及原始返回、逐项状态 |
| `fact_observation` / `project_fact_head` | 不可变项目事实与各分项最新成功/最新尝试引用，沿用[任务运行时](research-task-runtime.md) |

`artifact_kind` 固定为 `quality_report`、`owner_plan`、`fee_recipient_plan`、`tax_plan`、`public_links`。种类间不共用 revision，不将五项打包成只能同时发布的对象。

`code_hash` 是已确认的复用入口，不等于源码内容摘要。同一源码响应中所有实际文件都进入输入清单，不虚构文件名。重复非空响应按实际内容去重；并发取得不同源码内容时保留各自来源，既有绑定不被后台覆盖，不拼接不同输入的分析结论。新项目始终引用当前绑定的实际源码，读接口同时返回其取得地址和复用依据。这里不增加编译或字节码再验证流程，也不把提供方关联视为系统独立验证源码正确性的结论。

提示词或模型配置更新本身不触发批量重分析。管理员可以指定共享质检报告重检；请求绑定确切输入、配置快照及新 revision。同一哈希同一种类串行生成，其他种类可并行；旧执行结果不得覆盖较新有效 revision。失败重检保留之前有效报告并显示本次错误。

## 源码获取、合并与停止

1. 创建源码需求时先检查非空绑定。命中只建立引用，不调用 Etherscan；空源码和请求失败都不是可跨地址复用的非空绑定。
2. 未命中时按当前链和地址建立独立轮次。每地址至多一个运行轮次及一个合并后继，防止活动风暴重复提交。相同哈希的其他地址仍可查询，不能被本地址成功空结果抑制。
3. 成功非空时在同一事务保存源码、CAS 绑定、完成本轮和登记缺失五项共享需求的 outbox 意图。协调者按运行时锁序幂等创建共享工作及订阅，避免持有项目锁再反向获取共享工作锁。并发败于绑定 CAS 的源码仍保留证据，不额外产生第二套默认分析。
4. 成功空时结束本轮，记录“本次未返回源码”。仅研究中项目的手动补采、期限内 Transfer 或部署者/当前 owner 成功主动顶层交易可以再次触发；Approval 不触发，没有周期轮询。
5. 源码一轮最多 4 次真实请求。错误分类、退避、凭据隔离和通知沿用运行时；耗尽后通知管理员。空结果不进行技术失败重试。已有非空绑定后消解尚未派发的多余补采需求。

源码补采的触发合并独立于 Transfer 资料刷新组的 10 分钟冷却，不擅自给源码新增固定冷却或次数总上限；它仍受统一额度及一个运行/一个后继限制。

项目停止和首次执行按同一项目状态锁裁决。未开始的项目需求取消；已开始逻辑任务保留有限重试并保存结果。共享分析若仍有活跃项目需求或明确管理员重检请求则继续；最后一个活跃需求停止也不取消已经开始的共享分析。结果只向仍研究的项目派生读取/钱包任务。已停止项目始终能看到最新共享有效产物，但不会因此重新读取部署状态。详见[停止与共享订阅](research-task-runtime.md)。

## AI 产物契约与校验

每次调用固定输入清单及 schema，模型不持工具、网络访问或链上写入权限。源码注释中的指令只是数据。输出必须包含分析覆盖范围、结论状态、源码证据和实际限制；缺少必填事实、无效 JSON、证据位置不存在或调用方案不合法均为技术失败，不能缓存成“没有风险”“未发现”或“无可用方法”。

质检五项各保存结论、所需权限、触发条件、影响和源码依据。结论可为存在、不存在于已分析范围、无法确定；无法确定须有实际依赖或可见性原因。代理/外部未知依赖不触发追查，也不据此拒绝项目。结构验证只验证产物可解释及证据引用成立，不声称证明了 AI 的业务语义。

输入必须完整进入配置模型允许的上下文。无法容纳、响应超限或预算不足时记录具体资源错误，不静默截断源码后宣称完成。每产物每轮最多两次模型请求（包括修复无效输出的请求），单次超时初值 120 秒。模型、上下文、输入/输出字节上限和并发作为部署配置保存版本；容量验收覆盖最大实际输入，不能用通用模型宣传窗口证明 5 分钟目标。

## 声明式读取说明

可执行说明由版本化 schema 表达，每项具有以下字段：

| 字段 | 允许语义 |
| --- | --- |
| `item_key`、用途和证据 | 源码内稳定定位；owner、具体税费用途或税率分项 |
| `function_signature`、返回 ABI | 完整签名与类型，不只给方法名；必须与实际可见声明相符 |
| 参数绑定 | 确定常量、当前合约/链上下文、同图先前只读调用取得的确定值；类型必须可校验，不猜地址或构造参数 |
| 结果路径 | tuple 字段、数组元素或整个地址数组；路径必须可解码 |
| 调用依赖 | 无环只读调用图；允许先读数组长度再按索引读取，不能包含任意循环脚本 |
| 税率表达式 | 常量、具名读取结果，以及有类型的加减乘除和单位换算；保留原值、单位、分母及公式 |

Go 从 ABI 计算 selector、编码参数和解码返回。目标限定为当前链当前合约；不调用模型任意指定的外部地址，不允许任意 calldata、直接读取存储、动态脚本或发送交易。源码已有确定方法才能执行；未确定参数或依赖外部不可见逻辑时保存“没有可执行方式”及原因。

读取图在一个显式最新观察块执行。动态数组以有界执行窗口推进，保存长度、已完成索引和缺项，不用响应大小或并发窗口作为地址数量截断上限。每个 RPC 受统一限流、超时、gas 和返回大小限制，失败如实标记；一次调用失败不抹去同轮其他成功项。默认单 RPC 超时 10 秒，具体 gas/返回限制按节点和真实输入校准并版本化。不能完成的集合保持部分结果，不伪称完整空集。

重试采用以下边界：已有成功的同轮读取仍绑定原观察块；需要改变观察块时新建快照代次，不混合区块。owner 读取因活动有序性采用[owner 观察屏障](discovery-research-lifecycle.md)：每次实际观察先登记尚未应用的最新块；失败释放屏障，重试重新选块，失败观察不产生 owner 更新。相关成功结果只有在整项语义可确定时更新当前 owner。项目已经停止时，在途重试仅保存实际读取事实，不再建立屏障、监控目标或新的钱包入口。

## 地址、税率与链接的结果语义

| 结果 | 当前事实及下游处理 |
| --- | --- |
| owner 明确为一个非零地址 | 保存原值；仍研究时在项目事务内切换角色/监控区间、建立历史 L1 入口并派生钱包需求；停止后的在途结果只收尾事实 |
| owner 明确为零地址 | 保存零值和依据，清除当前 owner 角色与旧 owner 监控；部署者监控保留，不为零地址建 L1 |
| owner 多个入口冲突且无法消解 | 保存全部返回和冲突；保留最近成功 owner 与监控，最新尝试标记未更新，不任择其一 |
| 税费接收方多个用途/入口 | 按用途、入口保留来源；地址去重而用途不丢失。同一数组部分成功时，已证实的非零新地址立即登记当前来源角色及 L1，研究中即可派生钱包需求；只有该集合完整成功才允许关闭旧地址角色，未知缺项不等于删除旧值 |
| 税费地址为零 | 原值仍可查，不成为钱包或活动目标；完整成功的零结果可以结束该项旧地址的当前角色 |
| 读取失败/不可解码 | 保留最近成功事实，另存本轮错误，不写成无 owner、无税费或零税率 |
| 税率部分成功或分母为零 | 保留各项原值，无法换算项注明原因；不输出伪造百分比，其他项可查 |

税费钱包只有与 deployer/owner 角色重叠时才具相应主动活动资格，税费身份自身不新增监控类型。旧 owner 或税费钱包失去最后一个当前角色后，保留历史 L1 入口和证据，继续未完成历史及上游研究，受 L5、地址库及项目停止限制。

固定税费地址只能来自实际源码中不可变的确定值；可变变量的初值不能代替当前值。固定地址证据的观察块可为空，来源为实际源码；动态地址一定绑定链上观察块。税率各分项及动态分母同块，配置值不等于任何交易必然实付的税费。

公开链接首版仅提取源码实际出现的 HTTPS URL；原始源码中的其他文本仍保留，不升级协议、不拼接账号或猜网址。按完整 URL 去重，保留多处证据；同类多条不截断。分类冲突保留“其他/归属不明”及依据，不选为官方。输出保存类别、用途、源码文件位置及提取时间，固定注明“来源：合约源码”；不访问网页、不证明归属、可达性或审计有效性。

## 持久化和故障恢复

外部请求在事务外执行，发布前核验任务 claim generation、业务代次及输入版本。不可变原始结果和解释结果同次提交，当前指针仅单调前进；数据库提交失败依赖原任务恢复，不把未提交产物当缓存命中。失租后的结果不能直接移动 head。

共享任务提交需要锁共享版本行；向项目派生需求时以固定顺序锁项目并检查研究状态。项目停止后只允许有在途资格的项目读取结果收尾；源自共享新版本的后续调用没有这种资格。所有项目专属在途任务终结后记录 `facts_frozen_at`；该字段不冻结共享产物 head。

原始源码、产物、读取依据长期保留，可压缩存入 PostgreSQL；业务摘要和查询指针用类型化列及索引，不能每次列表查询解码大 JSON。并发限制、提示词、schema、模型和解析规则都留配置版本，后续配置变化不改写旧证据。

## 现状与目标差距

当前[六源 processors](../../../internal/token/collection/application/processors.go)、[结果提交](../../../internal/token/adapters/postgres/collection_result_store.go)及[资料模型](../../../internal/token/collection/model.go)以一次性源码采集进入画像，没有上述五类 AI 产物、声明式读取图、独立版本或项目停止边界。当前源码复用需由“曾查询过”改为“存在可复用非空源码”，不得让某地址空结果阻断同哈希其他地址查询。

目标直接替换旧六源/画像依赖，不新增兼容 API 或旧报告格式。现有 Etherscan 适配器可复用 HTTP 基础，重试、额度和缓存判断迁入统一任务边界。当前系统通知复用其投递机制，源码失败通知由可靠 outbox 交入。

## 验收与运行指标

- 两地址同哈希并发查询，空结果不互相抑制，非空源码和五类任务不重复默认发布；内容不同的来源可追溯且不覆盖绑定。
- 五项 AI 独立成功/失败，失败重检不覆盖旧有效报告，提示词更新不自动触发分析；不能把无效输出包装成业务空结论。
- 调用参数不明、数组部分失败、多个 owner 冲突、明确零 owner、税率零分母均按表中语义持久化。
- owner 新观察不会追溯改变已经应用的活动；失败屏障能释放，Swap/人工停止可先完成，在途结果不派生新任务。
- 停止项目与活跃项目共享源码时，分析继续服务活跃需求；停止项目共享显示更新而动态事实不重新采集。
- 每种产物分别统计源码就绪到有效完成延迟、排队/服务时间、逾期未完成数、校验失败率及请求次数；基础源码首轮另统计空响应、成功率和失败率。未真实调用或未完成的任务不能从时效分母中消失。

请求配额依据和容量测量方法见[任务运行时](research-task-runtime.md)和[主 spec](../../superpowers/specs/2026-09-10-token-first-block-design.md)。本设计没有实际测得提供方延迟或模型吞吐。
