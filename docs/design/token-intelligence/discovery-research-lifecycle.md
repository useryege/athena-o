# Token 发现、连续监控与研究生命周期

> 设计状态：设计中（分节方案已确认，书面规格待审阅；尚未实现）。
>

## 范围与文档边界

本设计负责单链部署发现、Token 识别、项目登记、研究期活动、七协议 Swap、观察期限、停止及扫描通知。
首版只运行 Ethereum Mainnet（`chain_id=1`）；同类程序使用同一构建产物按唯一链配置启动，后续扩链不复制业务代码。
采用按职责拆分进程、PostgreSQL 保存任务和事实的方案；数据库是跨进程可靠交接点，内存、订阅及唤醒消息均不是完成依据。
第二板块筛选和交易、内部 `CREATE/CREATE2` 发现、链重组回滚不属于范围。

## 当前实现与目标差距

现有 [扫描器](../../../internal/token/discovery/application/chain_processor.go) 一次查询 H 后逐块获取、识别、提交；“100”目前限制候选批次，并非区块预取。
[现有事务](../../../internal/token/adapters/postgres/chain_processing_store.go) 已把候选、项目、六类一次性任务及游标原子提交，可复用逐块提交原则，但不保留“恰好六任务”约束。
[现有识别适配器](../../../internal/token/adapters/evm/candidate_inspector.go) 同步读取部署回执并检查最多 10 个接收钱包；目标把回执及最多 5 个接收钱包改为后台任务。
[ATHENA](../../../pkg/abi/ATHENA/ATHENA.sol) 已有地址数组判断，单元素数组也能取得单地址结果；目标补齐合约内代码检查、六项诊断与显式观察点，不将单地址能力误报为完全缺失。
当前 Token 模块没有本文的连续覆盖、owner 屏障和项目停止状态；多链公共启动还会同步全部链配置。目标直接替换相关边界，不设计历史兼容路径。

## 组件与运行隔离

| 进程职责 | 所有权与交接 |
| --- | --- |
| 单链发现扫描 | 唯一链的有界预取、串行识别与 `chain_processing_checkpoint`；提交项目及初始任务 |
| 单链事件监控 | 头部接收、日志/交易补查、协议映射、覆盖推进、项目活动应用与停止；独立于发现积压 |
| 单链研究执行 | 只领取本链资料任务；owner 实际读取通过本设计的观察票据协调 |
| 共享 AI、投影及查询 | 不要求无关链节点配置，不修改链启用状态；按对应文档处理静态产物和查询 |
| 通知转交 | 从 `notification_outbox` 逐条交入现有系统通知组件，不直接操作 Telegram |

同链同职责用 PostgreSQL 专用连接的 advisory lock 选举活动领导者，并在 `chain_runtime` 中递增运行代次；连接失效立即取消工作并重新竞争。
扫描/监控事务首先共享锁定运行行并核验代次，再锁业务行；新领导者更新代次与旧事务互斥，失去领导权的旧工作不能跨新代次提交。
锁采用预先分配的职责编号和 `chain_id`，不依赖不稳定字符串哈希；新领导者从数据库恢复。资料 worker 可多实例，通过任务租约并发。
链配置仅校验当前职责需要的当前链节点、聚合合约和协议清单；全局链支持状态与实例负责链分开，不写回其他链的 `enabled`。
各进程独立健康端口，指标保留链、职责和实例；数据库通知仅缩短轮询等待，丢失后由 500 毫秒轮询恢复。

## 身份、表与跨文档数据契约

链地址统一为 `(chain_id, address)`，地址保存 20 字节，哈希保存 32 字节；高度/序号使用非负整数，链上时间与系统时间使用不同字段。
项目身份唯一为 `(chain_id, token_address)`；部署区块、交易哈希、交易序号、发送者及 nonce 是不可变发现证据。

| 表 | 主身份、关键状态与约束 |
| --- | --- |
| `chain_runtime` | `(chain_id,role)` 唯一；实例、运行代次、健康心跳与已观测链头，领导切换递增代次而不覆盖其他职责 |
| `chain_processing_checkpoint` | 每链一行，最高完整提交高度 C、运行状态；只允许相邻高度推进 |
| `project_candidate` | 每链候选地址唯一；原始 Token 结论、六项诊断、代码长度/哈希、观察块号/哈希/时间不可被刷新覆盖 |
| `project` | `research_state`、`revision`、当前期限及期限策略版本、主停止原因、停止证据、停止提交时间、冻结完成时间；保留资金门槛快照 |
| `research_task` | 共享任务契约；`first_started_at` 不随重试清空，`claim_generation` 阻止旧执行者提交；生命周期不另建任务状态机 |
| `monitor_target` | 链、项目、目标种类、地址/协议版本、有效链上区间、目标 revision；部署者和 owner 可共享地址但保留角色 |
| `monitor_coverage` | 目标/协议版本/分片 revision 与闭区间；区分采集完整、映射解析完整，保存连续前沿与仍有缺口的区间 |
| `project_activity_cursor` | 每项目已应用的链上位置、目标 revision、三类活动各自首次/最近证据及去重累计数 |
| `owner_observation` | 项目、观察块 B、任务及 `claim_generation`、读取方案版本、观察状态、屏障位置、租约；每项目最多一个未结观察 |
| `protocol_deployment` | 链、协议版本、清单版本、官方 Factory/Manager、部署起块、ABI 摘要、官方依据及内容校验和；激活后不可原地改写 |
| `pool_mapping` | 链、清单版本、Pair/Pool 或 `(Manager,poolId)`，币种与完整 PoolKey/fee、验证证据、解析状态 |
| `chain_event` | 链、交易哈希、种类和位置唯一；保存区块哈希/时间、交易序号、日志或成功顶层交易证据及接收时间 |
| `notification_outbox` | 每次真实失败唯一 `failure_id`、链/块/阶段/尝试、消息、转交状态、重试时间及通知组件返回 ID |

`chain_event` 的日志以 `logIndex` 去重；顶层交易使用独立种类，不能与同交易的 Transfer 合并。同一项目同一主动交易合并全部命中角色。
目标有效区间使用链上位置的左闭右开形式：部署者从部署交易之后起，新 owner 从 B 的首笔交易起，旧 owner 止于 B 的首笔交易之前；覆盖区间仍用闭区间，并按目标有效区间取交集。
跨项目同一证据可以共享原始记录，各项目独立应用；游标、汇总与派生任务同事务提交，保证重复接收不重复执行业务动作。
按链和区间建立覆盖索引，按链/区块/交易/日志建立事件顺序索引，按研究状态/期限建立超时索引；禁止仅靠最大已收到高度推断完整。

## 按时间定位起点与 100 块流水线

1. 先恢复持久 C；没有游标时固定最新头 H0，以 `timestamp(H0)-72h` 为目标，对区块时间二分查找首个不早于目标的块 B0，并验证相邻边界。
2. 保存初始化 `C=B0-1`；不足三天历史时从该链第一个可处理块开始。最新头和起点查询错误均保留原状态并记录实际失败。
3. 每轮固定 `[C+1,min(C+100,H)]`，初始 8 个并行获取槽位；取到一块立即进入按高度索引的缓冲。
4. 单个处理者仅等待 C+1，立即发现候选、批量识别及提交；后续块可预取但不识别，不等待整批到齐，不越过缺块。
5. 每次成功提交立即释放该块；本轮完成立刻查新 H。仅 `H=C` 等待 1 秒，积压时无额外周期等待。
6. `H<C` 保留 C，写入需人工处理状态及通知；同一未解除异常只通知一次，新的异常另建 ID。管理员通过运维命令登记处理确认，扫描进程重新校验 chain ID 与 H≥C 才解除暂停；失败仍保留异常，不能自动回退、重置游标或把异常当作追平。

预取同时受 100 个高度和 256 MiB 预算约束，单响应初始上限 16 MiB；为最早待处理块预留一个请求槽位和响应预算。
后续块按高度优先派发；达到字节预算暂停新的远端获取，不挤占最早失败块的重试能力。超限产生明确资源错误，不能截断区块后提交。
请求初始超时 5 秒；同一失败操作按 1、2、4、8、16、30 秒退避，随后保持 30 秒并加 0–20% 抖动，无次数上限。
单个预取失败只重试该高度，其他本轮请求可继续；识别/事务失败保留当前块，不能让下一块进入识别或改变 C。
进程停止时全部内存可丢弃；恢复总从数据库 C+1 开始，不把预取或已识别未提交的数据视为完成。

## 批量识别与逐块提交

顶层 `transaction.To()==nil` 才进入候选，按发送者和 nonce 推导地址；不以部署回执 status 作前置判断，也不发现内部创建。
每块按交易顺序汇总全部候选，初始每批最多 64 个。空候选跳过聚合调用；单候选仍走批量路径，跨块、跨链不得混批。
目标 ABI 提供 `InspectToken(address)` 和 `InspectTokens(address[])`，两者调用同一个内部探测函数；这是直接替换目标返回契约，不要求保留旧 ABI。
每次批量先读取最新头 O，再用显式块号调用；适配器从头部附上 O 的块号、哈希和时间，合约结果与输入逐项对应。拆批分别记录实际观察点，不尝试在合约内取得当前块哈希。
合约首先取得 `code.length` 和运行时代码哈希；无代码时判为非 Token，六项标记未执行。有代码时执行全部六项，即使前项失败也继续。
六项诊断分别区分 `passed`、`call_failed`、`decode_failed`、`invalid_value`、`not_executed`，保留实际值、返回数据长度及错误证据。
名称/符号非空、decimals 与 totalSupply 大于零，balanceOf/allowance 可解码且允许零；探测条件沿用既定规则，不附加风险筛选。
保留现有字符串 50,000 gas、数值 30,000 gas 和字符串返回最多 4,096 字节边界；用有界 returndata 复制避免恶意返回耗尽聚合调用。
错误数据最多保留前 4,096 字节并显式标注原长度和截断；数值解码允许尾随数据，不能因为新增诊断而改变原识别规则。
批量外层 gas 初值 30,000,000；确定的批量资源超限记录失败后按二分缩小批次，最小一项仍失败则重试，不伪造逐项否定结论。
业务拒绝保存后最终有效，不自动或人工重新识别；外层请求、返回数量/顺序、观察块核对及保存失败属于技术异常，不产生第三种 Token 结论。

逐块事务先锁本链 checkpoint，确认当前 C 等于目标块前一高度，再保存所有候选记录、接受项目及初始 `research_task`。
项目同步保存部署身份、观察点、代码哈希、期限与资金门槛快照，并登记 Token/部署者/Swap 监控目标；部署者 L1 入口可同步建立。
初始任务覆盖部署回执/接收钱包、Token 当前状态、源码和 Ave，以及已知 L1 的研究入口；具体任务种类与依赖由任务运行时定义，不创建 `simulation_result`。
回执及最多 5 个初始接收钱包的净接收量排序、无代码筛选完全后台执行；任何该任务失败不回退发现游标，不保留两条派生池地址非空的项目创建门槛。
最后 CAS 推进 C 并提交；空块也执行推进。提交响应丢失先重读 C，已成功块不重写原始识别；记录这次真实请求错误并对照持久结果恢复。

## 实时接收与连续覆盖

监控进程以 `newHeads` 加 1 秒头部查询驱动，Token 日志/可信池日志用共享地址分片订阅，每片初值 256 地址，不为项目单独建立订阅。
订阅连接与批量 RPC 连接分开；单个请求错误不关闭全部订阅。每条完整头部触发必要区间补查，实时收到的日志先写 `chain_event` 以降低延迟。
顶层主动交易读取完整区块，筛出当时有效监控地址的 `from`，再取得匹配交易回执确认成功；零 ETH 调用有效，不使用资金来源金额门槛。
新增目标先建立实时接收，再固定补查终点 H；Token 与 Swap 从部署块起，部署者从部署交易之后起，owner 从成功观察块起。
目标分片换代先启动新分片，再补齐切换重叠区间，最后退出旧分片；旧 revision 的结果只补所属区间，不能推进新 revision 的覆盖。
历史日志初始每段 200 块、最多 8 并发；遇到响应/数量限制分裂区间直到完整，不把提供方截断当作成功。单块超限改取完整回执日志重建同一查询范围。
一个区间的原始匹配事实、查询边界/过滤摘要及覆盖结果在同一事务保存；空结果也形成覆盖，失败保留缺口。无法证明完整的端点隔离，换端点补查。
已持久区间可乱序到达，但连续前沿只能合并相邻成功区间；映射未解析另外阻塞“已解析完整”，采集成功不等于可以确认超时。
项目登记前事件由登记后补查补齐；订阅丢消息、断线、进程重启一律从持久缺口恢复，不依赖内存接收长度。

| Sushi V3 | `0xbACEB8eC6b9355Dfc0269C18bac9d6E2Bdc29C4F` |

| PancakeSwap V3 | `0x0BFbCF9fa4f9C56B0F40a671Ad40E0805A091865` |

共享映射索引从各官方部署起块接收/补查 Factory 创建事件及 V4 Initialize，与发现扫描并行。项目登记时可按 indexed 币种定向补齐 V2/V3 创建历史，无需等待全链映射索引全部追平。
映射发现范围不从 Token 部署块截断：预先计算的地址允许池创建或 V4 Initialize 早于 Token 部署；项目 Swap 查询仍从 Token 部署块开始。
V2 以官方 PairCreated 或 `getPair(token0,token1)==emitter` 证明归属；V3 以 PoolCreated 或官方 `getPool(token0,token1,fee)==emitter` 证明归属。
池自己返回 `factory()` 不足以证明可信；PancakeSwap V3 不误用 Uniswap V3 的事件 ABI，也不假定 CREATE2 的实际部署者就是 Factory。
V4 必须由可信 Manager 发出，保存完整 PoolKey 并校验 poolId；native ETH 的零地址依协议解释。收到未知 poolId 的 Swap，按该 Manager 部署起块至事件块定向查询 Initialize。
V4 找不到映射或请求失败时保留 `unresolved` 并补查，绝不标为与项目无关。币种未知可能影响所有该版本研究项目，因此对应 Swap 解析覆盖不得越过该缺口。
新建可信池先建接收范围，再从池创建块与项目部署块中较晚者补查；Factory 创建日志、池映射和本块 Swap 均完整后才能推进本块 Swap 覆盖。
同 topic 不代表同协议，实际解析组合校验可信发出方、ABI 布局和币种；flash swap 有效，Router、方向、金额和报价币种不构成筛选条件。
项目记录其当前协议清单版本；新增协议只给仍研究项目创建新版目标并从部署块回补，未完成时不宣称新版覆盖完整。已停止项目保留停止版本，仅补齐该版本原有缺口。

## 活动的有序应用

活动按 `(block_number, transaction_index, kind_order, log_index)` 应用，顶层交易先于该交易日志；同块时间相同，角色命中先合并，日志保持 logIndex 顺序。
每项目应用前沿只能推进到 Token 两类日志、部署者及有效 owner 交易覆盖的共同连续前沿；Swap 未解析不阻塞一般续期，但必然阻塞超时确认。
处理者锁 `project`，核对 revision、目标版本、owner 屏障及持久游标，再按链序读取下一小批事件；每事务最多 128 个事件或一个区块，先到者结束。
同事务保存各类活动的首次/最近/数量、适用策略版本和新期限，并合并对应源码/刷新触发；全批成功才推进活动游标。
晚到但链上更早的活动不能在已有缺口时被越过；未来区块事件先入库等待，不能先判迟到再事后补偿已经执行的副作用。
事件时间不晚于处理前期限才有效，期限严格赋值为“事件时间＋处理时当前链观察时长”；配置缩短可以使期限缩短，禁止用 `max` 改写公式。
每次应用事务读取当前策略版本并保存引用；配置更新不回放历史、不重写现存期限。重试事务重新读取当前配置，已提交事件不再执行。
Approval 只续期；Transfer 续期、缺源码补查并按配置刷新；主动交易续期和缺源码补查，无其他刷新。迟到事件仅保留证据，不触发任务。
刷新轮次、默认 10 分钟冷却及合并后继沿用任务运行时；活动逐条续期不受冷却影响，初始默认刷新组为 Token 当前状态与 Ave 持币资料。

## owner 观察屏障

源码与 AI 方案准备不持屏障。worker 确认实际调用配额可用后，在项目锁内核对仍允许该任务执行，向监控协调器申请尚未应用的最新区块 B；B 必须严格大于已应用活动所在块，不能在部分应用的块中途设立观察。
若最新块已应用，登记等待下一头部的意向，不登记首次派发；下一头到达且执行配额就绪时，协调器在允许应用该块之前原子设立 B 屏障并登记派发，否则意向等待后续最新块。
票据保存 B 的哈希/时间、读取方案版本、任务 ID、`claim_generation` 和租约；同项目最多一个未结观察，不在数据库事务内做网络读取。
Go 固定 B 执行只读调用。每次调用失败即以 generation 条件关闭本次屏障，旧 owner 区间保持；下次有限重试重新申请最新观察块，不跨重试等待长持屏障。
成功时锁项目并核对票据；项目仍研究中时，原子保存 owner 事实、关闭旧 owner 在 B 起的角色区间、从 B 建立新 owner 目标与缺口；同地址保持区间并追加观察依据。
成功零地址保留读取原值但不建立钱包或活动目标；旧地址若也是部署者，部署者区间始终有效。历史 L1 及其研究范围按钱包文档保留。
成功后仍保留 B 屏障，固定当时补查终点 H，完整补齐新有效区间 `[B,H]`，发布覆盖后才放开；H 后接入常规连续补查。
票据租约过期时拒绝迟到旧 generation 结果；尚未成功读取的票据释放屏障并恢复任务，已经安装 owner 的票据保留正确目标，由监控恢复缺口后放开。
超时检查不能越过可能影响当前期限的未结观察和成功后缺口；Swap 与管理员停止可直接越过屏障停止，随后票据只允许在途事实收尾，不新增项目任务或恢复研究。
已经停止的项目若有合法在途 owner 重试，固定本次最新观察块只读取并保存最终事实，不再申请观察屏障或增删活动目标；停止前已安装目标的覆盖缺口按冻结范围收尾。

## Swap 快速停止、超时和人工停止

已验证 Swap 单独进入快速事务，不等待活动应用游标或 owner 屏障；保存触发证据后锁项目，以 `research_state=researching` 条件写停止原因并增加 revision。
首次成功写入的主停止原因永久保留；随后人工请求、超时检查或更早 Swap 只追加事实，不能覆盖主原因。普通停止不生成管理员通知。
分开保存触发停止的事件、当前已知最早 Swap、系统识别时间及最早性是否已证明；更早范围未完整时展示待补齐，不声称全市场首笔。
停止时固定当前覆盖版本与收尾 H，取已持久链头、已登记补查终点及触发 Swap 高度的最大值，不在停止事务内请求节点；该版本从部署块到 H 的 Swap/映射缺口继续补齐，不新增未来研究范围。
超时处理每秒检查到期候选，逐个短事务锁项目，重新读取期限/revision、owner 票据、活动游标及五类采集和解析覆盖。
必须存在链上时间严格晚于期限的块，所有目标在各自有效区间内完整覆盖到该块，且期限内无未应用有效活动或 Swap；旧 owner 已关闭区间不要求继续覆盖，证明随停止记录持久保存。
若读取到更新期限或新目标 revision，当前判断作废并重算；服务器时钟仅驱动调度，不决定业务超时。
人工停止经管理员授权后直接锁项目写状态/操作者/原因/服务器受理时间及当前链头参考，不等待网络补查或海量任务更新；权限与响应见查询文档。

## 首次执行、停止与在途收尾事务

项目专属任务按 `project → research_task → 目标/事实` 顺序取锁；共享任务按运行时规定的共享工作、项目、需求、任务、预算方向取锁，项目持锁后不能再反向锁共享工作。扫描/监控先完成运行代次锁定，事务内不调用远端服务；共享预算使用数据库短事务预留。
领取及等待配额不设置 `first_started_at`；配额可用后，worker 锁项目和任务，核验 generation 和研究状态，按任务运行时原子取得执行预算并登记首次执行与派发，再发实际请求。
停止与这次登记互斥：停止先提交，尚无 `first_started_at` 的任务永远不能开始；派发登记先提交，该任务取得原有限重试的收尾资格。
停止事务只更新项目状态/revision，不同步更新全部任务行；领取/派发条件和查询投影立即把未开始任务视为取消，清理器每批 500 行补写取消状态。
`retry_wait` 且 `first_started_at` 非空属于在途，不能被清理器取消；其配额等待和有限重试继续，重试不建立新的任务或刷新轮次。
结果提交核验 `claim_generation`，在途最终事实可保存；任何下游创建、L1 扩展、owner 目标新增都在项目锁内再次检查研究状态。
项目不存在未终结的已开始任务后标记冻结完成；静态共享产物可继续展示最新有效版本，已停止项目不因此启动自己的新采集。

## 每次扫描失败的通知转交

每次真实获取、识别或保存失败生成新的 `failure_id`；失败记录与 outbox 同事务保存，各次失败分别保留，不合并、去重或抑制真实尝试。
通知暂不可用时继续区块重试，outbox 按每条记录退避转交；同一次传输重试沿用 failure_id，不新增一条“扫描失败”。
系统通知请求增加生产者事件身份，接收端以 `(source,failure_id)` 唯一保存并返回原 delivery ID，解决已入队但响应丢失的重试重复。
当前 [系统通知接口](../../../internal/notification/notification.proto) 尚无此幂等字段；实现需同步其协议、存储与消费者，不由 Token 直接写通知数据库。
收到可靠入队 ID 后标记已转交；扫描责任到此完成，Telegram 的有限重试及最终失败沿用 [现有通知机制](../notifications/system-notification-operations.md)。
若 Token 数据库本身不可写，把错误追加到实例持久卷的 fsync 队列，恢复后按 failure_id 导入；初值上限 256 MiB，未成功导入不得删除。
持久卷不可写或队列满时停止派发新的扫描请求、保留游标并标记不健康，不能继续制造无法可靠记录的失败；恢复持久记录能力后继续原区块。

## 背压、恢复与数据保留

发现、实时监控、监控补查、研究采集分别使用 RPC 并发配额，初值为 8/8/8/8；识别串行调用占发现配额，监控有独立保留额度，不被三天发现补扫占满。
每进程数据库池初值 16 连接，项目应用并发 16；停止事务保留连接容量，锁等待超过 250 毫秒退让重试，不长期占锁拖住人工停止。
节点需支持显式块号调用、历史日志/区块/匹配回执和可靠响应完整性；启动记录端点能力及限额，换端点后先核对 chain ID，不把错链结果写入本链。
数据库提交失败不推进任何游标；租约/generation 使旧 worker 无法覆盖新结果。订阅溢出主动重连并从持久覆盖补查，不能丢弃数据却继续宣称完整。
事件按链分区，分区内保持事件身份唯一并建立时间索引；项目研究中、覆盖仍欠缺、存在未完成票据/在途任务时不删除所需原始证据。停止且收尾完成后保留 30 天，再按日分批清理非引用原始事件。
原始识别、活动首次/最近摘要、计数、停止证明、被引用 Swap/映射和配置版本永久保留；公共事件只在全部引用方允许时清理，保留策略不缩短恢复区间。

## 时效、容量与验收证据

| 路径 | 目标与统计边界 |
| --- | --- |
| 正常发现 | 配置节点首次可服务新区块至新项目及初始任务提交，独立 P95 ≤ 15 秒 |
| 已登记活动 | 同上游时点至合法活动续期提交，独立 P95 ≤ 15 秒；包含排队、补全与应用 |
| 已登记 Swap | 同上游时点至停止提交，独立 P95 ≤ 15 秒；包含可信身份和必要币种解析 |
| 首次三天发现 | 按时间定位起点并开始扫描至 C 追平持续增长链头，≤ 2 小时，不等待后台研究 |
| ≤1 小时断线恢复 | 上游恢复正常至已登记目标缺口完整补齐并追平，≤ 5 分钟 |
| 超时停止 | 全部业务覆盖与解析条件满足至停止提交，独立 P95 ≤ 15 秒 |
| 人工停止 | 管理员请求到达 API 至可靠禁止新首次派发，独立 P95 ≤ 2 秒 |

链头观测器对配置节点每 250 毫秒采样新区块可查询性，保存成功时点和采样误差；生产指标为这一可观测近似，验收用可控 RPC 服务记录精确可服务时点。
各路径使用独立直方图、样本数和失败率，按正常追平/初次补扫/故障恢复分开；不从 worker 开始执行重新计时，不用快失败满足成功链路指标。
三天约 21,600 个 12 秒出块机会，加上两小时新增块约需 3.1 块/秒；这是容量估算，尚无当前实现达到该吞吐的证据。
首轮容量验收重放连续三天真实 ETH 区块和实际候选/日志分布，另以 1,000 个研究项目、5,000 个监控地址作明确压力档，并记录峰值每块事件数与提供方限额。
至少覆盖 24 小时正常追平；可控加速回放另外用于吞吐与故障演练，不能替代真实时间延迟验收。测量原始分布、P95、最大积压、内存峰值和 RPC/数据库耗时，不把压力档当作已经承诺的支持容量。
首次补扫期间持续注入新区块；故障恢复注入 5/30/60 分钟断线。容量失败调整技术并发、批次、资源或节点能力，不跳块、少建任务或提前超时。
