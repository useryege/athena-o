## 目标设计

| 文档 | 内容 | 状态 |
| --- | --- | --- |
| [Token 目标设计](token.md) | 从合约部署开始研究项目，筛选值得关注的项目，交接给交易监控与执行板块，在交易开放且满足条件时及时买入 | 目标设计草案，尚未实现 |

Token 文档记录已明确的业务目标、开发阶段发现范围、未添加流动性时的采集安排，以及待确认建议与待细化规则。研究阶段的链上状态只保留代币基础信息，其中包含需要获取并保存的合约 `code.length`（运行时代码字节数），长度数据的具体用途后续明确；不采集或研究底池；模拟结果暂不作为必采项，本阶段不采集 Ave；合约 owner 获取仍待设计。后续讨论继续在该文档中完善，本轮只整理文档，不进行代码开发。

区块扫描已明确采用主动轮询：有进度则续扫，无进度从最新区块向前回看三天开始；逐块处理，每轮最多 100 块，轮末重新查询最新高度，追平后等待 1 秒再查询。区块处理失败时，每次通过通知组件通知管理员，并不限次数地重试同一区块，成功后才继续下一块。最新高度 `H` 小于已保存扫描位置 `C` 时，通过通知组件通知管理员人工处理。相关执行流程图已记录在 Token 目标设计中，尚未修改代码。

Token 识别由聚合合约内部先检查目标地址是否有代码：无代码直接判定不是 Token，并记录“地址无合约代码”；有代码后执行现有六项检测，全部通过才为 Token。不设置独立的交易成功判断，结论只有是 Token 或不是 Token。识别结论、未通过项和原因需返回并关联具体合约持久保存，供后续人工查询排查。合约内部代码检查及逐项诊断能力待实现。

通过 Token 识别后的项目研究以规则筛选为目的：符合研究筛选规则的项目交接第二板块，不符合的项目被过滤；筛选结论、未通过规则、原因和依据需关联项目持久保存，供后续人工排查。具体研究规则和阈值仍待设计。

第二板块已明确需要扩大 DEX 与协议、报价资产和底池类型的覆盖，现有 WETH/WBNB、USDT 与 V2 协议范围不作为新设计的固定限制；具体接入清单及方式待设计，尚未实现。

已确认不再保留系统自有的合约代码黑名单和钱包黑名单。Token 目标设计已记录后续删除范围，当前代码和数据尚未清理。
