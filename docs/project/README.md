Token 文档记录已明确的业务目标、开发阶段发现范围、未添加流动性时的采集安排，以及待确认建议与待细化规则。现有 `chain_state` 拆分后保留代币基础信息，其中包含需要获取并保存的合约 `code.length`（运行时代码字节数），长度数据的具体用途后续明确；不采集或研究底池；模拟结果暂不作为必采项，本阶段不采集 Ave；由 AI 分析源码判断是否存在可用的 owner 读取方式，Go 程序按该方式读取当前合约的 owner；税费接收钱包则由 AI 提取源码中的固定地址，或提供读取方式交给 Go 读取，支持一个或多个地址，并将取得的 owner 与税费接收地址纳入关联钱包采集；税率同样由 AI 识别可用读函数及数值解释方式，Go 读取当前合约的链上税率配置并保存展示。后续讨论继续在该文档中完善，本轮只整理文档，不进行代码开发。

区块扫描已明确采用主动轮询：有进度则续扫，无进度从最新区块向前回看三天开始；逐块处理，每轮最多 100 块，轮末重新查询最新高度，追平后等待 1 秒再查询。区块处理失败时，每次通过通知组件通知管理员，并不限次数地重试同一区块，成功后才继续下一块。最新高度 `H` 小于已保存扫描位置 `C` 时，通过通知组件通知管理员人工处理。相关图示见下方流程图索引，尚未修改代码。

Token 识别由聚合合约内部先检查目标地址是否有代码：无代码直接判定不是 Token，并记录“地址无合约代码”；有代码后执行现有六项检测，全部通过才为 Token。不设置独立的交易成功判断，结论只有是 Token 或不是 Token。识别结论、未通过项和原因需返回并关联具体合约持久保存，供后续人工查询排查。合约内部代码检查及逐项诊断能力待实现。

通过 Token 识别后的项目研究以规则筛选为目的：源码质检报告评为高风险的项目直接排除，不再研究；明确非高风险的项目继续其他研究，符合其余筛选规则后才交接第二板块。筛选结论、风险等级、报告引用、未通过规则和依据需关联项目持久保存，供后续人工排查。风险评级细则及其他研究规则仍待设计。

基础信息、字节码、owner、需要链上读取的税费接收地址、税率配置和钱包资产等链上状态按各自采集时最新区块读取，保存实际来源区块与时间。第一层直接关联钱包包括部署者、最多 5 个初始接收钱包、已取得的 owner 和税费接收钱包，均采集部署前普通交易及 WETH/WBNB、USDT 等已追踪代币余额，不采集原生币余额。初始接收钱包上限已确认为 5 个，当前代码仍为 10 个，待实现时调整；这一上限不限制税费接收钱包数量。owner 采用统一的 AI 分析与 Go 读取流程：按 `code_hash` 复用同一源码已完成的分析结论及读取方式，未命中且有源码时由 AI 判断如何读取，不限定函数名。已完成但未识别出可用方式的结论也可复用；AI 或 RPC 技术失败不记为不可读取结论。存在可用方式时，由 Go 程序读取当前合约最新链上状态，每个部署的实际 owner 地址分别读取。没有源码且无可复用结果、未识别可用方式或读取失败时，记录实际结果与可知原因，继续已知钱包和其他资料采集，不因缺少 owner 阻塞研究或单独过滤项目。该流程尚未实现。Etherscan 源码记录查询时间及来源。

[税费接收钱包](token-fee-recipient-wallet-flow.md)支持一个或多个地址，同一合约可同时包含固定地址和需要读取的地址。AI 根据实际源码中的税费流向识别接收方：确实固定的地址直接提取；依赖当前状态的地址则给出可执行读取方式，由 Go 读取当前链、当前合约在本次最新采集区块的状态，再合并全部已取得地址。可变变量的初始字面量不视为当前固定接收地址，不为此新增部署初始化资料采集。AI 分析结论、固定地址及读取方式按 `code_hash` 对应源码复用，动态实际地址逐部署读取；保存来源类型、源码依据、读取结果及实际区块。税费接收地址可以是合约地址，按链与地址去重后纳入 L1，保留全部角色与税费用途依据。没有取得或只取得部分地址时保留真实结果与原因，继续已知钱包资料采集，不新增项目筛选规则；不继续获取或分析代理实现与外部依赖。该设计尚未实现。

[税率读取](token-tax-rate-flow.md)作为独立研究资料，由 AI 根据实际源码语义识别可读取的税率项目，例如买入、卖出、转账税率或分项；不固定函数名，也不要求每份合约都有全部项目。AI 给出可执行调用说明、返回含义、单位、分母及换算公式，Go 在当前链、当前合约的本次最新采集区块读取原始值及需要动态读取的分母，同一税率项目的相关调用使用同一区块。保存源码依据、原值、实际区块与时间，解释明确时展示百分比，不按 Token 精度或假定分母换算，不重复叠加总税率与其分项。同一源码共享 AI 读取与解释方案，实际税率逐合约读取；无方法或读取失败不记为零税率，部分成功结果保留。当前只采集展示税率配置，不声称已核实某笔交易实际扣税，不新增税率阈值过滤、买卖模拟、角色白名单核实、代理或外部依赖分析、直接存储读取，也不将源码固定值当作链上读取结果。该设计尚未实现。

[源码中的项目公开资料](token-public-links-flow.md)由 AI 从实际取得的源码中提取 HTTPS 链接，按官网、X、Telegram、项目文档、GitHub、公开审计报告及其他类型整理。同一份源码和同一类型均可保留多个链接，按完整 URL 去重并保留各处源码依据；展示时明确标注“来源：合约源码”。按 `code_hash` 定位同一源码，复用其已完成的提取结果；缺失且有源码时才提取，不依赖链上读取，也不要求与质检报告或其他 AI 分析同次调用、共同完成。当前只提取、分类、保存展示，不搜索网络、抓取链接页面或核验官网与审计真实性；没有源码且无可复用结果、未发现链接时记录实际结果，继续其他研究，不新增过滤规则。该设计尚未实现。

[当前持币地址资料](token-holder-flow.md)已纳入目标设计，尚未实现。系统现有 Etherscan API Key 均为免费 Key，继续用于源码、普通交易等原有查询；后续配置一个专门用于持币地址数据的 PRO Key，通过 `tokenholderlist` 分页获取持有人地址及各地址的目标代币数量，通过 `tokenholdercount` 获取持有人地址总数。专用 PRO Key 不加入普通请求的 Key 轮询，也不在两类 Key 之间回退；未配置时记录未采集，继续其他研究，不使用免费 Key 尝试这些 PRO 接口。取得的地址按链、目标代币与持有人去重，可以匹配已有项目角色，按有依据的总供应量与统一单位计算占比并保留分母时点；普通持有人不自动纳入 L1 或触发钱包历史、资金来源与其他余额采集。资料描述 Etherscan 的当前索引结果，记录查询起止时间、来源、分页范围和未取得原因；不将多页结果当作部署初始分配或固定区块的一致快照，不按 `code_hash` 跨合约复用。权限不足、查询失败或部分成功时保留真实结果，未采集不填为零持有人或完整列表。当前只展示持仓分布，不增加集中度过滤，也不要求源码、AI 或 owner 完成后才能采集；专用 Key 的具体配置、调度、存储及后续更新方式另行设计。

钱包历史交易的查询设计已确认原样保留：L1–L5 每个去重关联钱包通过 Etherscan `account/txlist` 查询区块 `0` 至 `项目部署区块 - 1`，按 `desc` 倒序取第 `1` 页、最多 `300` 笔普通交易，不足则保留实际数量，不继续翻页。部署在第 `30000` 区块的项目，始终查询 `0–29999` 范围内最近的最多 300 笔，不包含部署区块内及之后的交易，不随采集时最新区块改变截止范围。上述单钱包查询规则当前已实现；多层发现和分析仍待实现。具体规则见 [Token 研究证据说明](token.md#研究证据与完成条件)。

已确认 [多层关联钱包研究](token-wallet-research-flow.md)：从 L1 交易样本中成功、直接转入原生币且金额大于零的交易提取来源地址，形成 L2，再按相同规则逐层追溯至 L5。L5 对应四轮上游扩展，仍分析其历史，不向 L6 扩展。各层均分析成功直接部署过的合约及交互过的代币，补充同一批交易的回执与日志，并匹配已有项目及报告。保留来源、接收钱包、金额、交易哈希、区块和时间；按链与地址去重，来源已分析时复用结果并保留全部资金关系与角色，跨项目复用须匹配截止区块和采样规则。首版资金来源不含代币入账或内部转账；余额采集仅限 L1。多层分析、数据补充及复用尚未实现。

关联钱包当前阶段明确为“采集数据 → 解析事实 → 保存展示”。同一地址可以同时具有部署者、owner、初始接收钱包、税费接收钱包等多个项目角色标签；历史部署与交互项目、资金来源关系、余额及交易证据照常解析和展示。此阶段不根据钱包身份、多层资金来源、历史项目、余额或未取得结果产生风险评分、通过／不通过结论或项目排除；钱包筛选逻辑不纳入当前设计。独立的源码 AI 高风险过滤及前置 Token 识别继续按各自规则执行。

钱包历史中[交易项目的识别](token-wallet-research-flow.md#交易项目识别的协议覆盖)不限定为 PancakeSwap V2 或 Uniswap V2，目标覆盖不同 DEX、版本、聚合器及路由。先从既定交易样本保留有证据的钱包代币关系，再结合协议语义判断买卖；不按 V2 预筛交易，不把授权、普通转账或被动收款直接视为买卖。具体协议解析仍待实现。

[钱包资金来源关系图](token-wallet-funding-graph.md)按 L1–L5 分层展示资金来源树，底层保留有向图。同一地址只显示一个节点，保留共同来源和循环转账关系，按距任一 L1 的最短路径确定层级。默认展示 L1、L2，支持逐个分支展开、折叠及一键展开至 L5；折叠不删除已取得的数据。连线按来源、接收地址和资产汇总，点击查看交易依据，同一交易不重复计数。该图表达样本内的历史关系；追溯某笔入账的连续来源时需核对交易先后顺序，但不改变 300 笔查询范围，也不将共同来源直接认定为同一团队。

合约源码按运行时字节码哈希复用：先查数据库，相同哈希已保存源码时直接复用，避免重复调用 Etherscan API；没有可复用源码时，即使此前查询过但结果为空，也使用当前合约所属链和地址重新查询。请求成功但源码为空时标记当前合约未开源；请求失败最多重试三次，本轮按首次请求之外再重试三次、总计最多四次请求记录。重试耗尽后通过系统通知组件通知管理员，再将当前合约状态记为未开源，并保留实际失败原因及次数。重试间隔、通知提交失败处理、研究与区块流程衔接、同一合约定时补采与并发请求协调仍待设计。

获取源码用于 AI 静态质检、风险评级和项目过滤，也用于提取其中的项目公开资料链接。通过运行时字节码 `code_hash` 匹配数据库中的源码及报告：已有报告直接复用，缺少报告且有源码时才由 AI 静态分析、生成报告并评级；同一份源码只生成一份共享质检报告。高风险项目直接排除、不再研究，并保存当前项目引用的报告与排除依据。同一份源码也分别共享公开资料提取结果及 AI 对 owner、税费接收钱包和税率的已完成分析结论及方式，需要链上读取的实际地址与税率仍由 Go 程序逐合约读取。这些分析属于独立资料流程，不要求与报告在同一次 AI 调用中产生，也不互相作为完成前提；本次质检不读取链上状态核实角色或参数，不接入静态分析工具。AI 调用失败作为技术异常单独处理，不作为业务筛选分支；风险评级细则、报告格式及技术异常处理仍待细化，尚未实现。

AI 静态报告同时保存两个独立识别结果：“是否使用了代理”和“是否存在外部未知依赖”，附简短源码依据，并随同报告按 `code_hash` 复用。外部未知依赖指合约行为依赖本次源码未提供或无法确定的外部实现，不因出现 `import` 就将完整提供的库或父合约判为未知。两项可以同时存在；“未发现”仅表示本次源码范围内未发现，不代表已核实链上不存在。当前只识别和展示，不读取实际代理实现地址，不继续获取或分析代理实现、外部依赖源码，不递归扩展，也不新增凭这两个标识直接排除或升级风险的规则；原有根据源码代码证据评为高风险后排除的规则继续保留。

第二板块已明确需要扩大 DEX 与协议、报价资产和底池类型的覆盖，现有 WETH/WBNB、USDT 与 V2 协议范围不作为新设计的固定限制；具体接入清单及方式待设计，尚未实现。

已确认不再保留系统自有的合约代码黑名单和钱包黑名单。Token 目标设计已记录后续删除范围，当前代码和数据尚未清理。
