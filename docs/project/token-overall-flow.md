# Token 整体业务流程

> 文档状态：目标设计草案，尚未实现。本图整理已明确的两板块业务关系，不代表当前程序已经具备完整目标能力。

## 入口与目的

从开发阶段纳入范围的顶层合约创建交易发现项目，识别 Token 后取得或复用源码质检报告及风险等级。高风险项目直接排除、不再研究；明确非高风险的项目继续其他研究，符合筛选规则后交接给交易监控与执行板块，在交易开放且满足买入条件时及时买入。

## 流程图

```mermaid
flowchart TD
    deployed["顶层合约创建交易（开发阶段）"]
    subgraph research["板块一：项目发现与研究"]
        discover["发现候选合约并识别 Token"]
        review["取得或复用源码质检报告<br/>同源码共享报告及风险等级"]
        risk{"质检报告风险结论"}
        investigate["继续其他资料研究"]
        select{"是否符合研究筛选规则？"}
        selected["保存通过结论与依据<br/>形成关注项目"]
        filtered["排除项目，不再研究<br/>保存未通过规则、风险报告及其他依据<br/>供后续人工排查"]
        discover --> review --> risk
        risk -->|高风险| filtered
        risk -->|明确非高风险| investigate
        risk -->|没有有效报告或无法评级| unresolved["记录实际原因<br/>后续研究处理待明确"]
        investigate --> select
        select -->|符合| selected
        select -->|不符合| filtered
    end
    subgraph execution["板块二：交易监控与执行"]
        monitor["持续监控是否开放交易"]
        conditions["开放交易后判断买入条件"]
        buy["满足条件后及时买入"]
        monitor --> conditions
        conditions -->|满足条件| buy
    end
    deployed --> discover
    selected -->|关注项目及研究结论、依据| monitor
```

## 关键说明

- 第一板块判断项目是否符合研究筛选规则，第二板块判断当前是否满足买入条件。进入关注范围不直接触发买入。
- 源码质检报告及风险等级按源码共享，按 `code_hash` 查库命中后直接复用，无报告时才由 AI 静态分析。报告评为高风险时立即排除当前项目，不等待其他资料齐备；明确非高风险仅允许继续研究。
- 第一板块以交易开放前完成研究为目标，不采集或研究底池，也不以证明项目尚未添加流动性作为研究或交接前提。
- 添加流动性、开放交易和实际可以买入分别判断；底池和交易开放状态由第二板块研究与监控。
- 早期买入用于寻找盈利机会，不构成盈利保证。两个板块是业务职责划分，不固定服务数量、进程或通信方式。
- 本图展示业务主线。不是 Token 的分支见识别流程；研究不合格的项目仍可保持“是 Token”的识别结论。

## 待明确边界

高风险质检直接排除项目及同源码共享报告已经确定；风险评级细则、无有效报告时的处理、其余研究规则与买入条件、研究完成前已开放交易的处理、买入条件不满足后的处理、交接后继续研究或撤销关注、买入结果确认和防重复执行仍待设计。第二板块将扩展协议、报价资产及底池类型，具体范围待定；持仓和卖出尚未纳入确定范围。
