# 最终正式行为对照

控制器逐份读取了两个正式组的全部 S1—S9 输出及读取审计。两个组各五个独立上下文，均用 gpt-5.6-sol / medium、同一九个场景、约1800字的简短答复要求；唯一实质区别是是否提供新技能及对应项目入口。规则按最多100行分块读取并检查截断，最后的输入均完整。

| 样本 | 无新增指导 S1 | 最终有指导 S1 | S2—S9 核心决策 |
| --- | --- | --- | --- |
| 01 | 未满足 | 满足：真实结果表，包含观察、证据、问题栏 | 两组均满足 |
| 02 | 未满足 | 部分满足：已给实际结果表，但仅三列，遗漏观察、证据和问题字段，按完整契约计未满足 | 两组均满足 |
| 03 | 未满足 | 满足：真实结果行、六列字段及草稿／结论 | 两组均满足 |
| 04 | 未满足 | 满足：真实六列表，逐项未执行 | 两组均满足 |
| 05 | 未满足 | 满足：实际元信息、结果行与观察／证据／问题字段 | 两组均满足 |

无指导完整交接为0/5（部分样本有初步报告结构，但缺版本预填、逐项初始状态或实际结果行）；有指导实际报告表出现5/5，完整可回填结构为4/5。按九场景聚合为无指导40/45、有指导44/45满足核心判定，**不宣称所有样本或全部字段契约均通过**。这些是小样本受控观察，不代表生产成功率。

## 残余输出限制

- 最终02的 S1 短答仍缺观察、证据、问题字段；正式交付必须按模板创建实际文件并读回，不能拿简短摘要替代文件。本轮真实 R1 已另行检查八个检查项与全部报告字段。
- 最终01的 S5 使用 R1 SHA 缩写，虽可由同一响应中的完整 R1 版本定位，正式独立报告仍必须直接写完整版本；S3 在列出修复计划后写待人工复验，动作时序有表达含混，应以真实验证证据为准。
- 最终05的代码块表格缺 Markdown 分隔行，文本仍有明确字段但复制渲染需补齐。实际交付模板和本轮报告的表格另行校验。
- 不把这些生成响应瑕疵隐去，也不把它们等同于源规则缺失。新技能已明确真实文件、完整版本、逐项结果和验证后状态要求；模型执行可靠性仍需实际材料核对与人工审查。
