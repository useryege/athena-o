# 第三方 Go 依赖漏洞修复计划

> 用户已确认本方案并授权实施。基于当前未提交的 Go 1.27.1 升级结果；不提交、不推送、不部署远端。

## 目标与原因

当前 govulncheck 有 9 项可达漏洞，涉及 x/image、gRPC、x/text、Excelize 和 go-git。头像会解码用户上传图片；gRPC HTTP/2 传输实际使用；Excelize 仅用于生成导出文件，没有外部 XLSX 导入；go-git 仅由未注册的错误转换器引用，漏洞调用链来自包初始化。

## 实施步骤

1. 在 `.worktrees/third-party-vulns/` 隔离实施，保存当前源码及未提交改动基线。保留其他任务文件。
2. 删除 `util/grpc/errors.go` 中 go-git 专用错误转换函数和两种 Git 拦截器，删除 `internal/server/athena-server.go` 的两行已注释注册语句。保留 K8s 转换和通用错误处理。
3. 定向升级 `golang.org/x/image v0.45.0`、`google.golang.org/grpc v1.82.1`、`github.com/xuri/excelize/v2 v2.11.0`、`golang.org/x/text v0.41.0`。允许必要的 MVS 间接升级，记录原因；执行 tidy，移除 go-git 及无用依赖。不使用无目标的整体升级。
4. 添加头像格式、资源上限、截断、动画及官方 WebP 安全样本回归；资源较大样本使用内存和时间受限环境。添加 Excel 本地空数据、普通数据、Unicode 导出回读验证。
5. 验证 gRPC 健康、普通请求、认证拒绝、取消和超时；执行完整 Go 测试、四个本地二进制构建、三个 ATHENA Docker 镜像构建。在一次性副本执行完整代码生成，不交付无关生成差异；运行 lint 并区分基线问题。
6. 执行完整隔离 UI 验收；仅同步本次差异回原工作区，重建其 vendor，重启确认归属的本地应用进程，执行真实 smoke，保留数据和无关服务。验收后保留本地应用运行。
7. `make vuln-check` 要求原 9 项消失、可达漏洞为 0 且退出 0；单独报告仅导入包/模块级告警。更新验收文档，独立审查后从原仓库发送一次完成邮件。

## 验收目标与边界

- 清除 GO-2026-6222、GO-2026-5061、GO-2026-4961、GO-2026-6061、GO-2026-5970、GO-2026-5960、GO-2026-5496、GO-2026-4910、GO-2026-4909。
- 保持 Go 1.27.1、Node、前端依赖、业务 API、授权和导出格式不变。
- 不修改不相关的 MinIO 镜像，不禁用功能或过滤漏洞，不引入兼容分叉。
- 若需要更换核心组件、改变业务接口/授权/导出格式、再次升级 Go，或出现超出小范围兼容修复的回归，暂停对应组，告知证据、影响和风险，由用户决定是否暂缓。
- 只有代码、配置、文档和全部必要验收通过后才发送完成邮件。
