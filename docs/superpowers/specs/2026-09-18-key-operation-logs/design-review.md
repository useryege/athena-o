## 2. 已修正的设计歧义

- **迁移归属**：现有账户契约严格校验 public 对象和版本表，日志改用独立 operation_log schema、自有 Goose store 与版本表。已核对本机 Goose v3.25.0 的 Provider、WithStore 及 PostgreSQL 限定表名处理能力。
- **并发分页**：ingest sequence 不能代表连续提交水位，使用同事务发布的 publication 序号和历史可见版本；结果筛选必须在快照内进行。
- **游标一致性**：签名中保存固定筛选参数和首个快照有效期；列表与详情分别有 token kind，不因翻页续期或重新计算 now 而改变查询。
- **真实业务事实**：注册提交与随后的发布、登录分开记录；异步受理、未知、部分成功及响应写回失败不被协议状态覆盖。
- **两阶段乱序**：未确认 START 与可信 FINISH 的兼容关系不受到达顺序影响；已隔离冲突事件不再参与后续折叠。
- **入口准确性**：私钥查看路径保留实际 revealPrivateKey 大小写；认证初始化只补入失败路径，成功跳转／challenge 仍不采集；注册后登录明确为子动作。
- **异常计数**：同一事件两次提交只统计一次终态，未确认入箱不等于确定丢失；恢复后不删除历史观测。
- **等待边界**：每阶段最多 200 ms，同一请求包括子动作共用最多 400 ms 采集等待，不重放业务操作。
