# Solana 第一步：新项目发现与列表

> 状态：用户已要求规划并实现第一步，已选择 ATHENA 简单列表页。本文将该范围落实为最小实现方案；研究与刷新调度延后，不作为本步完成前置。

## 目标与边界

从 Solana Mainnet Beta 发现新初始化的代币 Mint，保存可核对的发行事实，在 ATHENA 独立 Solana 页面查看。用户基于真实样本再决定下一步研究能力。

首版覆盖原始 Token Program 与 Token-2022 的成功 InitializeMint / InitializeMint2，包含顶层和 CPI 内部指令。所有结果是新发行候选，未分类为投资项目；不以 decimals、供应量或是否已交易排除 NFT、LP 等候选，也不宣称已覆盖自定义代币程序。创建时发生首买不影响收录。

本步没有项目研究任务、活动监控、周期资料刷新、每小时限频、评级、筛选或交易。持续研究与一小时刷新是保留的后续方向。后台持续发现新 Mint 与持续研究单个项目是两种工作。

## 发现与存储

采用标准 HTTP RPC，固定 finalized commitment；启动核对主网 genesis hash。首次启动从最新 finalized slot 向前 32 slots 开始，可通过配置指定更早起点。保存首次扫描起点并从持久进度恢复，不在每次启动重置起点。

按有界 slot 范围调用 getBlocks，取得实际区块，再通过 getBlock 的 jsonParsed/full 元数据解析。支持 legacy、v0 和地址查找表解析；只处理执行成功交易，验证实际 Token 程序身份、Mint 公钥及初始化字段，不依赖日志关键字。解析器忽略其他程序的同名字段，合法未知指令不影响解析；已识别初始化形状损坏时必须报告错误，不能悄悄漏过。

每个范围的候选与检查点在同一 PostgreSQL 事务提交。按 mint 唯一去重，保留首次发行证据。已列出的区块无法读取或解析时，不推进范围进度；重试有取消、超时和退避。getBlocks 中未列出的 finalized slot 按提供方返回的跳过 slot 处理，历史不足或读取失败单独报告，不声称自行验证了节点账本完整性。

并发获取区块有固定上界，提交按 slot 顺序；一轮最多 32 slots；主网公共节点实测单块约17MB且触发限流，因此服务初值为每范围4 slots、并发1、请求预算每秒1次、每次超时15秒，预览使用每范围1 slot。追平后每 2 秒查新范围，有积压时继续推进。上述是可配置运行初值，不是已验证 SLO；公共节点的字节额度不足以承诺持续追平。服务展示扫描起点、进度、已观察最新 finalized slot、最后成功时间、积压及错误，公共节点不足时明确显示落后。

项目保存 mint、tokenProgram、signature、feePayer、mintAuthority、freezeAuthority、decimals、slot、blockTime（未知为 0）和 discoveredAt。两个 authority 是初始化时的值，不表示当前权限；feePayer 不标为项目创始人。Mint 地址标识候选，不执行外部 metadata 网页抓取。名称和符号不作为发现前置，本步通过链上链接进一步查看。

## 服务边界与权限（SDS-R1 至 SDS-R8）

新增独立 Go 服务 internal/solanadiscovery，由独立命令 cmd/athena-solana-discovery 构建和运行。该服务拥有扫描生命周期、独立 solana_discovery schema、检查点及项目查询；同进程中的解析器、RPC adapter、存储及查询只有一个业务 owner。

API 只代理查询，不持有扫描器或启动后台任务。同步接口使用 gRPC：ListProjects、GetDiscoveryStatus；公共 HTTP 为 GET /api/v1/solana/projects 和 GET /api/v1/solana/status。共用已生成的消息与服务定义，API 和独立进程分别注册代理与业务实现。公共请求不接受用户身份字段。

API 从已认证上下文提取真实账户，通过内部认证通道传递账户身份；独立服务验证独立 Bearer token 和唯一的可信账户 metadata，再从自己拥有的数据库连接读取账户权限，执行 Solana READ 的权威鉴权。后台扫描使用配置声明的节点服务身份，不伪装成用户查询。内部 token 缺失拒绝业务 RPC；健康检查只报告健康，不暴露项目。代理 deadline 为 10 秒，取消向下游传播。

新增 solana 独立权限模块，最高 READ；成员默认 NONE，管理员按现有规则不隐式访问成员业务，本地开发会员沿用最大权限机制。完整账户权限矩阵扩展为 11 项，修改其他权限时不能丢失 Solana 或已有 Token 授权。API、独立业务服务及页面均落实读权限。

Solana 与账户权限使用同一 PostgreSQL 实例的不同 schema；查询权限时创建只读 adapter，连接池生命周期由 Solana 服务控制，事务不跨 RPC。共享数据库是共同故障域。服务启动仅校验自身 RPC、DSN、内部 token、端口与扫描参数；节点故障不能退出 API。

提供正向独立 build/run/stop 入口，局部只依赖 PostgreSQL 与节点，不隐式拉起 API、UI 或其他业务。全栈 make run 显式包含新进程。优雅关闭取消节点调用、停止接收业务、等待有界收尾并关闭自有连接；局部停止不重置数据库或清理他人资源。

## 最小页面

成员端 /solana，桌面侧栏和移动导航独立显示 Solana，沿用 Token & Risk 分组和已有界面组件。标题 Solana；说明候选来自两个 Token 程序、资产尚未分类。显示扫描状态、起点、进度、最后成功时间；节点错误和空结果分别表达。

默认最近发行优先，25 项分页，最大 100；可按 Mint 地址查询，手动刷新仅重新读取已保存结果。列表主要列为 Mint（复制及 Solscan 链接）、程序类型、发行时间、发现时间、精度、交易链接；行展开显示初始化时的增发/冻结权限、手续费支付方及 slot。未知时间/无权限显示明确空值，不猜名称、项目类型或创始人。

保持加载、失败重试、无结果、无权限与已有数据状态。移动端表格在自身容器横向滚动，页面不溢出；复用既有明暗主题和键盘可访问组件。

## 验证与交付

解析器测试包括两程序、顶层/CPI、失败交易、伪造同名指令、重复初始化证据、v0 地址、未知及损坏形状。运行时验证重启恢复、失败不推进检查点、去重、事务失败和有界停止。真实 PostgreSQL 验证持久查询及并发提交，真实 Solana RPC 产生可查样本。

查询测试覆盖分页校验、空结果、错误传播、缺少/错误内部 token、缺少身份、NONE 与 READ 权限；账户矩阵和授权回归。页面测试覆盖数据、空态、错误重试、权限、刷新、分页和链上链接。

完成受影响生成、Go 测试/构建、UI 测试/lint、真实目标环境的 member/admin bootstrap 与 smoke，另对 Solana 页面取得真实数据的浏览器证据。记录节点、时间范围、样本数量及局限；没有容量和长期稳定证据时不作保证。验收环境默认保留运行。
