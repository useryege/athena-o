> 状态：已展示的 v5 截图视觉获用户确认，反馈为“可以”。本组规则服务于 ATHENA 当前全站前端 UI 重构；钱包列表是组件审阅样板，正式 UI 与 Nansen 接入仍未实现。
>
> 依赖：沿用已确认的 [v1 配色](visual-theme.md)、[v2 字体与数字排版](typography-proposal.md)、[v3 导航／页头／页面密度](layout-proposal.md)及 [v4 第一组通用组件与状态](components-proposal.md)。钱包数据字段与查询行为继续以[钱包战绩需求](../token/wallet-trading-performance.md)为准。

## 本轮审阅范围

v5 使用虚构的钱包逐币列表，集中展示下拉菜单、完整合约地址筛选及“加载更多”的视觉关系。桌面样板在列表上方横向排列搜索和排序控件；手机样板将两组控件纵向排列，并沿用 v3 已确认的逐币摘要结构。

用户直接查看了桌面菜单展开、手机菜单展开和手机筛选结果三张截图；其他截图通过文档提供。已确认范围及原件摘要见 [v5 确认记录](previews/theme-list-controls-v5-approval.json)。以下记录本组视觉内容，以直接展示状态为确认范围；未展示交互与追加加载过程仍是原型验证事实。

- 搜索输入、Search 按钮、排序触发器及展开菜单之间的尺寸、间距和层级。
- 下拉菜单的灰色边界与深色面板，以及当前选中项的深青色背景和青绿色勾选标记。
- 已应用地址筛选标签、清除入口和列表结果之间的视觉关联。
- 列表底部已加载数量、“加载更多”按钮及全部加载状态的布局；手机按钮采用满宽样式。
- 已展示的桌面列表、手机菜单展开及手机筛选结果的信息密度；追加加载后的密度保留为样板检查内容。

v1–v4 已确认的单一深色主题、文字层级、地址字体、按钮层级和手机页面结构不在本轮重新选择。焦点轮廓沿用原型已有的可访问性处理，其具体外观未由 v4 单独确认。正式逐币字段全集、金额精度、缓存、请求组织和生产组件实现也不由本轮视觉确认决定。

## 样板控件与行为

### 合约地址筛选

- 搜索框只接受完整 Ethereum 合约地址，地址文字继续使用 JetBrains Mono；Search 是明确提交动作。
- 输入内容是本地草稿，不会在键入时即时改变列表。提交有效地址后，已应用条件显示为独立筛选标签，并提供清除入口。
- 清除标签恢复全部虚构代币结果，但保留当前钱包、时间范围及排序方向。无效地址显示字段级错误；有效但无匹配结果显示当前条件下的成功空态，两者不能混用。
- 样板在完整本地虚构数据中执行筛选，不只过滤当前可见的五行。首版仍不支持代币名称或简称模糊搜索，也不扩展为全网代币发现。

### 排序下拉菜单

排序菜单只提供两个已确认选项：

- `Realized PnL: High to low`，默认选中。
- `Realized PnL: Low to high`。

当前选中项使用深青色背景、青绿色勾选标记和清晰文字；未选项保持深色背景，菜单整体使用灰色边界。菜单触发器显示当前排序方向。切换排序后从首批结果重新展示，不能只重排当前可见行后宣称是完整查询范围的排序。

样板不增加按未实现盈亏、买入金额、卖出金额、持仓或代币名称排序，也不展示 `show_realized` 一类供应商参数。键盘焦点、上下键选择、Enter 确认、Escape 关闭、点击外部关闭及关闭后回焦作为原型检查项，不由静态截图单独证明。

### 加载更多

- 列表底部显示当前已加载数量，并使用“加载更多”按需追加结果；不显示总页数、数字页码、每页数量选择或虚构的总记录数。
- 为让截图清楚展示控件，样板首次显示五行，再追加三行。这只是本地视觉演示，不改变正式需求中逐币列表首次及每批最多 20 个代币的规则。
- 更改地址筛选或排序后清除此前追加的结果，从新条件的首批结果开始。正式业务追加失败时应保留已经显示的数据并提供重试，不能表现成已经全部加载；该规则沿用钱包需求，本轮原型未模拟网络分页失败。
- 本地样例加载完八项后显示全部加载状态并禁用继续请求。该状态只描述样板数据，不表示真实钱包的全部代币或历史已经加载。

## 列表字段与业务边界

为集中审阅控件，v5 只展示以下已确认字段的子集：代币符号与地址、买入金额（USD）、卖出金额（USD）和已实现盈亏（USD）。桌面使用表格，手机使用 v3 已确认的摘要结构。未在样板显示的持仓数量、持仓价值和未实现盈亏仍属于最终字段映射，本轮不删除或调整这些需求。

所有钱包、代币和金额均为独立构造的虚构示例，仅用于比较筛选、排序和加载状态，不构成 Nansen 响应、完整账本或可汇总的真实结果。样板遵守以下既定边界：

- 买入和卖出金额采用 Nansen 口径，可能包含普通转入或转出，不包装成纯 DEX 现金流。
- 排序依据为供应商返回的已实现盈亏 USD 金额，不在本地重新计算收益。
- 已加载数量不等于完整查询范围；逐币结果为空也不能据此断言钱包没有任何交易。
- 缺失值、有效零值和微量非零值继续分别表达；本轮有限字段不扩大为空值与精度规则的完整确认。

已保存的 Nansen 样本使用 `page`、`per_page` 和 `is_last_page`，但 ATHENA 内部接口及分页缓存尚未设计。v5 因此只演示已经确认的“加载更多”用户交互，不承诺生产界面采用游标、公开页码或精确总量。

- 四种场景没有整页横向溢出、菜单水平溢出、重复 ID、字体加载失败或页面脚本错误；初始、菜单展开、筛选结果与成功空态均无 axe WCAG 2 A/AA、2.1 AA 自动违规。
- 校验无效地址、保留输入草稿、提交完整地址并找到首屏未展示的样例、清除条件、无匹配恢复、键盘选择代币通过。
- 菜单上下键／Home／Enter、Escape 回焦、点击外部关闭、两种排序与批次重置、追加到八行及末批禁用通过。
- 页面无外部网络请求。本次仅运行隔离浏览器，结束后已关闭；未启动预览服务或正式开发服务，也未改变已有环境。

200% 为根字号放大模拟，不代替所有浏览器原生缩放或正式产品验收；本次未覆盖所有网络失败、异步请求竞争和无障碍手工场景。用户已认可本轮展示的视觉效果；原始 HTML、截图和审阅记录保留当时的“待确认”状态，当前范围以确认记录为准。

独立视觉审阅结论为 `ship`：六张截图能够用于本轮用户确认，没有需要返工的可见问题。该结论只表示样板可审阅，不代替用户认可或正式产品验收。
