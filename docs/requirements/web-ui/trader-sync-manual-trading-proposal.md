## 视觉和交互依据

沿用[全站主题需求](visual-theme.md)、[v23 一致性修订](theme-consistency-contract.md)、[Trader Sync 首页](trader-sync-home-proposal.md)及[订阅详情](trader-sync-subscription-detail-proposal.md)。样稿直接读取正式 `ui/src/app/styles/tokens.css` 与共用字体资产；正式组件仍通过现有 Provider 使用这些规则。

- 近黑页面、深色面板、白／灰文字和青绿色主要操作。成功、警告、错误另用语义色并附文字。
- Inter 用于文字与数字，JetBrains Mono 用于完整地址。数值列对齐，未知与零分别表达。
- 桌面保留 224px 侧栏与 64px 顶栏；手机折叠侧栏，正文单列。页标题、正文、控件和辅助文字沿现有 rem 层级。
- 买卖、领取的账户与市场持续可见；来源、身份补充和过程证据按需展开。主操作位于核对内容之后，手机采用文档流，不遮住费用或输入错误。
- 本批是现有 Trader Sync 的交易流程局部预览。侧栏仅展示相关上下文，正式实现保留原导航与权限入口；不会将交易钱包设置变成可随意切换目标的全局账户配置。

## 八个页面视图

| 视图 | 桌面阅读顺序 | 手机阅读顺序与关键差异 |
| --- | --- | --- |
| Trading wallet | 左侧目标、绑定钱包及实际账户，右侧启用范围；就绪后右侧换为准备状态、余额与官网入金入口 | 目标／绑定 → 实际账户 → 授权范围 → 主动启用。绑定保存和启用是不同操作 |
| Buy | 左侧市场／Outcome、执行账户与折叠来源；右侧本金、价格保护、报价与费用核对 | 交易对象 → 输入 → 报价与预计支出 → 预留与余额 → Confirm BUY。首次金额和首次价格保护为空 |
| Sell | 左侧该仓位的账户、总份额、占用和可卖份额；右侧比例与核对 | 主动选择比例；100% 只使用当前可卖份额，另显示不可表达尾数。旧钱包使用自己的实际账户 |
| Redeem | 左侧已结算市场及到账账户；右侧全部影响范围、分项兑付与总额 | 每个 Outcome 完整成组。全余额路径显示实际执行时处理范围，零兑付侧也列明；指定数量另有状态 |
| My positions | 钱包／市场筛选后，依次显示未结算、已结算、资料待核对 | 表格重排为每仓位一组，保持市场、钱包、份额和操作关联；已解绑、小额余量和有份额的零价值记录仍可见 |
| System records | 历史页第一视图，逐条展示提交方向、对象、状态和已核准结果 | 先时间与方向，再对象／账户，最后实际结果与详情；拒绝、失败、待核对不会消失 |
| Trade history | 同一历史页第二视图，展示全部实际 BUY／SELL 与可靠的系统关联 | 保留一提交对应多笔成交、绑定前成交、费用未取得及无可靠关联的区别 |
| Record details | 左侧冻结的提交上下文，右侧实际结果与展开证据 | 当前结果优先；原确认、处理过程、相关成交和标识依次展开。待核对状态只查询原结果 |

历史两种视图属于同一页面，不新增第三类历史。启用步骤记录仍在 Trading wallet。入口继续遵循[已确认的页面组织](../../design/web-ui/trader-sync-manual-trading.md#已确认的页面组织)：目标买入活动进入买入；目标卖出活动只定位自己的对应持仓；钱包设置从目标详情进入。返回时保留上下文并重读当前条件。

## 这批页面落实的具体信息

### 账户准备

实际交易账户、Wallet 签名账户和官网身份分别说明；已有账户优先复用。查询失败、暂不支持、可靠确认不存在有独立状态。启用前显示资金最大额度、具体合约及持仓 operator 的持续范围，并主动确认；创建、准备、入金、买卖互不冒充。

已准备页面分别显示账户访问、买卖准备、领取准备、可用余额和历史覆盖。样稿内的地址均为虚构；正式合约清单必须来自已核准的后台路径，不能使用样稿地址，也不能把示例清单当成全部协议的固定配置。

### 买卖核对

买入本金排除费用；报价同时显示最优对手参照价、预计均价、保护价、份额、费用和预计支出。预留金额与实际预计支出分开，前者并不表示已经收费。卖出区分总持有、已占用、可卖和本次份额；百分比与价格偏差各用自己的上限。

必要事实失效或修改输入后禁用旧确认。15 秒期限来自后端，正式页面倒计时到期后只能刷新再确认。深度不足时显示预计部分成交并保留完整请求数量；不自动减本金、补剩余订单或放宽保护。

### 领取与同步

全余额路径明示处理所列 Outcome 在执行时的全部余额；指定数量路径冻结明示数量。必要准备缺失时先去钱包设置，准备后返回刷新并再次确认领取。已领取到账但持仓列表尚未刷新时，同时显示成功与更新中。

历史同步提示位于列表上方，账户间的覆盖、时间区间和缺口在展开区分别展示。没有可靠总量时不显示百分比。已取得内容可以阅读，当前资产条件核准与全历史完成分别判断。分页视图过期时明确重载，保留筛选条件。

## 辅助状态覆盖

样稿状态菜单承接这些情况；截图目录另外列出本轮保存的代表性状态，不把菜单存在等同于每个状态均已单独截图或做完整功能测试。

| 范围 | 可审阅状态 |
| --- | --- |
| 账户 | 启用前、就绪、未绑定、可靠不存在、查询失败、暂不支持、启用中、启用未知、缺权限、余额未知 |
| 买入 | 已报价、首次空表单、过期、余额不足、资产读取失败、预计部分成交、绑定变化、缺权限、登录替换 |
| 卖出 | 已报价、首次无比例、过期、数量低于门槛、资产读取失败、预计部分成交、缺权限 |
| 领取 | 全余额、指定数量、需要准备、过期、范围被占用、零兑付、资格未知、成功但持仓更新中 |
| 持仓 | 有数据、加载、真实空、筛选空、整体失败、单账户失败、有新数据待刷新 |
| 历史两视图 | 有数据、空、读取失败、同步中、分页视图过期 |
| 记录详情 | 部分成交、待核对、尚未确认系统接收、已拒绝且未发出、核准失败、领取成功但列表更新中 |

缺少授权、费用或余额等条件时，正式前端以后台原因和可恢复动作呈现；不能通过切换 UI 状态解锁交易。管理员与 APIKey 不增加交易入口。

## 验证与边界

本轮只验证静态设计样稿：桌面 1440px、手机 390px、320px 重排及根字号 16→32px。根字号模拟不等同于浏览器原生缩放。自动无障碍检查只覆盖本次运行的主视图；键盘与手动截图审阅补充其结果。

原型中的计算用于排列说明性样本，报价时间暂停供审阅；点击提交只展示本地模拟记录，没有 SDK、后端、密钥、签名、真实授权或成交。时间／状态筛选的示意控件、远端刷新、真实恢复与持续同步仍须在正式实现中完成，预览检查不证明这些后台行为。

本批无需启动 ATHENA、数据库、容器或预览服务器；浏览器进程在检查后关闭。代码与批准资料保留在原工作区，未修改正式 `ui/` 或 Go 实现。
