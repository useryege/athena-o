> 状态：v2 的字体搭配、字号层级与数字排版视觉效果已确认。用户查看桌面和手机截图后反馈“可以 舒服”。交互、业务展示语义及跨平台交付细节不由本轮截图认可整体确认。
>
> 依赖：[全站视觉主题需求](visual-theme.md)中的 Nansen 参考方向和已确认 v1 配色。正式 UI 尚未修改。

## 确认依据与范围

用户查看 [桌面截图](previews/theme-typography-v2-desktop.png)与[手机截图](previews/theme-typography-v2-mobile.png)，针对字体大小和数字清晰度反馈“可以 舒服”。本轮确认字体搭配、文字层级和数字排版的视觉效果；页面布局、表格字段、业务计算及完整组件状态继续按各自需求讨论。具体范围和审阅文件摘要见 [v2 确认记录](previews/theme-typography-v2-approval.json)。

[v2 HTML 样板](previews/theme-typography-v2.html)、两张截图及原始审阅记录保留提交审阅时的内容，包括“待你确认”等历史标记；当前状态以本文和确认记录为准。后续样板另存版本并沿用已确认的配色与字体基准。

样板保留已确认的八项基础颜色以及主次按钮视觉层级。工作台使用现有产品的英文语言，外围为中文审阅说明，并提供中文阅读样例。该样例不表示新增中英文切换需求。

## 字体搭配（视觉已确认）

| 角色 | v2 字体搭配 | 使用理由 |
| --- | --- | --- |
| 英文标题、正文、控件、金额和百分比 | Inter | 同一字体通过字号和字重建立层次；Nansen 官方品牌资料将其列入字体体系，符合已明确的参考方向 |
| 钱包地址、交易哈希等逐字符核对内容 | JetBrains Mono Regular | 等宽字符便于辨认地址，仅用于这一明确用途；关闭编程连字 |
| 中文内容 | Noto Sans CJK SC → PingFang SC → Microsoft YaHei → sans-serif | 由可用中文字体补全字形；当前样板使用设备字体，跨系统字形仍有差异 |

这是 ATHENA 工作台已确认的视觉搭配，未声称复制 Nansen 的完整字体系统。Nansen 的 Uniforma 标题字体是参考证据，当前不纳入样板；工作台的标题、正文与数字用 Inter 统一层次。金额使用 Inter 的等宽数字特性，不将整页文字改成等宽字体。中文截图确认的是当前样板的阅读效果，其他系统上的中文字体回退仍需实际验证。

字体依据：[Nansen 品牌规范](https://nansen.ai/brand)、[Inter 官方字体与数字特性](https://rsms.me/inter/)、[JetBrains Mono 官方介绍](https://www.jetbrains.com/lp/mono/)。两份字体及各自随附的 SIL Open Font License 1.1 均已保存到 `previews/files/`，来源 URL、大小和 SHA256 见[字体来源记录](previews/files/typography-v2-font-sources.json)。许可全文见 [Inter](previews/files/Inter-LICENSE.txt) 与 [JetBrains Mono](previews/files/JetBrainsMono-OFL.txt)。

预览实际从同目录加载字体，不依赖访问者安装 Inter 或 JetBrains Mono，也不向字体服务发送运行时请求。当前仅保存两份直立字体资源，共 444,620 字节；Inter 使用可变字重，JetBrains Mono 只使用 400。采用 `font-display: swap` 保持加载期间文字可见；生产部署时的回退度量、中文资源与加载策略仍需实际页面验证。

## 文字层级（视觉已确认）

以下尺寸以浏览器默认根字号 16px 为基准，样板使用 rem，保留文字放大能力。字重限定常规 400、中等 500、半粗 600；无需用大量接近的字号区分角色。

| 角色 | 桌面字号 / 行高 | 手机字号 / 行高 | 字重 | 用法 |
| --- | --- | --- | --- | --- |
| 页面标题 | 28px / 1.3 | 24px / 1.35 | 600 | 标识当前业务页面 |
| 区块标题 | 20px / 1.4 | 同桌面 | 600 | 分隔任务内的信息组 |
| 正文说明 | 16px / 1.6 | 同桌面 | 400 | 连续阅读的说明与中文内容 |
| 控件文字 | 14px / 1.4 | 同桌面 | 500 | 主次按钮共享文字层级 |
| 表格数据 | 14px / 1.5 | 同桌面 | 500；代币名称 600 | 便于连续扫描和纵向比较 |
| 表头 | 13px / 1.55 | 同桌面 | 500 | 正常大小写，不采用全大写加宽字距 |
| 辅助信息 | 13px / 1.55 | 同桌面 | 400 | 时间、单位、数据来源说明 |
| 首要金额 | 40px / 1.2 | 32px / 1.2 | 600 | 中等视口 36px；空间不足优先重排 |
| 次要指标 | 24px / 1.3 | 同桌面 | 500 | 百分比、计数等 |
| 地址与哈希 | 13px / 1.7 | 同桌面 | 400 | JetBrains Mono，仅该角色使用等宽字符 |

标题轻微收紧字距（页面 −0.02em、区块 −0.01em），正文保持正常字距。主要金额 −0.025em，表格数字保持正常字距。普通说明最大宽度约 68ch；中文应结合字形和视口判断实际行长。13px 辅助文字使用已确认的灰色，不能因“辅助”而降低到不可读。

表格与控件采用 14px，是为工作台密度提出的角色选择；16px 正文承载连续说明。窄视口保留表格字号，在表格区域内横向滚动；不靠缩小整张表解决空间不足。

## 数字排版基准与后续展示建议

本轮确认了等宽数字、金额列右对齐，以及截图中千分位金额、百分比、正负号和辅助文字的视觉清晰度。以下列出样板的展示建议，作为后续业务与组件设计的输入；不能将截图认可扩大为所有业务的精度、舍入、缺失状态或交互契约已确认。这些建议不改变上游数据、计算方式、数据库精度或 Nansen API 口径。

- 金额、百分比和计数启用 `tabular-nums lining-nums`。金额列与对应表头右对齐；在业务格式规则允许时，同列美元金额使用相同的小数位。不为对齐改写原始精度或统一所有业务的显示位数。
- 美元金额常规展示千分位和两位小数，例如 `$1,284,567.89`；盈亏正负号置于货币符号前，如 `+$4,110.00`、`−$415.00`。符号与数字不分行，盈亏不能只靠颜色表达。
- 百分比常规显示一位小数，例如 `68.4%`；单位层级弱于数值。此为首选展示格式，特殊业务精度需按该业务确认。
- 极小非零美元金额不能伪装成零；本样板以 `+<$0.01` 表示大于零且不足一美分，完整值展开为 `+$0.004218`。负值对应保留负号；实际为零显示 `$0.00`，避免 `−$0.00`。
- 大金额核对区域保留完整千分位，不默认换成 K/M。详情保留来源提供的完整精度；样板不据显示位数改写或截断原始值。
- 数据缺失明确写 `Unavailable`，使用辅助文字颜色；不显示成零。真实业务若有可用的缺失原因，应按接口事实说明。本轮不创造新的缺失状态或推测原因。
- 钱包摘要保留 `0x` 和首尾片段，例如 `0x12ab…90cd`；完整值可展开并复制。复制始终使用完整原值，保持字符大小写，不复制省略号。
- 完整地址的只读输入可选中、横向查看；完整哈希可在任意字符处换行。展开入口支持键盘与触摸，不只依赖悬停提示。复制被浏览器拒绝时，展开并选中完整地址，提示手动复制。

样板的统计数字与逐币行是分别构造的字体示例，明确标为虚构，不构成可汇总的钱包战绩或 API 返回样本。两个按钮仅演示展开与本地复制；不查询链上数据，不消耗 API 额度。

## 样板检查与范围

检查结果见 [v2 浏览器记录](previews/theme-typography-v2-checks.json)。本次使用项目已有 Playwright 配套 Chromium 和 axe 检查独立 HTML：

- 1440 × 1050 桌面、390 × 844 手机、320px 窄视口，以及 720px 视口下根字号增至 200% 的文字放大场景；均无整页横向溢出或金额裁切。
- 两份字体在上述场景均实际加载；金额使用等宽数字和右对齐。中文截图体现当前 Linux 的 Noto Sans CJK SC，尚未检查 Windows/macOS 的中文回退。
- 完整值展开与焦点、复制完整地址、剪贴板拒绝后的选中回退通过；无页面脚本错误或失败资源请求。
- 四个初始视图的 axe WCAG 2 A/AA、2.1 AA 自动扫描均无违规；这不等同于所有状态或正式平台通过完整无障碍验收。
- 初次文字放大暴露了固定三列指标相互挤压，已改为按内容宽度换行；说明区同样按字体所需宽度重排，重验通过。200% 是文字尺寸模拟，320px 是重排检查，不宣称已覆盖所有浏览器原生缩放组合。
- Impeccable 的 `overused-font: inter` 提示已审阅：样板根据用户指定的 Nansen 参考方向选择 Inter，并有明确的数字特性用途。通过 `impeccable hooks ignore-value` 保存仅针对 `theme-typography-v2.html` 中 Inter 的例外及理由，其他文件、字体与检查规则继续生效。该例外最初在方案待审阅时登记，用户随后通过截图确认了字体视觉效果。

已确认的 v1、v2 HTML、截图及原始审阅记录保持原样。后续 v3–v22 的确认与当前范围见[主题需求](visual-theme.md)；[实施计划](../../superpowers/plans/2026-09-14-web-ui-theme-refactor.md)已形成。总体审阅后的[修订契约](theme-consistency-contract.md)补齐实际字号放大和局部内容边界检查，以及 Worm／Market Radar 的数值列角色；不覆盖各业务的精度规则。正式组件变量和 UI 实现仍待实施。
