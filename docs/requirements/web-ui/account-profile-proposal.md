# Account Center / Profile 页面视觉基准

> 状态：v11 所展示的桌面资料页、手机编辑状态与手机离开确认视觉已确认；正式 `ui/` 未修改。
>
> 范围：现有会员 `/account/profile` 在 v1–v10 视觉体系中的普通扩展。管理员 `/admin/account/profile` 虽复用当前源码，但不属于本轮视觉审阅或确认范围。

## 目标与视觉方向

页面应让用户一眼分清不可变的账户用户名与可修改的显示名称，并在一个资料面板中完成身份核对、头像操作、名称编辑和未保存状态判断。v11 合并当前页面重复的已保存身份、首字母头像与上传区域，形成一条资料身份行；下方依次显示只读 Username、可编辑 Display name、状态反馈以及 Reset／Save。

v11 沿用已确认的 Nansen 单一深色方向与 v1–v10 基准：近黑 `#06080B` 页面、`#0F1114` 面板、白／灰文字、青绿 `#00FFA7` 主要操作、克制边框和既有警告／错误语义。英文标题、正文和数字继续使用 Inter；技术标识才使用 JetBrains Mono。本轮原型没有新增视觉身份或修改全站基准，具体证据见[样板索引](previews/README.md)。

## 页面结构与导航

桌面保留 Account Center 页头、账户局部导航和单个 Profile 面板；手机以 Account section 选择器替代局部侧栏，并按身份、用户名、显示名称、状态和操作纵向阅读。Standard 仅为展示层级，Member 仅说明当前 fixture 身份，两者都不构成授权证明；账户 UUID 不成为新的自助页面可见字段。

目标单一深色界面中移除 Appearance 导航与说明。浏览器内仍有效的非主题偏好继续保留，主题偏好、服务端偏好及旧主题路径的实际清理范围仍由全站重构技术设计确定。Security 只在普通会员且 `access.apiKeyEnabled` 为真时出现；管理员 Account Center 不因共享页面代码而获得本轮视觉确认。

## 资料与头像规则

- Username 保持不可变并只读展示；Display name 是唯一可编辑名称。输入先 trim，再按 1–80 个 Unicode code point 校验，禁止控制字符；字符计数按原始输入显示，不能用 UTF-16 code unit 或 trim 后长度冒充计数。
- 脏状态比较规范化后的草稿与最近保存基线。已保存身份与当前草稿保持区分；Reset 恢复最新基线，不能恢复到页面首次加载后已经过时的值。
- Save 使用账户 UUID、当前 Profile revision 和规范化名称。`409` 时刷新最新 Profile，保留用户的脏草稿并显示冲突警告；其他失败继续显示真实 `requestErrorMessage`。失败或本地演示均不能显示虚构的保存成功。
- 头像接受 JPEG、PNG、WebP，最大 2 MiB；原图在圆形框中裁切显示。当前 fixture 没有头像，使用现有规则得到首字母 `A`，没有伪造照片。
- 头像上传、替换和删除是即时、独立于名称 Save 的操作；只有当前确实存在头像时才显示 Remove。头像 revision 冲突要刷新最新资料，文件无效、上传失败和删除失败保持不同反馈。

## 未保存更改与恢复

正式实现继续使用路由阻止与 `beforeunload` 保护名称草稿。离开确认应同时展示已保存名称与草稿，默认安全焦点落在 Keep editing；Tab／Shift+Tab 保持在弹窗内，Escape 与 Keep editing 保留草稿并恢复触发点焦点，Discard and leave 才放弃草稿并继续导航。账户或授权身份切换、Profile revision 更新、初次加载和保存中的边界需要在生产改版中重新验证。

## 正式实现契约

以下行为来自当前 React、校验与账户资料设计，是后续正式改版必须保留并验证的契约；本次文档原型没有验证真实服务行为：

- Profile 读取、名称保存、头像上传／删除及 CAS 冲突使用真实 API、账户 UUID 与服务端 revision；刷新后的保存基线与独立草稿状态保持一致。
- 文件类型、大小与真实头像对象状态由生产逻辑判定；上传／删除进行中、失败、冲突刷新和 Remove 条件状态不能由原型 notice 代替。
- 路由切换、浏览器关闭／刷新、身份切换、授权变化与异步加载继续保护或正确清理草稿，不把另一账户资料复用为当前基线。
- 会员 Security 条件继续满足 `!isAdmin && access.apiKeyEnabled`；管理员共用源码的自助 Profile、权限和视觉需要单独设计及验收。
- 生产表单应像原型一样用明确的 `label`／`id` 关联 Username 与 Display name。当前 React 对比采集发现可见的 `Form.Item` 标签未关联输入框；本轮没有修改生产源码。
- [当前账户资料与偏好设计](../../design/identity-access/account-profile-and-preferences.md)仍描述已实现的明暗偏好现状；本提案只记录目标视觉，不能据此宣称旧主题存储与接口已经清理。

## 原型数据与交互边界

[共享数据](previews/theme-account-profile-v11-data.json)是虚构 fixture，当前无头像，首字母 `A` 来自真实回退规则。可操作 HTML 支持本地草稿、校验、Reset、样例状态和离开弹窗；Save 与 Upload 只显示本地 notice，不提交账户写请求，导航也不离开原型。原型未展示已有头像时的 Remove，也未覆盖实际上传、删除、Profile／Avatar CAS、身份切换、权限或管理员页面。

原型检查覆盖 1440×900、390×844、320×844 和 720×900／根字号 200%，核对无页面横向溢出、重复 ID、页面错误、外部请求与记录问题，并检查字体、对比度、校验、草稿恢复及离开弹窗焦点行为。12 张最终原型图覆盖默认、编辑、无效输入、名称冲突、保存错误、上传错误、离开确认、窄屏与文字放大；2 张当前 React 图使用同一虚构 fixture，仅发出 bootstrap GET，1 个测试通过并生成 2 张截图。它们不是完整 smoke、服务端验收或真实账户写入验证。

所有 PNG 均为带来源记录的 Playwright Chromium 截图，没有 AI 生成或修图。用于当前 React 对比的临时 Vite `127.0.0.1:5621`（会话 38406、PID 3628576）已停止；任务前存在的共享服务均保持原样。Impeccable detector 仅对 v11 HTML 持久忽略 `overused-font=inter`，依据是 v2 已确认字体；没有其他检查发现，此例外不扩展到其他文件。

## 审阅与确认边界

[v11 审阅记录](previews/theme-account-profile-v11-review.json)覆盖全部 14 张图片、原型源码、既有视觉方向、当前源码契约和浏览器证据，独立审阅处置为 `ship`，未提出需要修正的视觉问题。该结论表示原型在本地展示范围内达到交付标准，不是用户视觉批准、生产验收或正式实现完成。

用户于 2026-09-14 查看桌面默认资料页、手机编辑状态和手机离开确认弹窗后反馈“舒服”。这三张截图的布局、疏密、阅读顺序与操作层级作为已确认基准，具体范围见 [v11 确认记录](previews/theme-account-profile-v11-approval.json)。其他辅助状态与管理员页面未逐图确认；原型、截图和原始审阅记录保持不变，正式前端尚未改版。根目录 `DESIGN.md` 与 `.impeccable/design.json` 在本轮前均不存在，v11 作为既有视觉世界的普通扩展继续保持缺失状态。
