# 导航、页头与页面密度（v3 视觉基准）

> 状态：v3 截图中的导航、页头、页面密度及手机重排效果已确认。用户查看桌面、手机与手机导航展开截图后反馈“舒服”。沿用已确认的 [v1 配色与 v2 字体](visual-theme.md)，未修改正式 UI。

- [桌面截图](previews/theme-layout-v3-desktop.png)：1440px 宽视口的整页截图。
- [手机截图](previews/theme-layout-v3-mobile.png)：390px 宽视口的整页截图。

这轮确认截图中呈现的侧栏宽度、顶部信息组织、页面标题与操作位置、内容留白和手机重排。配色和字体继续使用此前已确认基准。用户对整体布局与疏密程度反馈“舒服”，具体确认范围及文件摘要见 [v3 确认记录](previews/theme-layout-v3-approval.json)。

原始 HTML、三张截图与审阅记录保留提交时的内容，包括“待确认”等历史标记；当前状态以本文和确认记录为准。后续组件样板沿用 v1／v2／v3 基准，另存版本。

## 已确认布局与样板参数

| 位置 | v3 样板设置 | 使用目的 |
| --- | --- | --- |
| 桌面侧栏 | 已确认截图中的常驻 224px 侧栏、分组和底部帮助；样板另含 76px 收起态，未在本轮截图中展示 | 为业务内容保留横向空间，同时完整呈现现有分组和模块名称 |
| 顶栏 | 高 64px，左侧导航控制及当前位置，右侧账户入口 | 将全局位置与账户操作集中，和页面内业务操作分开 |
| 页面页头 | 标题与说明在左，刷新等页级次要操作在右；手机按阅读顺序换行 | 先明确当前任务，再找到页面操作 |
| 查询区域 | 地址、7／30／90 天和主要查询按钮集中一组 | 查询条件与执行动作保持接近 |
| 内容区留白 | 宽屏 32px，中等视口 28px／24px（垂直／水平），手机 24px／20px；内容框最大宽度 1360px | 同组紧凑、不同区域留出 24–28px，标题与内容框共用左对齐线 |
| 数据密度 | 逐币表格采用约 70px 双行记录；单行交易记录约 50px；数据字体保持 v2 的 14px | 保留名称和辅助文字的阅读空间，不靠缩字容纳更多数据 |
| 手机导航 | 900px 及以下收为菜单按钮；抽屉宽 280px，上限为视口减 48px，全高展示并覆盖顶栏；触控导航项至少 44px | 在窄屏保留内容宽度，展开时集中完成导航 |
| 手机逐币表现 | 600px 及以下改为同一面板内的摘要行：名称与盈亏在上，买入与卖出在下 | 直接看见核心数字，避免首次打开只能看到币名 |
| 手机交易明细 | 本样板保留表格内部横向滚动 | 展示复杂表格的过渡效果；完整交易详情和最终手机结构随组件设计确认 |

表中尺寸用于复现已确认截图；未展示的 76px 收起态、临界宽度切换、超宽页面、长内容和不同业务页面仍需相应设计及实际验证。此次截图认可不等于全部响应式参数、交互行为和组件状态已验收。

页面采用一个总览面板及两段数据内容，没有给每个指标单独加卡片。背景、内容面板、白／灰文字和青绿色选中项来自 v1；Inter 与 JetBrains Mono 及文字层级来自 v2。

## 导航与已有产品的关系

菜单分组和顺序依据 [member/app.tsx](../../../ui/src/app/member/app.tsx) 中 `navSections`：Markets 下为 Market Radar、Trader Sync、Sports、Managed OO、Worm Trading、World Cup Corners；Token & Risk 下为 Token、Wallets；Operations 下为 Profit Sharing、Notifications。样板呈现有相应权限的会员视角，不改变正式导航的权限过滤规则。

账户入口从当前侧栏底部移到顶栏右侧，是本轮已确认的布局调整；样板保留 Profile、Access、Security、Help 和 Log out 的演示菜单，菜单展开外观未在本轮截图中展示。正式 Security 的可用性仍受现有账户能力约束。已确认单一深色，目标样板不包含 Appearance 的明暗选择。二级菜单的展开外观、长账户名称与权限不足状态继续随组件设计完善。

当前生产代码的 Token 仍是无路由的禁用项；本样板展示未来钱包战绩页面的位置，不能作为 Token 功能已上线的证据。钱包总览、逐币表现与交易明细仅用于布局；接口字段、代币筛选对两份列表的作用、分页、缓存、时间和计算规则仍以[钱包战绩需求](../token/wallet-trading-performance.md)为准。样板顶部总览和各行是独立构造的虚构示例，不保证它们能组成完整账本。

会员和管理员继续维护独立入口、菜单、身份、数据与请求边界，本图不新增身份切换器，也不合并两套应用。管理员页面仍需单独确认适用布局。

## 样板交互与验证

样板只在浏览器本地运行：侧栏折叠、手机抽屉、账户菜单、时间选中、地址校验、模拟加载与刷新，以及四条演示记录排序。其他导航、筛选和加载更多明确提示它们是布局预览，不实际调用 API、退出账号、跳转正式业务或消耗额度。局部排序只针对四条样例，不声称满足供应商全局排序需求。

[检查记录](previews/theme-layout-v3-checks.json)覆盖 1440、1024、390、320px 四个宽度：

- 无整页横向溢出、主数字裁切、重复 DOM ID、字体加载失败或页面脚本错误。
- 桌面折叠／展开、手机抽屉的焦点进入与圈定、Escape 关闭、回焦和背景 inert 通过。
- 账户菜单、时间选择、无效／有效地址演示、刷新与局部排序通过。
- 四个初始视图及两种手机宽度的抽屉状态，通过 axe WCAG 2 A/AA、2.1 AA 自动扫描；这不是正式页面或全部组件状态的完整验收。
- 首次检查发现 SVG 图标和输入框复用了 `wallet` ID，已将图标独立命名；截图审阅发现桌面关闭按钮被通用按钮样式覆盖，已修正只在抽屉出现。修复后重验通过。
- Impeccable 两项提示已按样板范围处理：Inter 是用户在 v2 已确认的字体；表格面板本身不内缩，但表头／单元格、表格滚动容器和页脚分别提供实际内边距，文字没有贴边。两项均通过 `hooks ignore-value` 保存仅针对本 HTML 的例外和证据，其他文件与规则继续检查。

本次交付是已确认的布局视觉基准，不是正式 UI 重构、钱包 API 接入或产品验收。v1、v2、v3 的原始截图及审阅记录保持不变；下一项确认通用组件及其状态。独立截图审阅结论为 `ready_for_user_review`，用户随后确认了本轮视觉效果。
