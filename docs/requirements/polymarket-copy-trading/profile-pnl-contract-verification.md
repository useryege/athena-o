## 输入、数据与请求路由

原始数据为按返回顺序排列的 `{t,p}` 数组：`t` 为Unix秒，图表转为毫秒时间；`p` 为源提供的累计P/L值。图表直接使用p绘制纵轴；区间标题金额另行采用下述首尾规则。不可将所有图表点先减首点后宣称是原始曲线。

请求形式为公开User PNL服务的 `/user-pnl`，参数 `user_address`、`interval`、`fidelity`。origin来自 `USER_PNL_URL`；另一份已保存profile bundle明示默认 `https://user-pnl-api.polymarket.com`，但本文件本身导入该常量，不能仅凭本文件证明运行时未覆盖origin。

实际只有四个query key：1D、1W、1M、ALL。选择1Y或YTD时使用ALL的query key和数据，不发 `interval=1y` 或 `interval=ytd`。

### 未取得有效ALL缓存历史年龄时的参数

有效年龄指：ALL缓存是非空数组，并且以浏览器 `Date.now()` 减首点时间所得年龄大于0；缺失、空数组或年龄0都走此表。

| 展示区间 | 实际query key | interval | fidelity |
| --- | --- | --- | --- |
| 1D | 1D | 1d | 1h |
| 1W | 1W | 1w | 3h |
| 1M | 1M | 1m | 18h |
| 1Y | ALL | all | 1d |
| YTD | ALL | all | 1d |
| ALL | ALL | all | 1d |

### 已取得有效ALL缓存历史年龄时的动态参数

设 `A=max(0,(request_clock_ms−ALL[0].t×1000)/86400000)`，单位是天。这里request_clock取浏览器 `Date.now()`，与后面的展示参考时间来源不同。代码把A当“账户年龄”，但事实只能证明它是ALL数据首点至今的跨度，不等于用户注册时间。

以下规则作用于实际query key Q；1Y/YTD先被转换成ALL，因此请求函数不会接收到它们。令R为请求区间，初始R=Q；若Q=1M且A<31天，则R=ALL。该严格小于条件不可写成小于等于，也不可改为30天。

| Q | interval | 用于挑选精度的跨度H（小时） | 目标点数N |
| --- | --- | --- | --- |
| 1D | 1d | min(24,24A) | 24 |
| 1W | 1w | min(168,24A) | 56 |
| 1M且A≥31 | 1m | min(720,24A) | 48 |
| 1M且A<31 | all | min(720,24A) | 60 |
| ALL，包括1Y/YTD | all | 24A | 60 |

精度选择是确定算法，不是固定每区间一个值：

1. H≤0时为1h。
2. 按顺序考察候选小时数 `[1,3,12,18,24]`，跳过大于H的候选。
3. 选取使 `abs(H/候选小时数−N)` 最小的候选。只在严格更小时更新，因此平局保留较小候选。
4. 初始候选为24小时；若没有候选符合H且H<24，最终使用1h。
5. 最终候选≥24时参数为1d，否则为该小时数加h。

因此不能在spec中将1W/1M永远锁成3h/18h而说它与当前官方页面完全一致；当已有ALL缓存时会按上述规则改变。同一区间的请求参数也可能因ALL缓存是否已加载不同而变化。若产品选择固定采样，需要明确这是自己的参数选择，不能称为完整复现当前网页。

## 六区间裁切：边界、时区与数据顺序

金额/裁切函数使用参考时间T，实际调用传入 `useServerReferenceTime()` 转成Date后的毫秒值。本bundle未包含该hook的实现，无法证明它如何同步、何时更新以及客户端/服务端初始参考时刻是否相同。因此精确复现必须把所用T记录在适配结果中；不能把抓取耗时忽略后宣称与用户此刻页面逐秒一致。

| 展示区间 | 下界L |
| --- | --- |
| 1D | T−86400000毫秒（24小时） |
| 1W | T−604800000毫秒（7×24小时） |
| 1M | T−2592000000毫秒（30×24小时） |
| 1Y | T−31536000000毫秒（365×24小时） |
| YTD | T所在年份的1月1日00:00:00，采用执行JavaScript的本地时区 |
| ALL | 不裁切 |

非ALL只保留 `t×1000≥L` 的记录，起点包含。源码没有额外 `t≤T` 条件，没有补插边界点、没有插值、没有自动排序或去重；首尾按返回数组顺序取。不可擅自加插值或改为自然月/自然年。

YTD调用JavaScript本地年份/本地日期构造，**不是UTC年初，也没有硬编码Asia/Shanghai**。在实际浏览器中是浏览器运行时区；若代码在SSR执行则采用服务器JavaScript运行时区。本bundle不能证明上游部署服务器时区，也不能保证SSR与客户端时区一致。精确YTD适配必须明确本次参考时区，或直接读取该官方页面已渲染的YTD值。缺少该时区/参考时间时，YTD返回unavailable；不要偷偷用UTC或业务服务器时区填空。

## 标题金额：首尾差与历史不足例外

必须先确认原数据至少2点；裁切后也至少2点。否则源函数返回null；ATHENA应标unavailable，不生成0。

设过滤后第一点p为B，最后一点p为E。另以同一展示参考时间T计算 `A_display=max(0,(T−ALL[0].t×1000)/86400000)`。ALL数据缺失/空时，源码使用3650天默认值；这只是页面回退，不构成“账户已有10年数据”的事实。

| 展示区间 | 采用绝对末点E的条件 | 其他情况 |
| --- | --- | --- |
| 1D | A_display<1 | E−B |
| 1W | A_display<7 | E−B |
| 1M | A_display<31 | E−B |
| 1Y | A_display<365 | E−B |
| YTD | A_display<(T−本地年初)/86400000 | E−B |
| ALL | 永远 | 无 |

注意1M裁切30天、历史不足判断31天是源码的实际差异，不可归一化。等于阈值走首尾差。历史年龄取ALL首点，不读取createdAt/注册时间。即使某区间只有近几天的数据，只要ALL首点更早，源码仍按表走首尾差；不能仅看该区间长度改成绝对值。

鼠标悬停时标题将E替换为被选中点p，仍使用同一绝对/首尾差判断。确认卡未悬停的默认值应使用末点，不能因抓取时页面有hover状态而保存一个历史点的值。

图表最后调用外部 `roundPnlToCents` 再显示两位货币金额。本文件只导入该函数，未提供其精确舍入/浮点修正规则；不能从函数名假定ROUND_HALF_UP、banker rounding或负数零规范。若只返回已验证原始p值/未舍入区间金额，可保持十进制精度并标明其为原值；若承诺与官方显示到分完全相同，应直接取官方页面显示值，或在另行核准舍入函数前令该“精确显示值”字段unavailable。

## 可实施的失败边界

上面的请求路由、动态精度、裁切和首尾选择均可明确实现；但不应复制源页面所有容错方式。官方此构建在缺钱包、请求异常、非数组和null计算等路径中会合成零点或零金额；ATHENA需求明确不能用零伪装不可用。

因此以下情况应独立返回unavailable并附原因，而不是写“按官方逻辑”占位：

- 请求失败、超时、非数组、t/p非合法数、数组未按时间顺序、原始或裁切后不足2点；不排序修补未知响应。
- 需要判断绝对值/差值却缺少可靠ALL首点；不要沿用3650天默认值掩盖判断资料缺失。ALL本身不依赖年龄判断，但仍须有效数据及至少2点。
- YTD缺少明确执行时区或参考时间。
- 要提供与官网精确到分相同的数值，但既没有已渲染原值也没有核准roundPnlToCents语义。
- 上游网页/数据字段或消费链发生不能解释的变化。

保留每项的source URL、抓取时间、T、时区、实际interval/fidelity、原始点与可用性。收益区间失败不能改变目标钱包身份或将真实0收益改成缺失；同样不能把资料不可用误报为0。以上是在现有“允许辅助资料unavailable”要求内保护证据准确性的适配边界，不引入额外收益计算口径。
