# 单客户端登录需求

> 需求状态：已确认。用户明确要求「不允许多端登录，我们只允许一个客户端登录」，并选择「新客户端登录成功，旧客户端立即失效」。
>
> 当前实现尚未具备账号级单一有效登录会话校验；本轮只记录需求和设计，未修改登录代码。关联技术设计：[单客户端登录目标设计](../../design/identity-access/single-client-login.md)。

## 背景与目标

同一个 ATHENA 账号在同一时刻只允许一个客户端保持有效登录。用户可以改用电脑或手机，新客户端成功登录时替换旧客户端的登录资格；Trader Sync 和其他已授权页面都遵守同一账户规则。

## 术语与适用范围

| 术语 | 含义 |
| --- | --- |
| 账号 | ATHENA 的稳定账户 UUID，沿用现有身份与权限归属；不同账号独立计算 |
| 客户端登录 | 一个浏览器环境持有的一份交互式登录会话；共享同一登录会话的标签页属于同一客户端 |
| 新客户端 | 通过独立浏览器环境或其他设备建立新的登录会话；不能只凭页面传入的设备名称证明它与旧会话相同 |
| 登录生效 | 系统成功接受新登录，并以它替换该账号此前的有效登录资格 |

该规则按现有账号边界应用，不合并同一人持有的不同会员／管理员 UUID。API Key 与服务凭据沿用其独立认证用途，不作为浏览器登录；单客户端规则不新增任何 API Key 交易权限。

## 已确认的行为

1. 同一账号不得同时保留两个有效的客户端登录。
2. 新客户端完成身份验证且登录生效后，旧登录立即失效，不能继续访问该账号受保护的数据或发起新操作；不等待旧令牌自然过期。
3. 新登录验证失败，或在生效前被拒绝时，旧登录保持有效；不能在用户仅打开登录页或尚未完成验证时就踢出旧客户端。
4. 旧客户端发现会话失效后，清理旧登录对应的敏感状态和缓存，停止以旧会话发起请求，提示「账号已在其他客户端登录，请重新登录」。断网或后台页面在恢复请求时仍须通过当前会话校验。
5. 旧客户端迟到的退出请求不能撤销新客户端的有效登录；不同账号的登录互不替换。

「立即失效」是服务端访问资格在新登录生效时立即改变。在线页面应尽快显示原因；页面是否及时重绘、是否断网，不得成为旧凭据仍能访问服务的依据。

## 与 Trader Sync 的关系

电脑与手机都支持交易流程，但同一账号不能同时在两端保持有效登录。切换客户端后，新客户端仍查看该账号原有的绑定、持仓、订单与历史。

单客户端规则不替代交易幂等。重复点击、网络重试及同一会话的重复请求不能生成重复订单；已经取得合法提交授权并由后端接收的操作继续按原记录处理和核对，不因客户端切换自动补发或复制。账号权限关闭、钱包归属变化等独立资格变化仍执行各自校验。

此前「一笔待核对操作阻止整个交易账户的新操作」的提案未获确认，不因本次登录规则而成为已确认业务约束。后端仍需正确协调交易请求，不能只依赖页面按钮或假定单客户端只会产生一个请求。

## 异常与边界

- 两次登录同时完成时，服务端必须确定唯一有效会话；不能让两个客户端都持续保持有效访问资格。
- 新登录已经生效但响应丢失时，不能重新激活旧登录。登录恢复方式由技术设计处理，始终保持至多一个有效会话。
- 客户端只剩旧令牌、旧标签页、旧敏感操作凭证或旧本地缓存时，不能绕过当前登录资格继续操作。
- 会话切换不取消已发送到 Polymarket 的交易，也不把未知结果当作失败；尚未被合法接收的草稿和请求由当前有效客户端重新核对后提交。

## 验收场景

- 电脑登录后手机成功登录：手机可访问，电脑旧凭据的后续受保护请求立即被拒绝。
- 手机登录失败或被拒绝：电脑原登录仍有效。
- 两端同时登录、旧端延迟退出、重复登录回调及服务重启后，仍至多存在一个有效客户端登录。
- 同一有效登录的标签页共享登录状态，不被误判成多个独立客户端。
- 旧端失效时清理敏感状态，并向用户说明需要重新登录；已提交交易在新客户端按原记录查看，不重复执行。
- 会员与管理员的独立账号、其他用户及合法 API Key 的既有边界不被错误合并。

## 后续技术落实

需要补齐账号级当前会话的权威校验、登录生效与替换的原子边界、旧端退出、会话失效反馈，以及交易接收与会话替换之间的处理顺序。核心业务决定已确认，不重复询问是否允许多端或是否替换旧客户端。
