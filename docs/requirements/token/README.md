# Token 需求目标与研究资料

本目录属于 [`docs/requirements/`](../README.md)，记录 Token 业务目标、已确认决定、仍在讨论的边界和支撑调研。`需求状态` 描述业务决定的确定程度；细分状态继续说明其中已经确认、尚待细化或仅供选择的内容。

钱包战绩已确定采用 **Nansen API 接入 ATHENA，直接清楚展示其返回数据**。首版仅支持 Ethereum Mainnet，在 Token 内提供钱包总览、逐币表现和交易明细，USD 金额及盈亏采用供应商结果，胜率暂缓。2026-09-14 用户再次明确旧自研分析与重复的字段业务设计停用；字段映射和展示格式由工程侧落实，不再逐项确认转入、转出规则。有效需求和当前执行原则见[钱包交易与战绩](wallet-trading-performance.md)。API Key 与三个目标接口已实际调通并保存响应，[后端接入设计草案](../../design/token-intelligence/wallet-analytics.md)已形成，ATHENA 页面及后端业务接入尚未完成。

初期约 3–5 个用户，低频查询，本地开发也需验证接口；使用方向为 Nansen Free API 起步、额度不足时按需购买 credits，无须为 API 订阅网页 Pro。用户自行到 Nansen 官网注册后提供 Key，服务端通过 `NANSEN_API_KEY` 环境变量加载，有权限用户共用对应账户额度，不做平台内的 Key 配置页面。额度不足时有效缓存仍可查看；获取新数据失败则提示原因、保留并标注对应旧结果，不连续重试或自动充值。用户已提供 Key；一次 Ethereum 战绩摘要实测返回 HTTP 200，并确认 Free 套餐，本次消耗 1 credit、调用后剩余 94 credits。随后新 Key 的账户余额先查得 0 credits；用户自行充值 10 美元后，20:27（北京时间）复查返回 HTTP 200、Free 套餐、剩余 10,000 credits。两次账户查询均不消耗额度；以上余额分别为各次验证快照。随后对同一钱包和时间范围完成了三个目标接口的最小实测，均返回 HTTP 200；含一次逐币筛选对照共消耗 4 credits，最后响应余额为 10,096 credits。第二轮另以 20 次真实请求核实筛选、分页、时间范围及活跃钱包，消耗 24 credits，最后余额快照为 10,072 credits；发现 `show_realized=false` 的已实现盈亏排序差异，另保留胜率口径疑点的研究记录。用户随后决定首版暂缓胜率，胜率调查不再作为推进前置；字段映射作为工程参考维护，页面及后端业务接入尚未完成，详见[样本核验报告](nansen-api-validation-2026-09-13.md)。[成熟产品调研报告](wallet-analytics-vendor-research-2026-09-13.md)保留各家产品、价格、免费额度和选型依据，并记录 Nansen 已被选定。

首版已确认支持按完整代币合约地址直接搜索当前钱包在所选时间范围内的该币战绩和交易，钱包总览保持整体统计；暂不支持名称或简称模糊搜索，详见[代币搜索需求](wallet-trading-performance.md#按代币合约地址搜索已确认)。首版不设置平台或每用户每日查询次数上限，记录实际 API 用量与额度消耗，沿用共享缓存并遵守供应商限流。低于 1,000 credits 时显示页面提醒，恢复至 1,000 或以上后解除；不拦截仍有足够额度的查询，首版不发邮件或短信。成功结果自获取时起保留 24 小时，其中前 10 分钟有效复用；有效期结束后刷新失败可回显仍在保留期限内的旧结果，并标明时间与失败状态。

后续 Nansen API 开发、联调和验证统一使用用户指定的新 Key，完整值记录在[开发凭据](wallet-trading-performance.md#后续开发使用的-api-key已确认)，通过服务端 `NANSEN_API_KEY` 环境变量加载。

原 Etherscan 最近 300／1,000 笔取样、自定基础币筛选、多跳归属、成本分摊、Gas 与最新报价重算规则已移入[本地计算方案历史记录](wallet-trading-performance-local-calculation-history.md)，不再作为开发、验收或待确认事项，也不要求将 Nansen 数据适配成旧规则。[新发代币基础币调研](new-token-base-assets-research.md)保留当时的研究证据与选择。此次替换仅限钱包战绩，不改变下述项目发现与研究第一板块的 Etherscan、日志、资产估值或关联钱包能力。

Token 采用“设计后端 → 设计前端 → 实现后端 → 实现前端”的顺序，在后端编码前完成前端设计并对齐前后端方案。旧业务 UI 已移除，保留禁用 Token 父菜单、独立 Wallets 和后端 API，见[实施顺序与前端范围](token.md#已明确的实施顺序与前端范围)。后续开发遵循 [Superpowers 工作流](../../developer-guide/superpowers-development.md)，长期架构决定同步到 [`docs/design/`](../../design/README.md)。

项目发现与研究第一板块已确定以下业务边界；钱包交易与战绩的具体规则在其独立需求中讨论：

- **首版仅 Ethereum Mainnet（chain ID 1）**，源码、普通交易及按地址内部交易使用现有免费 Etherscan Key；以后扩链前，现有免费 Key 全部更换为付费 Key。持币资料改由 Ave 获取持币地址总数与前 100 名明细，不再设计 Etherscan PRO Key 或完整分页名单。
- **同代码、单链实例运行**：启动配置选择唯一链，扫描、活动/Swap 监控及外部采集按链运行；首版只启动 ETH，后续 BSC 使用同一构建产物增加实例。汇总、AI、源码报告和 API 可以共享，项目与任务保留链身份，实例不得覆盖其他链状态，详见 [运行设计](token-chain-runtime.md)。
- **区块扫描采用已选择的 A 边界和流水线预取**：每轮固定最多 100 块，并行预取到有界内存；下一应处理块到达即开始严格按高度串行识别和保存，不等整批。每块可靠保存识别结果、项目资料与研究任务后才推进；获取失败可继续预取后续块，但处理和游标不得越过失败块。源码、AI 和五层钱包采集后台独立执行；扫描按三天起点、追平等待 1 秒、失败逐次通知并重试，不考虑区块替换。
- **聚合合约同时支持单个与批量 Token 判断**：两种调用形态共享代码检查、六项检测、结论和逐项诊断规则；区块扫描汇总同一区块候选后统一使用批量判断，不在 Go 中逐个调用。单个候选不通过不影响批量中其他候选，整个聚合调用失败才按区块失败处理。
- **第一板块只输出事实**：当前阶段只发现 Token、采集、解析、保存和展示事实，不做 AI 评级、程序筛选、通过／不通过、自动排除、关注项目移交或买入判断。第二板块及撤回语义留待后续单独设计。
- **请求失败与空源码明确区分**：请求失败记录技术错误、重试并通知管理员，不能标为未开源。成功空源码表示可能未公开，支持手动补采；研究期间仅由期限内的目标 Token `Transfer`，或部署者／当前 owner 发出的成功顶层交易，在仍无非空源码时触发或合并源码查询。`Approval` 只续期，不重查源码；不设置定时轮询。
- **AI 只生成质检事实报告，不评级**：必查是否可以无限增发、修改余额、限制转出、绕过持有人授权转账，以及放弃 owner 后仍保留控制权五项事实，逐项保存权限、条件、影响和源码依据，另保存代理和外部未知依赖标识。后两项已作为新增单项要求确认，整份需求仍为讨论中。当前报告供成员查看，不配置、不执行任何筛选或排除规则。
- **同源码复用报告，允许人工指定报告重检**：默认按 AI 报告准确使用，新部署不重复分析；例如提示词变更后可由管理员触发重检。owner、税费接收钱包、税率和源码公开资料分别复用分析；实际链上地址与值逐合约读取。
- **后台自动采集 L1–L5，并展示五层结果**：L1 包含部署者、最多 5 个初始接收钱包、取得的 owner 和税费接收钱包；每钱包固定查询部署区块 B 之前 `0..B-1`，普通与内部各取倒序第一页最多 300 条原始记录，过滤后不翻页凑数。项目开始时保存按链配置的原生币资金门槛快照，ETH 默认 `0.01 ETH`、未来 BSC 默认 `0.01 BNB`；两类入账均须成功、未回滚、非零、实际转入当前钱包且单条达到门槛；普通交易保留实际直接来源，内部 ETH 入账按顶层发起人归因并保留实际转出证据，同交易内小额也不累计。内部实际转出方命中管理员交易所／跨链库时优先在该地址终止，不穿透发起人；终止节点仍完成本层两类历史与行为分析。L5 不扩展 L6。
- **内部 ETH 采用发起人归因并保留实流证据**：A 调用 C、C 向 W 内部转入时，默认按 A→W 研究上游，C→W 作为实际流水保存且不因中转占层；C 命中管理员地址库优先保留 C→W 并在 C 终止。归因不证明 A 实际出资或控制相关地址；未触发 C 地址库优先终止例外时，自身发起回款不新增外部来源，缺少发起人不猜测归因。不同内部明细分别保存，同一条跨样本去重，真实流水与归因不重复计额。内部记录关联的新增顶层交易也参与行为分析，只归属当前钱包有证据的行为。本能力不新增研究期续期、Swap 或工厂内部部署发现，详见[内部转账需求](token-wallet-internal-transfers-flow.md)。
- **首次已识别 Swap 截止研究**：首版 ETH 明确覆盖 Uniswap V2/V3/V4、Sushi V2/V3、PancakeSwap V2/V3。任一可信支持协议中涉及目标 Token 的有效 Swap（包括 flash swap）都会停止研究；添加流动性不停止。所谓“首次”仅指当前覆盖版本内按链上顺序最早识别到的事件，未覆盖路径保持未知。后续增加适配器只回补仍在研究的项目。
- **活动驱动 72 小时观察窗口**：默认从部署区块时间起观察 72 小时，按链可配置。当前期限内（含期限时点）的合法目标 Token `Approval`、`Transfer`，以及部署者／当前 owner 发出的成功顶层交易均可按区块时间续期；监控地址发出的零原生币合约调用有效，入账、失败交易与内部调用无效。部署者从部署交易之后开始监控，当前 owner 从成功读取它的观察区块开始监控；owner 更换后停止旧 owner，部署者始终保留。超时前必须确认上述四类活动及 Swap 覆盖都已完整越过期限，迟到活动不恢复项目。
- **活动动作严格分离**：`Approval` 只记录证据并续期，不重查源码、不刷新资料；`Transfer` 续期、在缺少非空源码时重查，并可按管理员的链级映射刷新资料，默认刷新 Token 当前状态及 Ave 持币总数和 Top 100；部署者／当前 owner 主动交易续期并在缺少非空源码时重查，但不触发其他资料刷新。每项目每刷新组默认 10 分钟冷却并合并重复触发，续期不受冷却限制。
- **资料保留当前事实与估值依据**：项目动态资料通常展示最近一次成功值，失败另存最近失败时间与原因；L1 每次估值快照保留路径、池、区块、时间及逐项结果，部分成功展示本次已知小计与不完整状态，不用旧结果填补当前缺项。项目停止后取消未开始任务，已开始任务按原有限重试规则收尾，项目专属事实随后冻结；按 `code_hash` 共享的报告、公开链接及静态读取方案始终展示最新共享版本。
- **L1 资产与 USDT 估值范围固定**：ETH 首版每个 L1 钱包读取原生 ETH、WETH、USDT、USDC、DAI、WBTC，逐项保留原始余额和独立 USDT value，并给出已知小计与总值完整性；L2–L5 不读余额。估值使用按链、按资产配置的固定可信 DEX 现货路径，支持直接或最多两跳，余额、池状态和价格统一到同一观察区块。非零资产无法估值时不得按零代替，保留其他结果并列出缺失资产。钱包历史中的明确买卖仍只按上述七个协议识别；第一版彻底移除现有六项 `simulation_result`。
- **交易所／跨链节点由管理员地址库终止追溯**：管理员按链维护地址、类型、名称和依据。L1–L5 任一钱包精确命中后保留标签、入账证据及本层普通与内部各最多 300 条历史和行为分析，但不再从该节点发现上游；新增标签对研究中项目停止后续扩展，移除标签可恢复尚未执行的扩展，已停止项目不重开。

owner、税费接收钱包和税率仍由 AI 基于源码提供读取说明，Go 在各自最新采集区块查询；同一税率的相关读函数使用同一区块。保留源码依据、原始值、实际区块和未取得原因，缺失不填为零、不推测角色，也不把链上读取放进静态报告核实流程。源码公开资料提取多条 HTTPS 链接并标明“来源：合约源码”，不搜索或抓取网页。Ave 持币数据分别记录总数与 Top 100 的查询时间，明确其有界范围，不当作部署初始分配、完整名单或固定区块快照。

Token `READ` 或 `READ_WRITE` 成员可查看上述事实资料；观察时长、`Transfer` 刷新映射、L1 估值路径、原生币资金来源门槛、交易所／跨链地址库和手动停止只允许管理员配置或执行。研究正常因已识别 Swap、超时或人工停止时只记录原因与证据，不发送管理员通知。项目一旦停止不支持恢复或重开。

已确认的时效设计目标包括：正常追平的新 Token 发现、已登记项目活动续期和 Swap 停止分别为 **P95 ≤ 15 秒**；首次三天发现补扫 **2 小时内追平**；正常追平的新项目首轮基础资料分别为 **P95 ≤ 1 分钟可查**；非空源码就绪后的各项 AI 首次分析分别为 **P95 ≤ 5 分钟**；每个新加入 L1 的钱包首轮资料分别为 **P95 ≤ 10 分钟可查**。深层研究公平持续推进，不设统一整图期限。刷新具备执行资格后的首轮结果 **P95 ≤ 1 分钟**，一小时以内断线在上游恢复后 **5 分钟内追平**，全部超时条件满足后的停止 **P95 ≤ 15 秒**，人工停止 API **P95 ≤ 2 秒**。这些目标尚未验证性能，完整计时与范围见[时效目标](token.md#已明确的正常运行时效目标尚未验证)。组件、存储、接口、限流和容量验收方案见下方五份目标设计；实际负载、额度及性能仍待验证，见[未决事项](token.md#仍待明确的事项)。第二板块买入条件、执行和移交／撤回规则暂不设计，研究停止不是买入指令。
