# Token 需求目标与研究资料

本目录属于 [`docs/requirements/`](../README.md)，记录 Token 业务目标、已确认决定、仍在讨论的边界和支撑调研。每份可独立确认的文档以 `需求状态` 为阶段依据；细分状态继续说明其中已经确认、尚待细化或仅供选择的内容。

Token 当前先完成后端，再重新设计前端；旧业务 UI 已移除，保留禁用 Token 父菜单、独立 Wallets 和后端 API，见[前端范围](token.md#已明确的实施顺序与前端范围)。需求确认后，后端方案进入 [`docs/design/`](../../design/README.md) 的技术设计阶段。

| [单链实例运行需求](token-chain-runtime.md) | 同代码、单链实例的运行边界和首版链范围 | `已确认`，尚未实现 |

已确定以下业务边界：

- **首版仅 Ethereum Mainnet（chain ID 1）**，源码和普通交易继续用现有免费 Etherscan Key；以后扩链前，现有免费 Key 全部更换为付费 Key。持币资料改由 Ave 获取持币地址总数与前 100 名明细，不再设计 Etherscan PRO Key 或完整分页名单。
- **同代码、单链实例运行**：启动配置选择唯一链，扫描、活动/Swap 监控及外部采集按链运行；首版只启动 ETH，后续 BSC 使用同一构建产物增加实例。汇总、AI、源码报告和 API 可以共享，项目与任务保留链身份，实例不得覆盖其他链状态，详见 [运行设计](token-chain-runtime.md)。
- **区块扫描采用已选择的 A 边界和流水线预取**：每轮固定最多 100 块，并行预取到有界内存；下一应处理块到达即开始严格按高度串行识别和保存，不等整批。每块可靠保存识别结果、项目资料与研究任务后才推进；获取失败可继续预取后续块，但处理和游标不得越过失败块。源码、AI 和五层钱包采集后台独立执行；扫描按三天起点、追平等待 1 秒、失败逐次通知并重试，不考虑区块替换。
- **聚合合约同时支持单个与批量 Token 判断**：两种调用形态共享代码检查、六项检测、结论和逐项诊断规则；区块扫描汇总同一区块候选后统一使用批量判断，不在 Go 中逐个调用。单个候选不通过不影响批量中其他候选，整个聚合调用失败才按区块失败处理。
- **请求失败与空源码明确区分**：请求失败记录技术错误、重试并通知管理员，不能标为未开源。成功空源码表示可能未公开，支持手动补采；按链共享事件监控通过实时订阅与历史补查接收目标 Token 的 Approval/Transfer 活动，触发更新事件，再为仍在研究且仍无源码的项目查询，不定时轮询。
- **AI 只生成质检报告，不评级**：至少包含是否可以无限增发、修改余额、限制转出及依据，另保存代理和外部未知依赖标识。当前报告先展示给管理员；后续由管理员维护标准，程序根据报告判断风险。未配置标准不表示低风险或通过。
- **同源码复用报告，允许人工指定报告重检**：默认按 AI 报告准确使用，新部署不重复分析；例如提示词变更后可由管理员触发重检。owner、税费接收钱包、税率和源码公开资料分别复用分析；实际链上地址与值逐合约读取。
- **后台自动采集 L1–L5，并展示五层结果**：L1 包含部署者、最多 5 个初始接收钱包、取得的 owner 和税费接收钱包；每钱包固定查询部署区块 B 之前 `0..B-1` 的倒序第一页最多 300 笔。各层分析直接部署和跨协议代币交互，使用成功的 ETH 直接入账追溯来源，L5 不扩展 L6。角色、交易与地址去重，折叠只改变显示。
- **首笔实际 Swap 截止研究**：每条链使用一套共享事件监控，通过实时订阅与从部署区块开始的历史补查覆盖所有仍在研究的项目；按协议验证日志发出方、池或管理合约身份及实际交换币种。识别到可信 Swap 后立即结束研究，并继续补齐更早范围以确定链上首笔。协议不限 V2/V3/V4 或单一 DEX；尚未交接项目放弃本轮参与。具体事件族与候选优先级已调研，首批接入清单待确认，不能把覆盖内未发现说成全市场未交易。
- **资料展示与程序筛选分开**：钱包、税率、持币和源码公开资料当前只展示。为识别 Swap 取得必要的池身份与代币映射，不研究池深、流动性估值或 LP 风险；Ave 只用于持币地址总数和前 100 名分布，不采集其市场、池或风险标签，模拟结果非必采。系统自有源码/钱包黑名单按已确定方向后续移除。

owner、税费接收钱包和税率仍由 AI 基于源码提供读取说明，Go 在各自最新采集区块查询；同一税率的相关读函数使用同一区块。保留源码依据、原始值、实际区块和未取得原因，缺失不填为零、不推测角色，也不把链上读取放进静态报告核实流程。源码公开资料提取多条 HTTPS 链接并标明“来源：合约源码”，不搜索或抓取网页。Ave 持币数据分别记录总数与 Top 100 的查询时间，明确其有界范围，不当作部署初始分配、完整名单或固定区块快照。

具体报告结构、程序规则维护、活动更新合并、任务停止时的在途结果、事件监控组件与持久化边界、地址分片和协议覆盖仍待细化；这些不改变已确认的共享监控、实时接收与补查连续性规则。第二板块买入条件与执行规则另行设计，研究停止不是买入指令。
