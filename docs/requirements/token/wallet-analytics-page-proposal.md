## 页面组织

| 位置 | 展示与操作 | 说明 |
| --- | --- | --- |
| 全局位置 | Token 下的 Wallet analytics | 沿用会员侧栏和账户入口的已确认视觉；未启用正式 Token 路由。 |
| 查询区域 | Ethereum 钱包地址、7／30／90 天、Query wallet | 默认 30 天；无网络切换器或自定义日期。 |
| 钱包总览 | 地址、网络、实际日期范围、已实现盈亏（USD）、交易过的代币数量 | 总览不随代币筛选改变；来源、数据说明与完整摘要值可核对。 |
| 逐币表现 | 符号／合约、买入 USD、卖出 USD、持仓数量与 USD、已实现与未实现盈亏 | 桌面并列核对，手机分组；完整地址与数值按需展开。 |
| 代币筛选 | 完整 ERC-20 合约地址、点击代币、清除筛选 | 同时作用于两份列表，钱包和日期不变；不提供名称模糊搜索。 |
| 逐币排序 | 已实现盈亏从高到低／从低到高 | 完整保存集合按数值排序，空值最后；不按展示字符串比较。 |
| 交易明细 | UTC+8 时间、Nansen 返回的资产与数量、记录 USD、哈希／Etherscan、完整记录 | Out／In 只标识响应中的资产数组，不反推买卖、多跳或交易分类；不展示单笔“利润”。 |
| 区域状态 | 加载、失败重试、保留旧结果、来源与时间 | 区域失败不隐藏其他成功结果。正式实现使用各区域自身的成功获取时间与原查询范围。 |

样板中的 `request started` 明确指研究文件的请求发起时间，不冒充成功获取时间。模拟刷新只重新显示保存内容，不伪造新的数据时间。正式接口接通后，产品改用后端返回的成功获取时间、缓存状态和各区域实际查询范围。

桌面沿用 224px 侧栏、64px 顶栏和 32px 内容边距；手机沿用 20px 页边距及导航抽屉。钱包数据页面使用 [v1 配色](../web-ui/visual-theme.md)、[v2 字体与数字](../web-ui/typography-proposal.md)、[v3 布局](../web-ui/layout-proposal.md)、[v4 状态](../web-ui/components-proposal.md)和[v5 列表控件](../web-ui/list-controls-proposal.md)。未修改这些已确认样板或全站样式。

本页包含局部适配：列表在 760px 及以下切换为分组行；320px 窄屏主金额使用 28px；反馈框采用中性面板与边框、10px 圆角并沿用 v4 语义文字色，未逐项复制 v4 的反馈背景与边框。复制被拒绝后的全文弹窗属于本页辅助状态。本版整体页面设计已确认；这些差异仅作为本页实现参考，不扩展为新的全站视觉规则，也不将整体反馈记为各辅助状态的逐图确认，详见[设计记录核对](previews/wallet-analytics-v1-documentation.json)。

## 数字与来源

- 美元通常显示千分位和两位小数。盈亏保留正负号；负零展示为 `$0.00`。不足一美分的非零值用 `<$0.01` 表示，盈亏同时保留符号。
- 数量最多展示六位小数；微量数量保留到首个非零位后共四位有效数字，避免显示为零。被舍入的数量加 `≈`，例如 SHIB 的 `≈0.000001816`；完整值仍为 `0.00000181579280252`。
- 缺失值显示 `Unavailable`，与已知零值区分。持仓数量和持仓 USD 各自处理，不通过乘价格补齐。
- `Full values` 和 `Full record` 保留选中字段的原始数值精度。数值由保存 JSON 的十进制值提取为字符串，展示格式化和比较不经过 JavaScript 浮点数；不计算新的盈亏或估值。
- 地址与哈希可复制完整值；剪贴板被拒绝时弹出并选中全文供手动复制。ETH 原生资产标识不伪装成 ERC-20 合约或生成代币合约链接；WETH 仍单独显示。

所用[提取数据](previews/wallet-analytics-v1-data.json)只包含本页字段及对应样本路径、请求范围、请求开始时间和 SHA256。API Key、账户额度、胜率、ROI、Top 5 和其他未选指标没有进入 HTML 或提取数据。全部原始核验文件保持原样。

## 保存样本的边界

| 场景 | 已有证据 | 预览处理 |
| --- | --- | --- |
| 钱包 B · 30 天 | 摘要、两组完整逐币返回、第一页交易 | 逐币取完整行合并并排序；显示 3 个币和 20 条交易。 |
| 钱包 A · 30 天 | 摘要、两组逐币返回、两页共 40 条交易 | 默认显示 20 条，点击加载更多追加真实第二页；之后提示没有保存的后续页，不宣称历史已完整。 |
| 钱包 A · CATE／USDT 精确筛选 | 单独保存的 Nansen 带合约筛选响应 | 使用该真实筛选结果，保留其末页标识。 |
| 其他合约筛选 | 部分场景只有交易第一页或前两页 | 清楚注明仅在已保存记录中筛选，不能将无匹配解释为完整历史没有记录；正式版由后端向 Nansen 发起对应筛选查询。 |
| 钱包 B · 7 天 | 真实零值摘要；未保存两组完整逐币数据及该钱包交易样本 | 摘要显示 0／0，其余注明样本未记录。 |
| 钱包 B · 90 天 | 真实负值摘要与已实现逐币返回 | 显示 `−164,453.51 USD`，逐币注明范围未完整核验；交易区注明样本未记录。 |
| 钱包 A · 7／90 天 | 仅对应交易请求 | 显示保存的交易；摘要和逐币区域不补造数据。 |
| 加载、失败、旧结果、额度耗尽 | 界面状态模拟 | 顶部审阅工具明示为模拟；不作为真实请求、缓存时限、账户余额或额度控制验证。 |

两份完整逐币样本均不足 20 行，本预览未伪造额外代币来演示第二批。正式版的两类每批最多 20 项、完整集合排序、游标与大集合验证按后端设计落实。
