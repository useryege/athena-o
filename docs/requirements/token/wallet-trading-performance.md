# 钱包交易与战绩需求

> 需求状态：Nansen API 接入方向已确认，接入细则讨论中，尚未实现。
>
> 用户于 2026-09-13 选择 Nansen API，将钱包战绩接入 ATHENA；不再设计或实现本地日志解析、成本账本和盈亏计算引擎。本文是当前有效需求，替代[本地计算方案历史记录](wallet-trading-performance-local-calculation-history.md)。[服务商调研报告](wallet-analytics-vendor-research-2026-09-13.md)保留选型依据、公开价格、免费额度和费用测算。
>
> 当前仍在维护业务需求；尚未形成接入技术设计、调用真实接口或完成系统集成。

## 业务目标与已确认方向

- 在 Token 领域提供独立的“钱包战绩”子板块，以用户输入的钱包地址为查询起点。
- 首版仅支持 Ethereum Mainnet（chain ID `1`），查询钱包的代币交易记录、逐代币表现、盈亏和胜率。
- 统一以美元（USD）展示供应商提供的收益、成本和收支金额；可取得的原币种与数量用于核对明细。
- 数据来源确定为 **Nansen API**。交易解析、成本与盈亏结果采用供应商提供的数据和定义，ATHENA 负责接入、组织查询和展示结果。
- 保留买入、卖出、转入、转出的查看目标，授权明细不作为本板块展示内容。具体交易分类及字段映射需对照 Nansen 实际响应确认，不从流入／流出字段自行推断买入／卖出。
- 初期预计 3–5 个用户，查询频率较低；本地开发也使用免费额度验证。每日查询量没有指定，调研报告中的频率和费用是估算假设。
- 沿用推荐的 **Free API 起步、额度不足时按需购买 credits** 的使用方向，无须为接入 API 订阅网页 Pro。尚未执行注册、充值或任何付费调用。

选择 Nansen 已经确定；后续讨论聚焦接入范围、字段含义、查询交互和运行管理，不再重新设计本地盈亏算法，也不因接口缺少某个字段而自动增加自研计算补齐。

## 本次替代的设计范围

以下旧规则不再是本功能的本地实现要求，也不据此推断 Nansen 的结果含义：

| 调整前的方案 | 当前接入方向 |
| --- | --- |
| Etherscan 获取最近 300／1,000 笔原始交易，再按哈希读取回执、解析日志 | 使用 Nansen 的钱包交易和战绩接口；查询时间、分页与覆盖范围根据接口能力重新确定。交易页大小不等于盈亏样本笔数。 |
| 本地只统计 WETH／USDC／USDT 直接交易对，多跳逐段归入 CC 等中间项目 | 采用 Nansen 的交易归属和统计范围，不在本地重建成交段或重新筛选后计算 PnL。可用的展示筛选另行确认，不能把它当成供应商已按相同范围重算。 |
| 跨基础币交易对合并持仓，维护移动加权平均成本 | 使用 Nansen 返回的成本和收益，不建设独立成本账本，不宣称其算法就是移动加权平均。 |
| 已知／未知成本比例分摊，普通转出及非基础币换出自行扣减成本 | 不执行本地数量与成本分摊；保留供应商可识别的缺失、覆盖及转账含义，不将缺失值填成零。 |
| 独立基础币报价程序、落库、内存缓存 10 分钟，以最新价格重算所有历史金额 | 本功能直接使用 Nansen 返回的 USD 金额，不为重算历史收益建设报价程序；查询结果缓存需要独立设计，不能继承旧报价缓存的 10 分钟期限。 |
| 自行分离 Gas／手续费并保证所有代币盈亏未扣 Gas | 不修改供应商收益结果；费用能否单列及其是否已计入收益，依据接口定义和验证结果说明。 |
| 缺失成本时由用户触发历史补查，再更新本地账本 | 是否支持扩展查询时间、加载更多明细按接入能力设计，不承诺本地补齐成本或重算历史盈亏。 |

原有详细示例与未决事项已转入[历史记录](wallet-trading-performance-local-calculation-history.md)，只用于理解业务背景。AA 接收侧成本建议未曾确认，现已退出待设计范围。

## 接入后的职责

Nansen 提供交易与战绩数据。ATHENA 将这些数据接入现有系统，承担钱包查询入口、参数校验、结果展示及必要的访问控制和调用管理。

以下为接入设计需要覆盖的事项，具体机制尚待确定：

- 服务端管理 API 凭据和上游调用，不把供应商密钥放入浏览器；实际接入归属、内部接口和配置位置在技术设计中确定。
- 将供应商返回的统计与交易明细组织成钱包总览、逐币表现和交易明细；展示供应商来源、查询范围与更新时间。
- 对时间窗口、分页、重复请求、刷新和历史结果留存形成明确规则，避免每次界面更新都重复消耗上游额度。
- 区分无交易、字段缺失、部分结果、数据尚未准备好、余额不足、限流与调用失败；不能用零收益或零胜率代替未知或失败。
- 记录调用额度与失败信息，支持本地样本调试和必要的真实接口验证；预算上限、刷新策略及告警方式另行确定。

本段不是数据库、缓存期限、任务队列或服务边界的最终方案。新服务或服务边界改造时遵循[服务开发规范](../../developer-guide/service-development-standards.md)，不为单纯 API 适配提前创建额外服务。

## 已核实的 API 能力与待验证含义

以下为截至 2026-09-13 的官方文档依据，不代表已完成账号或真实钱包验证。

| 页面内容候选 | Nansen 接口 | 可据文档确认的能力 | 接入时须核验 |
| --- | --- | --- | --- |
| 钱包总览 | `POST /api/v1/profiler/address/pnl-summary` | Ethereum、日期范围、已实现收益、`win_rate` 和表现较好的代币 | 胜率字段的单位与分母，返回空值和窗口含义；摘要可能有最长约一小时缓存。 |
| 逐币表现 | `POST /api/v1/profiler/address/pnl` | 按代币提供已实现／未实现收益、买卖数量和金额、成本、持仓及分页 | 已实现筛选参数、分页完整性、交易次数中流入／流出的含义；不能默认所有字段都非空。 |
| 交易明细 | `POST /api/v1/profiler/address/transactions` | Ethereum、日期范围、代币合约过滤、每页最多 100 条；返回哈希、时间、收发资产及原币数量 | 交易分类及费用字段的可用性、过滤与 PnL 范围是否一致；不能将 `sent`／`received` 直接当作买卖，也不能将每页 100 条等同于去重后 100 笔原始交易。 |

来源：[PnL 与交易表现](https://docs.nansen.ai/api/profiler/address-pnl-and-trade-performance)、[端点总览与消耗](https://docs.nansen.ai/api/overview)、[钱包交易接口](https://docs.nansen.ai/api/profiler/address-transactions)。

美元字段按供应商结果展示，不另用最新基础币报价重新计算。日期区间、交易明细页与 PnL 覆盖范围分别表述，不将返回的若干页交易说成全部历史，或宣称它们就是统计结果的全部依据。供应商未说明的成本法与胜率定义保持待核验状态。

## 套餐与使用规模

Free 提供初始 100 credits，之后每日余额回补至 10 credits；上面三个接口在公开端点表中各列 1 credit／请求。API 无须 Pro，额外额度为 $10／10,000 credits，购买额度一年有效。[官方计费](https://academy.nansen.ai/en/articles/0938495-get-started-with-api)

按一次摘要、一页逐币明细和一页交易明细估算，每轮基础查看为 3 credits。免费额度适合小样本验证，不承诺覆盖所有开发与用户查询；更多分页、其他端点、重复刷新和重试按实际消耗计入。预算测算见[调研报告](wallet-analytics-vendor-research-2026-09-13.md#35-个用户的初期套餐建议)。实际充值、额度上限及超限行为仍待安排，不自动扣费或购买订阅。

## 与现有 Token 能力的边界

[项目发现与研究](token.md)从新部署代币项目出发；[项目关联钱包研究](token-wallet-research-flow.md)采集项目相关地址的部署前证据。本功能从用户输入的钱包出发查询 Nansen 战绩，两者分别维护需求。

此次方向调整仅替代钱包战绩的自研采集与计算方案。第一板块已有或已设计的 Etherscan 采样、区块与日志处理、资产估值、源码与关联钱包研究不因此删除、改源或停用。

现有 Wallets 仍负责账户自有钱包管理。钱包战绩的查看权限、可查询地址范围、结果是否共享，以及是否关联自有钱包，继续单独确定。
